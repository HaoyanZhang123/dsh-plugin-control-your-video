# 工程验收记录

## 环境与范围

- 本记录对应 Control Your Video `0.6.0`（V3 知识层重排）。代码以公开 `0.5.0` 为基线，在 `release-v0.5.0` 之上新建 `v3` 分支完成；原开发工作树与现用 Profile 不属于测试写入范围。
- 实际执行环境为 Windows 11、Node 24.22.1、FFmpeg/FFprobe 9.0.1（`full_build`），宿主为已安装的 DSH Desktop。
- 隔离宿主测试使用已安装 DSH 的真实 Cordis、工具注册器、原生执行器、用户提问服务及 JSON 存储。项目、存储和测试用户答复是测试夹具；没有改动用户实际 profile，也没有使用生成服务或私人资料。

## 设计取舍及覆盖范围

- 视频预设**以标准预设的工具清单为底**，一个不减，再额外挂上 `cyv`、`evidence` 和审批存储。助手在本预设里拥有与标准模式相同的 Shell、文件读写、后台任务、子代理、工作流和计划模式能力。标准预设本身未被修改。
- `tools/preset-policy.js` 仍是**空实现**（只声明 `inject = ['tools']`，`apply()` 无操作）。它保留为插件行以便已安装的配置继续激活，不设任何插件级的全局门禁，也不收窄工具。
- 审批是**流程约束，不是运行时硬门禁**。三个确认点由宿主接口取得真实用户回答并绑定内容版本；通用 Shell 存在的前提下，理论上仍可绕过 `cyv` 直接渲染。这一点如实记录，不作为"不可绕过"宣称。
- `plan.md` 走契约检查：认镜头表或逐镜小节两种写法，查缺镜、单镜与合计时长、素材三态、每镜是否写了制作路线。它判结构、时长与可核实性，不判创意可行性与审美；`review.required` 恒为真，`pass` 之后仍需人审。
- FFmpeg 是随包的一条验证路线，不是唯一路线。助手可以用 Shell 调用本机 `node`、`python`、FFmpeg 或其他已装工具自行出片，也可以用 `cyv` 走带审批的外部本地路线。
- 生成模型默认不存在。宿主可扩展发现和连接模型提供方。本版把**选型并入完整方案批准**：方案里写明型号、用途、预计费用上限与拟外发范围，批准即认可；授权记录绑定批准时的方案摘要，方案改动后拒绝派发。仓库测试仍不连接任何真实提供方。
- 当前是 **8 个注册入口与 48 份按需参考**（两条知识族 + 六个直接入口）。净收益与真实 A/B 结论仍待验证。

## 已观察结果

- `npm test`（`node --test tests/*.test.js`）在本版复测为 **123 项通过、0 失败、0 跳过**，含真实媒体用例。构成：`project` 42、`plan-contract` 25、`media-grants` 18、`workflow` 17、`production` 8、`skills` 7、`evidence-sheet` 4、`tool-wiring` 2（按源码里声明的用例计）。
- **知识层结构回归**（`tests/skills.test.js`，本版新增）：每个技能目录名 = `name` = kebab-case、`description` 满足目录上限且带负向边界、两族入口正文有实质内容、**正文与参考之间互相引用的文件都存在**、**没有任何正文再指向已合并的旧入口名**、每份参考第三行写清"何时读"、发布面里没有本机私有路径、预设仍从包根挂载 `skills/`。
- **工具接线回归**（`tests/tool-wiring.test.js`，本版新增）：用最小假宿主调 `apply(ctx)`，走完 `approve_media → generate_one_asset → 落盘 → 同 operationId 回放`，并断言 `evidence` 的动作枚举里有 `sheet`。这一层此前没有任何自动化覆盖。
- **联系表**（`tests/evidence-sheet.test.js`，本版新增）：真实 2 秒测试片出图，校验 PNG 签名、每格绝对时间、与同键单帧互不覆盖、`--force` 重抽不新增、非法参数被拒。
- `tests/preset-check.cjs` 用同一 Electron Node 运行方式执行（`ELECTRON_RUN_AS_NODE=1`，DSH CLI 包目录作第一个参数、本包**绝对路径**作第二个参数）：**28 行声明全部挂载成功**，没有配置或解析错误；2 行在本平台未生效（`tool-bash` 在 Windows 上禁用、`tool-plugin-market` 按配置禁用）。用系统 Node 直接运行会因 `app.asar` 内虚拟路径无法解析模块而失败。
- `tests/host-smoke.cjs` 通过已安装 DSH 的真实工具执行器与本机 FFmpeg 跑通七个节点：预设装配与标准工具保留、用户问答贯通、真实 FFmpeg 小样 1 秒／全片 2 秒／修订 2 秒（H.264 + AAC）并抽到真实帧与媒体测量、素材复制到另一个项目并保留原件、经验库授权写入与检索、外部本地路线（显式 run、24 帧解码小样、三点 seek、48 帧全片与独立修订）、模拟媒体提供方的分别确认与幂等派发及项目替换后不继承授权。
- `tests/host-smoke.cjs --assembly-only` 同一运行方式通过：预设装配、候选条目与模块解析、标准工具不被收窄三项成立，跳过真实渲染部分。
- **22 个脚本**通过 `node --check` 语法检查（`index.js`、`tools/` 11 份、`tests/` 10 份）。

## 本版一次真实缺陷的复盘

重构 `index.js` 的媒体授权存储适配器时，把项目身份 `identity` 收进了 `mediaStoreFor()` 的局部作用域，而下游 `saveArtifact` 的闭包仍在引用它。

- **语法检查没有抓到**：`node --check` 只查语法，不做作用域分析。
- **单元测试没有抓到**：它们调用的是 `tools/` 里的函数，不经过 `index.js` 的闭包。
- **隔离宿主冒烟抓到了**：真实调用 `generate_one_asset` 时抛 `ReferenceError`，被授权层收敛成"工件保存失败并封锁授权"。

修复后补了 `tests/tool-wiring.test.js`，把这一层钉住。教训记录在此，因为它正是"能编译 ≠ 能工作"的一个具体实例：这类错误只有跨层调用才暴露。

## 本版在现用 Profile 上的安装

- Desktop Profile 的依赖已从 `0.4.0-rc.4` 的 tgz 改为本版 `0.6.0` 的 tgz（`.../control-your-video-v2-night/output/dsh-plugin-control-your-video-0.6.0.tgz`），并就地替换了 `node_modules` 里的安装副本；`pnpm install --lockfile-only` 已把锁文件对到新包。
- 备份：`package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml` 各有一份 `*.bak-cyv-0.6.0-20261122-211215`；旧安装副本完整复制在 `.../control-your-video-v2-night/backup-installed-0.4.0rc4/`。
- 安装后对**已安装副本**重跑 `preset-check`：28 行挂载成功，2 行按平台或配置禁用；该副本与仓库里的 `skills/**` 逐文件哈希一致。
- **正在运行的宿主进程仍加载着 `0.4.0-rc.4`**，需要重启 DSH 并新开会话才会切到 `0.6.0`。这一步没有在本轮验证——重启会终止进行中的会话。
- 过程记录：正在运行的 watcher 占着安装目录，目录本身无法改名，所以采用"清空内容 + 解包覆盖"的就地替换；文件级写入与删除均正常。

回滚：把依赖改回 `.../v13-dev/output/dsh-plugin-control-your-video-0.4.0-rc.4.tgz`，恢复 `package.json.bak-*` 与 `pnpm-lock.yaml.bak-*` 后 `pnpm install`；或直接把 `backup-installed-0.4.0rc4/` 的内容复制回 `node_modules/dsh-plugin-control-your-video/`。

## 这版没有证明什么

- 没有真实生成服务、没有真实计费、没有上传。模型路径全部用模拟提供方验证。
- 没有跨类型作品验证，没有 Skill 净增益的 A/B 对照，没有多用户或多平台验证。
- 没有在本版 Desktop 上完成一次真实作品。安装、手动交互与完整作品体验仍留给用户。
- 专业知识里的阈值仍来自文档与资产记录，不是本项目实测。各份知识的来源、验证程度与缺口见仓库根 `PROVENANCE.md`。
- `evidence` 的 `measure` / `recall` / `gc` 没有自动化用例；`sheet` 与 `extract` 有。

## 如何复测

```
npm test
node --check index.js            # 以及 tools/ 与 tests/ 下各脚本
```

用正在安装的 DSH 的 Node 运行装配检查与冒烟（Windows Desktop 可经 Electron 的 Node 模式启动）：

```
set ELECTRON_RUN_AS_NODE=1
"<安装目录>\DeepSeek Harness.exe" tests\preset-check.cjs <DSH 包目录> <本包绝对路径>
"<安装目录>\DeepSeek Harness.exe" tests\host-smoke.cjs <DSH 包目录> [--assembly-only]
```

真实 Desktop 安装后在**新会话**中按[用户验收指南](验证指南.md)验证意图、小样、完整成片与反馈体验；Skill 行为用 `tests/` 下的 15 份人工用例（另有一份索引）逐个新会话跑，不点名技能。

## 历史记录

`0.4.0-rc.1` 曾使用受限预设（只读图片访问、一个研究子代理，无通用 Shell），围绕它跑的"拒绝未挂载工具"断言只描述那一版。`0.4.0` 起取消收窄，`0.5.0` 与本版的冒烟断言的是相反方向：标准工具不被收窄。本版沿用这一口径，未重新引用旧断言作为门禁证据。
