# 工程验收记录

## 环境与范围

- 本记录对应 Control Your Video 0.5.0。代码以公开 0.4.0 为基础，合入本地 v2.2 候选的外部制作路线与项目级模型授权；原开发工作树和现用 Profile 不属于测试写入范围。
- 实际执行环境为 Windows 11、DSH Desktop `0.2.2-rc.5`、Node 24.22.1 和 FFmpeg/FFprobe 9.0.1（`full_build`）。其他平台与其他宿主版本由各自环境验证。
- 隔离宿主测试使用已安装 DSH 的真实 Cordis、工具注册器、原生执行器、用户提问服务及 JSON 存储。项目、存储和测试用户答复是测试夹具；没有改动用户实际 profile，也没有使用生成服务或私人资料。

## 设计取舍及覆盖范围

- 视频预设**以标准预设的工具清单为底**，一个不减，再额外挂上 `cyv`、`evidence` 和审批存储。因此助手在本预设里拥有与标准模式相同的 Shell、文件读写、后台任务、子代理、工作流和计划模式能力。标准预设本身未被修改。
- `tools/preset-policy.js` 是**空实现**（只声明 `inject = ['tools']`，`apply()` 无操作）。它保留为插件行以便已安装的配置继续激活，不设任何插件级的全局门禁，也不收窄工具。
- 因此审批是**流程约束，不是运行时硬门禁**。`cyv` 的三个确认点由宿主接口取得真实用户回答并绑定内容版本，改项目里的文字状态不会获得制作权限；但通用 Shell 存在的前提下，理论上可以绕过 `cyv` 直接渲染而不经过小样认可。这一点如实记录，不作为“不可绕过”宣称。
- `plan.md` 走契约检查：认镜头表或逐镜小节两种写法，查缺镜、单镜与合计时长、素材三态（已有／待产出／真缺）。它判结构、时长与可核实性，不判创意可行性或审美；`review.required` 恒为真，`pass` 之后仍需人审。
- FFmpeg 是内置的验证路线，不是唯一路线。助手可以用 Shell 调用本机 `node`、`python`、FFmpeg 或其他已装工具自行出片，也可以用 `cyv` 走带审批的内置路线。
- 生成模型默认不存在。宿主可扩展发现和连接模型提供方。项目级授权分别确认具体模型、用途、提示词传输范围和累计预算；授权范围内调用与重试由 Agent 安排，相同操作标识重放原结果，不重复占用费用。费用或交付结果不明时保留占用并阻断该授权。仓库测试不连接任何真实提供方。
- 当前保留 13 个 Skill 的分工，并把创作意图与完整方案统一到 `plan.md`。Skill 的净收益与真实 A/B 结论仍待验证。

## 已观察结果

- `npm test`（`node --test tests/*.test.js`）在本版复测为 **104 项通过、0 失败、0 跳过**，包含真实媒体用例。用相同时间点的解码画面摘要验证修订只改变目标字幕所在镜头，旧文件仍可读取；并发输出同名文件时仅有一个成功。
- `tests/host-smoke.cjs` 通过已安装 DSH 的真实工具执行器与本机 FFmpeg 跑通全流程：结构上确认标准行（`tool-pwsh`、`tool-bash`、`tool-fs`、`tool-fs-search`、`tool-jobs`、`tool-schedule`、`tool-todo`、`tool-web`、`present`、`tool-plugin-manager`、`delegation`、`tool-ask-user`）全部保留，`cyv` 与 `evidence` 出现在同一预设；运行期断言 `pwsh`、`write`、`edit`、`read`、`subagent`、`todo_write`、`ask_user_question` 均可用。测试用户答复贯通真实执行器，产出 1 秒小样、2 秒全片和 2 秒修订版，FFprobe 验证 H.264 与 AAC，成功抽取实际视频帧，宿主存储保留相应批准与工件摘要。
- `tests/host-smoke.cjs --assembly-only` 同一运行方式通过：预设装配、候选条目与模块解析、标准工具不被收窄三项成立，跳过真实渲染部分。
- 同一冒烟测试用外部测试 MP4 验证复制到另一个项目、独立字幕任务保留音轨、原件字节一致；测试库的按场景收录与授权检索成功。
- 外部本地路线通过 `prepare_run` / `register_artifact` 贯通小样、全片与完整修订：实际 MP4 完整解码，首中尾三个位置与声明镜头对应，登记结果另存且不覆盖旧版。
- 模拟媒体提供方贯通用途/传输范围与累计预算的分别确认、操作重放、项目替换后的授权隔离。真实隔离 DSH JSON 存储另重开两次，已用预算、工件摘要与费用结果不明后的阻断均保留。同一 Profile 的多进程计费互斥未纳入。
- 已解析发布包的安装配置及模块入口。本版真实 Desktop UI 安装、手动交互与完整真实作品验收仍留给用户。
- `tests/preset-check.cjs` 用同一 Electron Node 运行方式执行（`ELECTRON_RUN_AS_NODE=1`，DSH CLI 包目录作第一个参数、本包**绝对路径**作第二个参数）：28 行声明全部挂载成功，没有配置或解析错误；2 行在本平台未生效（`tool-bash` 在 Windows 上禁用、`tool-plugin-market` 按配置禁用）。用系统 Node 直接运行会因 `app.asar` 内虚拟路径无法解析模块而失败；用相对路径 `"."` 作包目录会让 `createRequire` 收到 `package.json` 报错，必须给绝对路径。

## 关于 0.4.0-rc.1 的受限预设

rc.1 候选包的 `cordis.patch.yml` 当时只挂了只读图片访问（`dsh-tool-fs` 关闭读写）与一个研究子代理，没有通用 Shell、文件写入、定时任务与工作流，并由非空的 `preset-policy` 行做收窄。围绕那一版跑的隔离执行器断言（“拒绝未挂载的通用 Shell、文件写入、定时、编排和 Fork”）只描述那个受限预设。

历史记录称 rc.3 起取消收窄，且正式 0.4.0 与 rc.3 的 `cordis.patch.yml`、`index.js` 哈希一致；本发布轮没有重新取得 rc.3 归档复核该哈希关系。因此那些旧的“拒绝”断言**不能当作 0.4.0 的门禁证据**，本记录也不再引用它们作为能力声明。0.5.0 的现行冒烟测试断言的是相反方向：标准工具不被收窄；本版 `cordis.patch.yml` 与公开 0.4.0 不同。

## 如何复测

- `npm test` 运行方案检查、项目与素材、审批绑定、本机制作与经验库的本地测试，含真实媒体用例。
- 用正在安装的 DSH Node 运行 `tests/host-smoke.cjs` 与 `tests/preset-check.cjs`，第一个参数为 DSH CLI 的包目录，`preset-check` 还要给本包的**绝对路径**。Windows Desktop 可经 Electron 的 Node 模式启动：设置 `ELECTRON_RUN_AS_NODE=1` 后执行 `"<安装目录>\DeepSeek Harness.exe" tests\preset-check.cjs <DSH 包目录> <本包绝对路径>`。`host-smoke` 加 `--assembly-only` 可验证预设装配与标准工具的保留情况。
- 在真实 Desktop 新会话中按[用户验收指南](验证指南.md)验证意图、小样、完整成片和反馈体验。
