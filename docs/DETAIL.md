# Control Your Video

从聊天里的想法和素材出发，一起做完整视频。助手负责理解和组织制作，创意方向、完整方案、小样和最终效果由你判断。

插件版本 0.6.0（V3）。这一页说明它怎么工作、边界在哪；安装与最短上手路径见 [README](../README.zh.md)。

## 开始创作

新开 DSH 会话并选择 **视频创作**。给助手一个想法、脚本、当前项目素材或明确的修改请求。

完整视频依次经过三个确认点：

1. **创意方向**。助手提出少量真正有区别的方向并说明代价，你用 `cyv` 的 `creative` 确认。
2. **完整方案**。全片逐镜写进 `plan.md`：每镜观众看到什么、在变什么、为什么在这一镜、**用什么做出来**；关键技术与具体模型（如果用到）、用途、费用上限与拟外发范围也写在同一份方案里。先过 `plan-check`，再批准这个版本（`approve_plan`）。
3. **代表性小样**。按批准的制作路线做出真实小样，你**看过并认可**（`approve_sample`）后才进入全片。

**批准方案就是认可方案里写明的技术选择**，之后在已说明的范围内自主执行、调整与重试，不会为同一个选型再问你一遍。超出已写明范围（新增费用、新的外发、换掉关键路线）才需要另外授权。

每次认可都记在宿主里并绑定内容版本：方案认可记 `plan.md` 摘要、制作范围与小样镜头选择，小样认可记样片 SHA-256。方案改动后之前的认可不再算数。

修改会另存完整新版并保留旧版。只处理现有片段的字幕任务有独立入口 `subtitle_edit`，不必走三个确认点；改字幕、修一段声音、审一支已有视频、判能不能发这类局部任务，都按任务本身的范围做。

项目放在工作区里的普通文件夹。当前作品的用户素材复制到项目内并保留原件。仅在你选择后，已交付作品的经验或资产才按使用场景复制入本地库。

## 三个确认点能保证什么

- 保证：在 `cyv` 路线上，助手继续制作时依据的是你确实批准过的那个内容版本；改项目里的文字状态拿不到制作权限。
- 不保证：技术上无法绕过。预设挂的是标准工具清单，Shell 与文件写入都在，本机渲染可以不经 `cyv` 直接驱动。这套确认是流程约束，不是运行时硬门禁。详见[工程验收](工程验收.md)。

## 可用制作方式

**没有预设的技术清单。** 助手可以用代码、浏览器出帧、三维、实拍剪辑、程序化图形、生成模型或任何经核实可用的方法，也可以为某一镜现写一段程序。随包的内置 FFmpeg 路线只是一条可用的兜底，不是能力上限——`cyv` 的 `local_capabilities` 报的是本机真能找到的版本与编码器。

自选本机路线的正式流程：`approve_plan` 的 `external` 参数固定引擎、画幅、帧率、音轨要求与需要固定的输入；`prepare_run` 取得阶段身份与预期参数；做完用 `register_artifact` 登记。**登记的必须是你自己组装好的完整 MP4**——画幅、帧率、帧数要与方案对上，能完整解码。图片序列、分轨音频、工程文件留在项目工作目录，不作为正式交付登记。

生成模型可选，不是前提。宿主插件可以提供 `controlYourVideoMediaProviders` 服务，项目授权绑定具体模型、用途、提示词传输范围与累计预算；在已说明范围内可自主调用与重试，同一操作重放不重复占用费用；费用或交付结果不明时会保留占用并停止派发。

**当前授权通道只接受提示词文本**：参数里出现图片、视频、素材路径一律拒绝，所以参考图与首尾帧生成目前没有通道。需要时必须如实说明并商量替代，不能假装能发图。本仓库只用模拟提供方验证，尚未连接真实计费服务。

专业 Skill 按任务加载，见下节。公开资料核对可以交给另一个独立预设：它挂网页检索与读取、文件查看、待办与提问，负责查证公开来源，创意与制作仍归主会话。

## 专业知识的组织

两条知识族 + 必要的直接入口 + 横向支撑，共 8 个注册 Skill、48 份按需参考：

| 入口 | 管什么 |
|---|---|
| `video-craft` | 观众看到与听到的这一层：症状分诊、叙事、视觉、运动、声音、剪辑、屏上文字、跨域裁决、审美判断怎么写 |
| `video-types` | 怎么做出来，以及每条路线独有的风险：代码/实拍/三维/生成/混合 |
| `video-intent` | 感受词、参考片、零散材料 → 可用的创作意图 |
| `video-plan` | 单一 `plan.md`：结构、时长、逐镜可执行、小样选择、修改影响面 |
| `video-review` | 取证协议、修改单、有依据的专业判断 |
| `video-release` | 能不能发/交/用：标识、许可、肖像、响度门槛、交付清点 |
| `video-library` | 跨作品经验与资产的查、用、存 |
| `video-skill-authoring` | 什么值得沉淀、怎么写能被触发、怎么验 |

正文只写判断，深入方法放在各自的 `references/` 里，按需读。模型型号、平台阈值、法条版本这类会过期的东西不写成结论，只写"去哪查、怎么核"。

## 经验库

位置是 `<工作区>/control-your-video/`。你不主动要用，它不会被创建，也不会铺占位文件。条目按**使用场景**归类（叙事与剧本／视觉与美术／角色与场景／镜头与运动／代码动画与特效／声音与配乐／剪辑与后期），读与写都要你明确同意，收录发生在交付之后。

它和"用户自己的研究资料库"不是一回事：本插件不建索引、不复制、不改动后者；那些资料只在本次明确授权时按路径只读地看。
