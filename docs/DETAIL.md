# control-your-video 视频创作

这个插件包只做一件事：让助手真的会做片子。

## 提供什么

- 一个 **视频创作** Preset。选中后，会话的身份是视频创作助手，能读写文件、运行本机命令、发起长任务、按需加载方法。
- 十三个方法技能，按任务分工，不是按工序：

| 技能 | 什么时候用 |
|---|---|
| `video-intent` | 说不清想要什么、丢来参考片说"就要这样"、材料一堆但没方向 |
| `video-plan` | 要一支片的整体方案、片型、结构、时长、镜头规格、参考重构、小样 |
| `video-script` | 写口播、解说、旁白、标题；把文章改成口播；清 AI 味 |
| `video-visual` | 配色、字体、版式、封面、3D 与空间 |
| `video-motion` | 单个元素怎么动、为什么像 PPT、缓动与效果库 |
| `video-prompting` | 某个模型的提示词怎么写、参考各控制什么、生成结果不对怎么归因 |
| `video-code-visual` | 用代码/Canvas/three 出画面，以及代码画面的验收 |
| `video-edit` | 转场与整体节奏、剪辑点、字幕排版、旁白对不上时重算时间 |
| `video-sound` | 真人/TTS/已有配音/无人声选哪条，表演、音乐音效、同步与混音 |
| `video-review` | 带着问题取证、看哪几秒、产出修改单与证据条目 |
| `video-release` | 能不能发：AI 标识、许可与肖像、响度门槛、交付清单 |
| `video-library` | 把这次的做法记进你自己的资产库，以及整理那个库 |
| `video-skill-authoring` | 把一套做法提炼成技能，以及验证它到底有没有用 |

- 四十八份按需参考，挂在各技能自己的 `references/` 下。正文只写"什么时候读哪一份"，不预先塞进上下文。
- 一份接口约定 `docs/编写规范.md`：五个共享接口（镜头规格、意图摘要、修改单、库条目、证据索引）只在那里定义，各技能只引用不复述。
- 一个取证与门禁工具 `evidence`：`extract`／`measure`／`recall`／`gc` 四合一，外加 `plan-check`——开工前检查方案是否完整，有红不许进制作。选装，不是必需——没有它照样能做片，只是"看过了什么"没法留档、也少一道门禁。

## 怎么用

1. 装好本插件，**新开一个会话**并选择 **视频创作** Preset。Preset 的改动只对新会话生效。
2. 把想法、文案、素材或修改意见直接说出来。不需要先填表单，也不需要懂参数。
3. 助手会给出可感知的方向与整体方案，需要时做一段小样给你看。看过再改。
4. 作品放在你自己的普通文件夹里，插件不会把它搬到别处，也不锁定格式。

第一次用会碰到一件反直觉的事：**你的资产库是空的，而这是对的**。库不是预装资料，是你自己的片子里长出来的。第一支片结束时助手会问你"这条要不要记下来"，那时才开始有第一条。详见下面的"疑问"。

## 你的资产库放在哪

两处，别混：

| 是什么 | 在哪 | 谁写 |
|---|---|---|
| **你的资产库**（跨作品的经验） | `<工作区>/control-your-video/` | 每支片结束后，助手问过你才写 |
| 这次作品的文件（方案、素材、成片、证据） | 你的作品文件夹，随便放哪 | 做这支片时写 |

库的结构由 `video-library` 定义，一共七个位置：

```
<工作区>/control-your-video/
  index.md          一行一条的入口，读库只从这里进
  preferences.md    你的审美偏好与硬约束（"我不喜欢蓝紫"）
  methods/          方法卡（"这类片子里蓝紫会抢主体，因为……"）
  prompts/          某个模型在本机实测出的配方，带失效条件
  references/       参考片拆解：借了什么、不搬什么
  templates/        可复用的段落结构（几段、什么顺序、多长）
  lessons.md        踩过的坑与它的识别特征
```

只建这次真要写的那一个文件，不预建空目录、不铺占位文件。库长到一屏读不完（约 40 行以上）就先整理再写新的。

## 不提供什么

- 不做创作页面或时间线编辑器。看片、提意见都在对话里。
- 不带渲染、模型或音频服务。这些用你本机已有的工具，缺什么会告诉你。
- 不附带任何素材、字体、音乐或资产库内容。随包的只有方法、代码与文档。
- 不管理作品版本，也不建立数据库。文件就是文件。
- 不保证任何具体模型或工具的能力。实际能不能做，以本机执行结果为准。
- 不替你判断好不好看。技术检查、已看证据、你的判断是三件事，报告里分开写。

## 状态

**0.3.0。做过一次全量实测**：用一支 5 分 12 秒的 B 站科普片从零跑到交付，13 个技能全部被加载使用，`evidence` 的 `extract`／`measure`／`recall` 三个动作在真实成片上跑通。

0.3.0 改的是流程本身：三个必经确认点（意图后、方案后、小样后）、完整方案的十节定义、镜头第 11 字段「动源」、以及一道 `plan-check` 门禁。**这套新流程还没在真实片子上跑过一遍**，已知会在旧 plan 上报红。详见 CHANGELOG。

**但要知道证据到哪为止：**

- 只有一次全量实测，**没有 A/B 对照**，所以不能说"装了它比直接用提示词更好"。
- 那次没有音频回放与连续播放通道，所有观感结论都是机器测量与抽帧推断，**没有人真的连看一遍**。
- 生成模型路线、Remotion、Canva 未测；`evidence` 的 `gc` 动作未在真实场景跑过。
- 资产库产出过一次（7 类 8 个文件），但**没有跨第二支片验证过复用**。

## 疑问

**第一支片之前，库里什么都没有，助手怎么办？**
照常做。它不会凭空说"以前我们是这么做的"——`index.md` 不存在就说明库还没建，它会老实按技能正文的方法做。等这支片有了你认可的做法，它再问你要不要记一条。

**能直接用别人分享的库吗？**
能，但那是别人的经验，适用条件未必对得上你。库里每条都带"适用条件"与"失效条件"，照抄前先读那两句。分享自己的库也没问题——库是你的文件，许可由你定。

**要找某个技能的细节在哪？**
技能正文在 `skills/<名字>/SKILL.md`，细则在同目录 `references/` 下。正文会写清楚"什么时候读哪一份"。
