# 用户验收指南

## 安装

1. 在 DSH Desktop 中安装 0.4.0 的本地目录或发布包 `dsh-plugin-control-your-video-0.4.0.tgz`，按宿主提示**重启**后**新开**视频创作会话。
2. 为真实试验选择单独的工作区。启动前可让助手用 `cyv` 的 `local_capabilities` 确认本机能找到 `ffmpeg`、`ffprobe`，并具备 H.264/AAC 编码器与字幕所需字体。工程侧探测环境为 Windows 11、FFmpeg 9.0.1。
3. 用「我想做一支 20 秒、让我能看出信息从混乱变得有序的短片。用本地程序图形或我给的素材，不调用外部生成模型」开始，也可直接使用你真实想做的题材。

## 完整作品

| 你做什么 | 预期看到什么 |
|---|---|
| 给一个尚未说清的方向 | 助手用文字提出少量有实质区别的方向，说明推荐与关键问题。确认后再集中调研。 |
| 确认创意 | 助手提交完整计划，可检查每镜的时长、画面、声音、素材与具体做法。尚待制作的素材应有可执行路径。 |
| 先退回方案，再批准修订版 | 退回时不会开始小样。批准只适用于你看到的完整版本。 |
| 观看小样，先要求改一处 | 主路线和小样一致。样片未获认可时不制作全片。 |
| 认可当前小样 | 开始全片制作。你应收到一份能够连续播放的完整 MP4。 |
| 先给一句含糊审片意见，再给具体字幕修改 | 含糊时应先问清。改好后另交完整新版，旧版和认可内容可比较。 |
| 告知满意 | 完成最终文件交付。是否沉淀经验由你选择。 |

可在会话中让助手用 `cyv` 的 `status` 检查当前方案与小样状态。机器检查仅验证可枚举的版本、媒体和目录行为。请用你的眼睛和耳朵判断节奏、可读性与创意是否符合期待。

## 再测两个独立场景

- **已有片段的字幕**。把原片交给这个项目，指定确切字幕文案，只要求生成一个完整新版。检查原片保留。该任务走 `subtitle_edit` 独立入口，不需要创意方向与方案批准。
- **跨作品经验**。完成一支片并明确同意收录一个条目。检查它是否按使用场景归类、是否保留项目副本和适用条件。开一个新项目时，只在你授权后查阅历史库。

## 判定与反馈

记录失败发生在哪一步、你当时的原话和正在看的视频版本。优先反馈你最关心的效果，例如「第 12 秒的字太小」「小样的镜头节奏与整片不同」「我刚确认了 v2，却渲染了 v1」。可在本包目录运行 `node --test tests/*.test.js` 重跑自动用例。

制作前的两次确认与小样确认由宿主记录的用户回答绑定到具体内容版本。通用 Shell 和文件工具仍然可用，所以这套确认是流程约束，不是不可绕过的安全边界；助手可以直接写代码、跑本机命令或用已装工具出片。同一台机器上的其他会话与手工操作也在此范围之外。

模型重试粒度、最终 Skill 架构和内置适配器以外的媒体路线随用户决定和实测结果推进。

## 可选 Skill 对照

等核心流程跑通后，选同一 20–60 秒任务，给两条新会话相同的原始需求、素材和模型。一次保留熟悉的普通方法，一次用视频制作的专业 Skill。记录各自输出的实际视频、逐镜可执行性、纠偏次数、耗时与调用成本。若比较的是 Skill 本身，应尽量保持其余工作方式相同。仅对比普通预设与整套插件时，记录结论为整套体验差异。两边都观看和试听后再判断是否有净收益。

## 已知的验证缺口

- 本指南覆盖的验收项目前由工程侧的隔离宿主与真实媒体测试覆盖。用户在 0.4.0-rc.3 上完成过一次真实最小正片，本指南的其余场景（多题材、跨作品经验复用、已有片段字幕的真实交付）仍待实际运行。
- 只做过 Windows 11 + DSH Desktop `0.2.2-rc.5` 的组合验证，其他平台与宿主版本未测。
