# plan-check 样本说明

这些文件不是"好方案 / 坏方案"的示范，是**给 `tests/plan-contract.test.js` 用的固定输入**。
改任何一个文件都要同步改测试里的断言。

| 文件 | 表达方式 | 用来测什么 |
|---|---|---|
| `valid-plan.md` | 旧格式：状态行 + 一、二、三、九、十 + 11 列镜头表 | 0.3.0 的旧计划仍能通过（向后兼容） |
| `flexible-table-plan.md` | 新格式：自定章节，镜头表列名换成 `Shot/Scene/Length/Approach/Audio/Why` | 换了列名的表仍能被认出 |
| `flexible-block-plan.md` | 新格式：`### 镜 1 · 标题` + `- 时长：…` 逐镜小节 | 不用表格也能表达逐镜方案 |
| `missing-shots-plan.md` | 声明 4 镜，只写 2 镜 | 缺镜必须红 |
| `duration-mismatch-plan.md` | 声明 30 秒，镜头合计 18 秒 | 时长对不上必须红 |
| `planned-assets-plan.md` | 所有素材都是"拟制作/待生成"，文件还不存在 | 待产出素材有路径就**不**阻断 |
| `missing-assets-plan.md` | 素材写成已有或"缺"，文件不存在也没有制作路径 | 虚构资源 / 真缺素材必须红 |
| `invalid-plan.md` | 旧格式的反面样本（无状态行、全片分配当成明细） | 旧问题仍能被抓住 |

## 素材占位文件

`素材/` 下那几个 `.mp4` 是**零字节占位**，只为让计划里"标为已有"的文件在磁盘上真的存在。
它们不是视频，也不该被播放或测量。删除任何一个，对应计划在走真实文件核对的路径（CLI）上
就会变成红灯——那是正确行为，不是测试坏了。

`planned-assets-plan.md` 里的 `work/gen/*.mp4` **故意不存在**：
待产出素材只要有路径就不该被机械阻断，这正是要测的东西。
`missing-assets-plan.md` 里的 `素材/峡谷/drone.mp4`、`素材/山顶/sunset.mp4` 同样不存在，
但它没有写制作路径，所以必须判成虚构资源。
