# 测试任务用例

这些用例不是"检查 Skill 写得对不对"，是**检查模型真的加载 Skill 之后行为有没有变**。

## 怎么用

一次只测一份 Skill，每次都用**新开会话**（老会话保持启动版本，改正文不刷新目录，这是 DSH 机制里的坑）。

测法：

1. 新会话选 **视频创作** Preset。
2. 把用例里的"输入"原样贴进去。前置状态（比如"作品夹里已有 plan.md"）要真的准备好。
3. 只观察行为，不提示技能名。**不要说"用 video-plan 试试"**——那测的是你做提示的功夫，不是触发面。
4. 对照"预期行为"与"失败信号"打分。

## 三层结果，不许混

| 层 | 这次证明了什么 | 不能证明什么 |
|---|---|---|
| 触发 | 这句话确实会加载这份 Skill | 加载后做得好 |
| 行为 | 加载后的第一步动作、产出格式、边界取舍符合正文 | 做出来的片子好看 |
| 效果 | 这次交付的东西用户认了 | 换一个题材还成立 |

只有第三层需要用户参与。前两层自己就能判。

## 失败信号的写法

每个用例的失败信号必须是**可观察的**，不写"效果不好"这种判不了的词。合格的失败信号：出现了某个具体句式、跳过了某个步骤、把某一段写成了不该有的样子。

例如：失败信号不是"回答得不够好"，而是"它先问用户'你想要什么风格'，而不是先给出两三种读法与代价"。

## 一个用例什么时候算过期

- 正文改了某条判断规则 → 对应用例要跟着改，否则测的是旧规则。
- Skill 合并或拆分 → 用例跟着迁移。
- 连着三次跑都过 → 它已经不测任何东西了，换一个更难的输入。
