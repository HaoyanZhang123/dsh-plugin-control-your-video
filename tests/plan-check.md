# plan-check 测试用例

## 怎么跑

```bash
node tools/plan-check-cli.js <作品夹或 plan.md>          # 人读的报告
node tools/plan-check-cli.js <路径> --json               # 机器读
node tools/evidence.js plan-check --dir <作品夹>          # 走统一入口
```

退出码：**有红 = 1，无红 = 0**。所以它能当门禁用。

## 两个固定样本

| 文件 | 应该是什么结果 |
|---|---|
| `tests/plan-check-fixtures/valid-plan.md` | 退出码 0，`✓ 全项通过` |
| `tests/plan-check-fixtures/invalid-plan.md` | 退出码 1，至少报出下面 8 条红 |

## 必测的红（invalid-plan.md 覆盖）

| # | 检查码 | 触发条件 |
|---|---|---|
| 1 | `state-missing` | 没有 `> 状态：草稿｜待审｜已定稿 · rN · 日期` |
| 2 | `section-missing:overview` | 缺「一、总述」 |
| 3 | `section-missing:glance` | 缺「二、总览」 |
| 4 | `section-missing:stages` | 缺「三、阶段」 |
| 5 | `section-missing:materials` | 缺「九、素材需求表」 |
| 6 | `shots-no-motion` | 镜头表缺「动源」列 |
| 7 | `pending-marker` | 正文出现「（估）」「TBD」「待定」 |
| 8 | `shots-howto-bare` | 做法列只写类别词 |

## 边界用例（手工验过）

**裸类别词的判定**——这一条最容易误伤：

| 做法列内容 | 判定 | 为什么 |
|---|---|---|
| `档案片＋调色` | ✗ 裸 | 两个词都在黑名单 |
| `素材` | ✗ 裸 | 在黑名单 |
| `档案片（Prelinger: 001234）` | ✓ 合格 | 括号里有具体条目 |
| `实拍素材 素材/机房/led-close.mp4 ＋冷蓝微调` | ✓ 合格 | 带文件名，不是裸词 |
| `代码排版` | ✗ 裸 | "代码"与"排版"都是类别词 |
| `gpt-image-2.6 出主视觉 + 代码叠粒子` | ✓ 合格 | 带具体模型与具体手法 |

**动源列**：写了七类之外的词 → 黄（`shots-motion-unknown`），不红。留空 → 红。

**动源契约**：主体位移＋运镜占比 < 30% → **黄**，不是红。因为讲解片、情绪片本来就不该到这个比例，只有爽片类才要求。

## 已知局限（不要当成 bug）

1. **只认中文节标题**（「一、总述」这种写法）。换成英文标题会全部报缺——这是有意的，规范就是中文的。
2. **不判内容好坏**。它只回答"写没写、齐不齐、对不对得上"，不回答"这个方案好不好"。
3. **不查总述里有没有视觉与声音的描述**。规范要求了，但那是语义判断，机器判不了。
4. **时长合计只比对阶段表与镜头表**，不比对 `script.md` 里的实测时长——那是回填阶段的事，不是开工门禁的事。
5. **`（估）` 这类词会误伤正文叙述**。如果某一段正文里正常讨论了"估算"这件事，也会触发。改法是把这类讨论移到 `feedback.md` 或方案之外的文档。

## 这条门禁拦的是什么

2026-11-19 两支真实片的实测：

| 片 | 方案覆盖率 | 做法列 | 动源 |
|---|---|---|---|
| 理解一切 | 11 镜 / 110 镜 = **10%** | 11 行全是 `档案片＋调色` | 无此概念 |
| 万年归唐 | 30 镜 / 30 镜 = 100% | 逐镜不同 | 无此概念 |

**两支片在旧规范下都算"合格"。** 一支做到了小样就交付全片，另一支连方案都是事后补的（`plan.md` 比 `script.md` 晚 43 分钟）。

新门禁对这两支片都会报红。
