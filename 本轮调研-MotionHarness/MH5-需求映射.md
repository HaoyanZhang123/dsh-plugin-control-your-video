# MH5 · 需求映射：MotionHarness 的七条能力，各自填我们哪个洞

> 依据标注：`【实测】`= 本轮读工作区文件或跑命令核出；`【审计】`= 上一轮 `本轮审计-20261111/` 已确认、直接引用；`【官网】`= 题目给定描述；`【推断】`= 我的判断，无直接证据。
>
> 许可前提：npm 包实测 **UNLICENSED**。全文不存在"搬代码"这个选项，只有三种动作：学设计自实现、当外部 CLI、不用。

## §0 三句话结论

**一。** MH 七条里只有两条真落在我们缺口上（AI 标记、代码参数隔离），而这两条填的洞我们**已经付过钱、只是没接线**：`editing/annotations.js` 561 行已有对象锚定、帧范围、12 种 aspect、按对象类型白名单、"标注不等于修改授权"的声明【实测】；`media/plan.js` 867 行已让参数成为独立于渲染器的数据。缺的是两端接线——UI 没有入口（`work.js:72` 画布是空的【实测】），模型没有工具（`ctx.tools` 0 命中【审计】）。

**二。** 它和 637 张卡**不是竞品**：MH 七条里没有任何"效果"，它自己不含动效库；637 张卡不含任何工程契约，自己不会出片。但"用 MH 当执行器"是错的——卡是 `HTML + stage.js + __seek`，零转换就能逐帧确定性渲染；MH 是 React，要接就得把 GSAP `snippet` 翻译成 React 组件，可机械转的只有 316 张（gsap 213 + css 103），其余 321 张要重写，而 **509 张连 `index.html` 都没有**，任何执行器都救不了。给已经能跑的东西加一层翻译是纯亏。

**三。** 建议只有一个：**不引入 MH，只带走两条设计**（第 ⑥ 条的"单一消费入口"、第 ② 条的"点画面即写"），并入上一轮六个动作，**顺序不变，动作一仍第一**。收益不对称：能立即兑现的只有这两条；其余五条要么我们更强（`versions.js` 1,312 行【实测】）、要么前置不成立（界面编辑要先有画面）、要么不需要（达芬奇往返）。

### 1.2 展开一：AI 标记——填的是"审阅从读变成改"，但我们缺的 90% 是接线

**它做的**（官网）：点画面 → 出现标记 → 写"这里应该……" → 交给 Agent → 回来看结果；也能在时间线打标记、按标记切风格。

**真问题不是"能加备注"。** 是：**"我觉得这儿不对"这句话机器没法执行。** 它至少含四个信息：哪个对象、哪一帧、哪个属性、改成什么。少一个 Agent 只能猜；猜错下一轮重说。回路就这么从 5 分钟涨到小时级。

**我们缺什么——精确地说是三件事：** 锚点数据**有，且比它严**（`annotations.js` 561 行；`AnnotationAspect` 12 种；`ASPECTS_BY_KIND` 规定"每种对象只说诚实的那些 aspect，绝不给万能列表"；存标注版本上的不可变快照【实测】）；**UI 入口没有**（`work.js:72`；画布只在选中已上传图片时显示那张图，`actions.js:250` 用 session-only `objectURL`【审计 1.3】）；**模型读取入口也没有**（`inject = ['webServer','connection']`；`apply` 唯一副作用 `ctx.webServer.register({kind:'prefix'})`；19 条路由全给浏览器【实测，`ui/host/index.js:17,54`】）。

**所以结论反直觉：这一条我们缺的是接线，不是能力。** 它的标记是**便签**（贴画面，靠人读），我们的标注是**可复算的锚**（贴对象+帧+版本，靠程序读）。便签优点是输入成本低，锚的优点是可验证。要学"输入成本低"，三条：**① 点画面即写**，不要先选对象再开表单——`selection` 机制已存在（`actions.js:163-447`【审计 1.3】），缺的只是"点到像素→反查对象"，这依赖动作一，`web-scene` 一出画面点画面就是点 DOM。**② 标记要编译成"意图"而非"任务"**——标记写"这儿太挤"，Agent 应拿到"frame 42–78 / object `t-03` / aspect=layout / 当前 box"；`plan.js` 天然能做，参数是数据，取当前值是读字段，不是解析自然语言。**③ "按标记切风格"这条别学**——它给了标记一个不属于它的职权，`annotations.js` 开头写死了：*"An annotation is discussion, not a modification authorization"*【实测】。

**代价**：数据 0 人日（已有），UI 锚点 ≈1（排在动作一后），两个工具 ≈1，**合计 +2 人日**。判据：连续三次修改，从"点一下写一句"到"看到改后那一帧"≤5 分钟，中间无人工翻译步骤。

### 1.3 展开二：代码参数隔离——填的是 D1，但 D1 不是"少修一个字段"

**D1 表现**（依据 `实施交接/证据/C16-证据/03-实测缺陷与限制.md`，经【审计 1.6】确认）：同一对象改属性，两次渲染**逐字节相同**；`fit`/`box` 被渲染层忽略。

**一种常见但不彻底的读法**：这是"修两个字段"的 bug，修完就好。**错在哪**——修完这两个，下一个字段还会漏，因为缺陷层次不是"字段实现不全"，而是：

```
plan.js（参数是数据，867 行，独立文档）
   ↓
ffmpeg / remotion / hyperframes 三个适配器
   ↓  各自用自己的"我认识哪些字段"
   ↓  不认识的字段 → 静默丢弃（不报错、不警告）
   画面：什么也没变
```

**这三个适配器就是三个私自决定者。隔离有了，强制没有。"静默丢弃"四个字就是 D1。**

**MH 第 ⑥ 条为什么能治**：不是因为分了三个文件夹（那只是形式），是因为**渲染入口唯一**——React 组件拿 `document.json` 当 props，没有第二个消费者能私自决定读什么。"改参数"这条路**在结构上**不经过任何人判断，必然到达渲染。

**处方分两级，第一级就够用。**

**一级（+1–2 人日，立刻做）：适配器能力声明 + 渲染前强制校验。** 每个适配器导出冻结的 `CONSUMES`（实际消费的字段集合），像 `plan.js` 的 `OBJECT_KINDS`/`TRANSITION_KINDS` 那样是冻结常量【实测，`plan.js:41,108`】；渲染入口在交给适配器前做覆盖校验：**plan 里每个对象字段必须被某个 `CONSUMES` 覆盖，未覆盖 → 拒绝渲染并列出字段名。** 效果：`fit`/`box` 从"静默丢弃"变成"渲染被拒绝"。**这不是修好 D1，是让 D1 这一类不可能再发生**——下一个未实现字段会在第一次渲染就炸，而不是三个月后在证据里被发现。这也正是用户原则的落地：**字段覆盖是形式化问题，不该交给"适配器作者记得"。**

**二级（+2–3 人日，随动作六做）：三适配器收敛。** 上一轮已提出合成两个，理由是"能力完全相同——共享同一个对象模型，换适配器不会变好"【审计 2.1】。**这句话现在同时是 D1 的注解**：三个能力相同的适配器只会让"谁读哪个字段"变成三份要同步的口头约定。收敛到一个，`CONSUMES` 只剩一份，强制校验近乎免费。

**连带结论：第 ⑤ 条在 MH 里成立，是因为第 ⑥ 条先成立。** 拖关键帧如果底层还是"改属性画面不变"，你会得到一个手感很好但画面对不上的面板。**顺序不能倒**——所以第 ⑤ 条判"不照搬"，不是它不好，是它排在我们动作一之后。

## §2 与 637 张卡的关系（本文最重的一节）

### 2.1 先给判断

**互补，不是竞品。但在"谁当执行器"上，637 张卡 + 我们自己的 `web-scene` 应该赢；MH 只能当设计参考，不能当默认执行器，也不值得当外部工具。**

### 2.2 它们不在同一层，所以不是竞品

**MH 自己不含任何效果。** 七条全在流程侧：工作台、标记、版本、导出、界面编辑、参数隔离、达芬奇桥。没有一条是"这个动效怎么做"。它的 `document.json` 是空骨架，填什么由写 React 的人决定。**637 张卡自己也不含任何工程契约**：它有一个 76 行的 `stage.js`，没有版本、没有锁、没有恢复、没有交付。它是**一本带可执行示例的词典**，不是工具。

最硬的证据是产物形态不同：MH 产程序（React 源码 + `document.json`），卡产配方（`snippet` + `params` 默认值/范围 + `useWhen`/`badExample`/`avoid`，637/637 全有【实测】）。**程序可以编译出来，配方不能反编译出来**——把 React 代码反推成"何时该用、用了怎样、何时别用"，反推不出来，那是判断不是代码。**配方能生成程序，程序不能生成配方**，这决定了卡是上游、执行器是下游。

### 2.3 用 MH 当执行器，637 张卡还能不能用

**能用，但不是 637 张。要分层，且这个分层必须诚实说出来。**【实测，`index.json` 全量统计】

| runtime | 张数 | `snippet` 形态 | 转 React 成本 |
|---|---|---|---|
| `gsap` | 213 | `tl.to` / `tl.fromTo`，paused timeline | **机械转换**：`useEffect` + `tl.seek(frame/fps)`，同构 |
| `css` | 103 | `@keyframes` + `animation` | **机械转换**：`getAnimations()[0].currentTime = ms` |
| `svg` | 128 | 属性/路径命令式设置 | **改结构**：包 ref + imperative，或重写声明式；`params` 语义会掉 |
| `canvas` | 79 | 逐帧绘制代码 | **重写**：绘制循环与 React 生命周期是两种时间观 |
| `webgl` | 114 | shader uniform 驱动（如 `material.uniforms.blockPx` 用 `tl.to` 改值）【实测样本 `depixelate-reveal`】 | **重建上下文**：renderer、uniform 绑定、纹理生命周期要重管 |

**能机械迁移的上限 = 213+103 = 316 张。** 剩下 321 张要重写，而重写会丢掉卡最值钱的东西。举个具体的：`overlapping-action` 的 `params` 写"部位间时差默认 0.07s，范围 0.04–0.10s"，`avoid` 写"超过 0.12s 禁止（像各自为政）"【实测】。重写成 React 时这两条要么被丢，要么变成 `prop` 的 JSDoc——**而 JSDoc 不会被模型读到**。

**更狠的一条：637 张里只有 128 张有 `index.html`**（128 有 `index.html` + `clip.mp4` + `preview.gif` + `README.md`，完整演示；**509 张只有 `README.md`**，有描述、有参数、有 GSAP 片段，**无参考实现**）【实测】。

**这 509 张任何执行器都救不了**——MH 没有这些效果，`web-scene` 也没有 HTML 可 seek。它们只能靠模型照 `snippet` + `params` 现场写，**而这恰好是"把创造性决策留给模型"的正确用法**，也是动作三（补 `slots` + `verify`）存在的理由。所以"MH 当执行器 + 637 张卡"实际拿到的是 **316 张的可靠迁移 + 128 个演示的画面水平**。

### 2.4 为什么还是不该转——桥存在，但没有修的必要

**技术上桥存在，上面已把 316 张的转法写了。** 但有个被忽略的事实：**卡片不需要桥，它已经是一个可寻址的画面源。**

`lib/stage.js` 76 行【实测】做了：`__seek(sec)` 按秒定位、`__dur` 时长、`__size` 比例（`data-size` 支持竖版）、`__poster` 海报帧、`Motion.rand(seed)` 种子随机数替掉 `Math.random`；配 `?render=1`（不自动播放，只接 `__seek`）、`?t=1.5`（定位某秒）、`?embed=1`（去页眉页脚只留场景）【`stage.js:5,12,25,34`】。

**这比 MH 的 `document.json` 更贴合我们**：MH 要"工程可移交"，我们要"按帧取像素"，`__seek` 正好是按帧取像素。且已验证：同帧 sha 一致、跨进程一致【审计实测：`accordion-expand` t=0.5 → `6002b4d1eeafa52a`】；页内 `toDataURL` 11.5 ms/帧，1440 帧约 17 秒（慢的是 CDP 传 PNG 259 ms/帧，不是渲染）【审计 2.1】。

**所以"用 MH 当执行器"等于：把 128 个已能确定取像素的 HTML 先翻译成 React，再用它的管线取像素。** 多一层、多一处失真、丢掉 `?embed=1` 调好的版式、丢掉 `data-size` 竖版、丢掉"改一行 HTML 就能试"的手感。**纯亏，不是权衡。**

补一条实测：抽样 `svg`/`canvas`/`webgl`/`css` 四类演示，**全部**在 `index.html` 里走 `Motion.timeline()` + gsap【实测】。连 runtime=css 的卡，演示也是 GSAP 驱动的——**卡的 `snippet` 和它的演示本来就是两套写法**，中间已有一道手工翻译。再叠一层 React，是第三层。

### 2.5 不用 MH，637 张卡 + `web-scene` 够不够

**够，这是唯一不亏的组合。但要承认两处不够。**

**够的部分（有实测支撑）：** 画面源 128 个演示零转换（`__seek` + 页内 `toDataURL` + FFmpeg 收帧，`CompositionPlan` 其余一行不改，6–10 人日）；确定性已实测；**2,686 条已声明参数**直接当工具 schema 字段来源；**637 条 `badExample` + `avoid`** 是任何执行器都不会自带的东西——"怎么拍好看"只有 1,176 行代码【审计 1.5】，而这 637 条是现成的、带具体数值的禁令；4 张决策表 + 11 套 recipes（`steps` 是卡的有序组合，可直接当编排模板）+ 7 条 routes【实测】。

**不够的两处：** ① **509 张没有可执行参考**，上限是"模型照描述写实现"，成败看卡的质量——正好是动作三要验的事（抽 10 张只读卡实现，≥7 张跑通 `verify`）【审计动作三判据】；② **风格是"杂志/讲解片/信息图"，不是"世界感"**，上一轮已点明这个岔路【审计 4.3】，**MH 也救不了这一条**——它同样没有 3D 场景库。

**本节结论：卡是知识（配方），MH 是执行器（程序），两者互补；但在执行器这一层，`web-scene` 已是更便宜、更准、更快的那一个，MH 的 React 执行器在这里没有位置。用卡，用自己的执行器；从 MH 拿设计，不拿代码，也不拿它的运行时。**

"引入"在这个许可下不是加依赖，是改变设计。所以下图是"照它的设计改过之后的我们"。

### 3.2 哪些层被替换

**诚实回答：没有一层被整体替换。** 被补上的是三个**空缺位**——它们现在不存在，所以只能叫"补上，形状照它的设计"：**适配器字段消费声明**（第 ⑥ 条，落在 ② 与 ③ 之间，+1–2 人日）、**标记→修改意图的编译**（第 ② 条，接在 `annotations.js` 后，+2 人日）、**参数面**（第 ⑤ 条前半，④ 从卡的 `params` 生成 schema，0–1 人日）。

**明确拒绝替换的：** ③ 不换 React（128 个演示零转换，换是纯亏，§2.4）；② 不换秒制（`plan.js` 用整数帧并重算全部派生值：*"a hand-edited plan that disagrees with itself fails loudly instead of rendering something else"*【实测】，秒制会给回浮点误差）；① 不换（`versions.js` 1,312 + `candidates.js` 四态——接受候选 ≠ 确认整片 ≠ 持久化效果【实测】，粒度比"一键撤回"细得多）。

### 3.3 模型在哪，看到什么

**位置：④ 接口层。** 不进 ①（不许直接写项目文件），不进 ③（不许直接改渲染器）。

| 它看到的 | 它看不到的 |
|---|---|
| `cards.search` 返回的 **2–3 张候选卡**：slug、oneLiner、useWhen、params（默认+范围）、badExample、avoid、对应 `clip.mp4` | 637 张全集（只会淹死它） |
| `evidence.read` 的**一帧或一组帧** + 上次 sha + `field-diff` 字段级差异 | `CompositionPlan` 完整 JSON（吃上下文，且不需要） |
| `annotation.read` 的**结构化意图**：frame 42–78 / object `t-03` / aspect=layout / 当前值 / 用户原话 | 完整聊天记录 |
| `render.preview` 的**结果**：哪些帧、多久、与上一版 sha 是否相同 | 三适配器内部实现、`CONSUMES` 表 |

**这个分配正是用户原则的落地**：留给模型的是创造性决策（选哪张卡、参数往哪调、标记怎么改）；交给代码的是形式化操作（取帧、编码、字段覆盖校验、版本落盘、diff、证据哈希）。**模型看不到 plan 全貌不是限制，是设计**——只让它通过"卡 + 参数 + 一帧"这个窄口操作，正好逼它做决策而非做文书。

### 3.4 637 张卡在哪

**⑤ 知识层，包外，不进渲染路径。** 它和 MH 的 `document.json` 有个根本区别：

| | MH | 我们 |
|---|---|---|
| 真相是谁 | `document.json` 是**唯一真相** | 卡是**可选真相**，被选中才进 plan |
| 空的时候 | 片子是空的 | 片子是空的，但**候选是满的**（637 卡 + 4 决策表 + 11 recipes） |
| 模型的选择面 | 无限（自己写 React） | 有限但够（15 个 family × 三个难度层【实测 179/306/152】） |

**"可选真相"比"唯一真相"更适合我们**，因为我们的问题从来不是"没有容器"，是"容器里没有东西"——87% 的代码不产生画面【审计 1.5】。**MH 解决容器问题，我们解决内容问题。这是两者可共存、不能互替的根本原因。**

## §4 不引入的反方案

### 4.1 六个动作照做，能到什么水平

| 动作 | 人日 | 完成后第一次拥有的东西 |
|---|---|---|
| 一、卡片接成画面源 | 6–10 | **128 个演示的画面水平**，可 seek、确定性、同帧 sha 可复算 |
| 二、让模型走进来 | 5–8 | 模型**不写任何脚本**，从零做出 10 秒画面，全程在锁内、有证据链 |
| 三、补 `slots`+`verify` | 3 | 卡可被另一个模型**只读卡就复现**（抽 10 张 ≥7 张跑通 verify） |
| 四、回路压到 5 分钟 | 3 | 连续 3 次修改，说话到看到画面 ≤5 分钟 |
| 五、两个白送的 | 3 | 转场 3 种→20+（`ffmpeg-adapter.js:319` 只有 `wipeleft`/`fade`【实测】）；救活 `rotation`（`motion.js:181` 恒 0）与 `loop`（`:194`） |
| 六、做减法 | 0（标记） | 2 万行标冻结，停收维护税 |

**合计 20–27 人日。产出：能出片、能改、能回退、模型在锁内工作、每次改动有证据。** 对照"什么算到了"六条【审计 §6】：能到第 2、3、5 条（关字幕知讲什么 / 抽帧像海报 / 回路 ≤5 分钟）。第 1、4、6 条要靠你的 3D 网页与素材库，六个动作不承诺也不妨碍。

### 4.2 比它差在哪（三条，都是真的）

**差距一：没有"界面编辑"——拖关键帧、调曲线、图层管理。** 差距不是"参数改不了"（参数是数据，改得动），是**改参数的手感**：改 `box` 要改 JSON 或写工具调用，MH 里是拖一下。补齐 3–6 人日，排在动作一之后（`work.js:72` 就是证据）。如 §1.3，它的前置是第 ⑥ 条，**顺序倒了会得到手感好但画面对不上的面板**。

**差距二：没有"可移交的工程包"。** `package.js` 788 行已在做（工程文档 + 版本/决策索引 + 素材字节 + plan 快照 + 恢复说明，排除可重建目录），拒 zip 是对的安全选择【实测】，但**没接工具、没接 UI**，外部拿不到。`.vmg` 是被人用过、有外部认知的形态。补齐 1–2 人日。

**差距三：没有"按标记切风格"这类即席能力。** 它的本质是"把一个整片变更做成有名字的可复用单元"。我们对应的是 `delivery/effects.js` 766 行，门槛更严：**空项目复现门**（必须在空项目用自带输入重新执行、探针通过才允许 `ADOPTED`）【实测】。**机制比它严，只是没接 637 张卡。**

### 4.3 反方案被高估在哪（这一条改变判断）

**"637 张卡"在画面层实际是 128。** 509 张只有 `README.md`【实测】。任何"接 637 张就得到 637 种画面"的期待都是错的。**动作一的真实交付是 128 个画面 + 509 份可被模型读的配方**，这个数字必须写进验收，否则做完会被判"没兑现"。

**动作一的前提我复核过，成立**：`?embed=1` 去页眉页脚【实测 `stage.js:34`】、`__seek` 同帧 sha 一致【审计】、`data-size` 支持竖版【实测 `stage.js:14-17`】。三个风险不变：`params` 字符串级替换失败率（先 20 张批量验，>10% 换策略）、`index.html` 是演示页不是模板、4K 逐帧成本未知（先 1080p）【审计 §5】。

**反方案真正的天花板是"风格"不是"质量"。** 要"一个活的 3D 世界"，六个动作到不了——**但 MH 也到不了**，它没有 3D 场景库。这一条上两者打平，都要自己写场景。

### 4.4 一句话对照

| | 用它（当执行器） | 不用它（六个动作） |
|---|---|---|
| 画面来源 | 316 张迁移后的 React（估 >15 人日）+ 509 张仍空 | **128 个演示零转换**（6–10）+ 509 份配方可读 |
| 模型入口 | 它的 Agent（在它的工作台里） | **`ctx.tools`（在我们自己的锁内）** |
| 治理层 | 它的版本管理（一键撤回级） | **`versions.js` 1,312（回退产生新版本、历史只读、候选四态）** |
| 时间层 | 秒制 | **整数帧 + 有理数帧率** |
| 界面编辑 | **有** | 无（差 3–6 人日） |
| 工程移交 | **有**（`.vmg`） | 有机制无接口（差 1–2） |
| 达芬奇 | **有** | 不需要 |
| 总代价 | **>25 人日，片子出 DSH，锁/版本/证据链旁路** | **20–27 人日，全部在 DSH 内** |

**最后一行是决定性的。** 用 MH 当外部工具，等于把片子搬出 DSH——**这正是现在"模型在门外写脚本"的同一个病，只是换了个门，而且这次门是别人家的、还锁不上**【审计 1.4：门外的人能干活，是因为门没锁，不是因为有门】。

## §5 建议（一个）

### 不引入 MotionHarness。只带走两条设计，并入上一轮的六个动作；顺序不变，动作一仍第一。

**带走的两条：**

**1. 第 ⑥ 条的"单一消费入口"→ 适配器字段消费声明 + 渲染前强制校验**（+1–2 人日，插在动作一里做完）。每个适配器导出冻结的 `CONSUMES`；渲染入口校验 plan 里每个对象字段都被声明覆盖，未覆盖则**拒绝渲染并列出字段名**。这一步不修 D1，它让 D1 这一类不可能再发生；把"适配器作者记得"换成"规则判定"，正对用户原则。连带在动作六把三适配器收敛。

**2. 第 ② 条的"点画面即写"→ 标记两端接线**（+2 人日，插在动作一之后、动作二之内）。UI 端：画面出得来后点像素反查 `data-object-id`，写进已有的 `annotations.js`。模型端：`annotation.read`/`.write` 两个工具，返回结构化意图（对象 + 帧范围 + aspect + 当前值 + 用户原话），**不返回聊天记录、不返回 plan 全貌**。保留我们比它强的那条：**标注是讨论，不是修改授权**。

**另外两处顺手做：** 动作二的 `cards.search` schema 直接由卡的 `params` 生成（2,686 条带 default/range/note，0 人日）；动作三的 `verify` 栏照 `delivery/effects.js` 的空项目复现门来定——一条 `verify` = 一个可复算的帧 + 一个可判定的谓词，机制已有，接上 128 张卡即可。

**明确不做（四条）：** `.vmg` 式 zip 打包（folder bundle 够用，拒 zip 是对的安全选择）；达芬奇往返（没有这个缺口）；MH 的 React 执行器（128 个演示零转换，换是纯亏）；拖关键帧/调曲线的 UI（前置是"有画面"，现在做是在空画布上做面板）。

**理由三条：**

**一、收益不对称。** 七条里只有第 ②、⑥ 落在我们**已付费、没接线**的地方：`annotations.js` 561 行、`plan.js` 867 行 + 三适配器 2,111 行。其余五条——版本（我们 1,312 行更强）、导出（我们安全选择更对）、界面编辑（前置不成立）、达芬奇（不需要）、开放工作台（契约已有更严的整数帧）——要么不需要，要么打平，没有一条值得为它改架构。

**二、许可与位置。** UNLICENSED 意味着只能学设计。而当外部工具会让片子出 DSH，锁、版本、证据链全部旁路——审计已给这个状态命过名：*"门外的人能干活，是因为门没锁，不是因为有门。"* 这一轮所有的钱都花在**把门修好**上，不是花在换一个更大的门外空地上。

**三、执行器之争我们有天然优势。** 卡零转换、确定性已实测、`?embed=1` 已调好；MH 是 React，要转 316 张（估 >15 人日）且丢 `params` 语义，509 张还转不了。**用 MH 当执行器，等于给已经能跑的 128 个演示加一层翻译。**

### 什么情况下我这个建议是错的

| 触发条件 | 该改什么 |
|---|---|
| 片子要**交给别人继续改**，不再是一个人用 | MH 的工程形态（`.vmg` + 参数/源码隔离 + 可移交）价值上升，**该重新评估**，甚至该直接用 |
| 128 个演示的风格被否决（"高级 PPT"，要世界感） | 两条路线都要重估——但 MH 救不了，它没有 3D 场景库；该走"自己写 3D 场景"（8–12 人日）【审计 4.3】 |
| 动作一做完，`params` 替换失败率 >10% | "卡直接当渲染源"前提破了，卡要退化成"知识"，执行器价值上升，**MH 值得重估** |
| 出现"要给别人一个能拖关键帧的编辑器"的明确需求 | 第 ⑤ 条从"不照搬"变"要照做"，且必须排在 §1.3 的强制校验之后 |
