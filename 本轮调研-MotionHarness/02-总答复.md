## 零、一句话

**能融进来的是它的「设计」，不是它的「代码」；而最该融的三条，恰好是我们已经付过钱的。**

具体说：**不引入它的依赖、不引入它的运行时、不用它的 SDK、不照它的 React 形态。**
带走 **4 条设计**（其中 2 条直接命中我们已确诊的缺陷），外加 **1 条纪律**。

## 一、它到底是什么（已实证）

### 1.1 产品形态

一个**本地 Rust 守护进程 + 浏览器 Studio + CLI** 的动效工具。工作流：

```
一句话 → Agent 写 src/scene.js → Studio 调参 → mh render → mp4
```

**它的核心契约小到只有两个方法**（官网 bundle 原文）：

```js
export default function ({ root, width, height }) {
  const scene = build(root, width, height)
  return {
    prepareFrame(time) { scene.seek(time) },   // time = 绝对项目秒数
    dispose()          { scene.destroy() },
  }
}
```

配上 `mh.json`：
```json
{ "version": 3, "projectType": "standard", "runtimeVersion": 1,
  "entry": "src/scene.js", "width": 1280, "height": 720, "duration": 4, "fps": 30 }
```

**框架无关**：Three.js / GSAP / Canvas 2D / React 四选一，各一行 import。

### 1.2 它卖的是什么

官网 bundle 原文，它明确划了分工：

| MotionHarness 负责 | 你的工程负责（原先要自己做） |
|---|---|
| `预览` `导出视频` `AI 标记` `版本` `工程打包` | `搭预览服务` `逐帧导出` `音画合成` `任意时间定位` `工程打包` |

**它不提供画面内容。** SDK README 明写：「不包含 Builder、Studio、数据引擎或导出 Renderer」。
它的 `document.json` 是空骨架，填什么由写场景的人决定。

### 1.3 技术栈（坐实）

| 项 | 证据 | 强度 |
|---|---|---|
| Rust 原生守护进程 | `MotionHarness.exe` 163,109,376 B；`package.json` description "Rust MotionHarness daemon" | 实证 |
| CDP 驱动用 `chromiumoxide` | 二进制 24 次命中；runtime README 原文 | 实证 |
| 内嵌 LGPL FFmpeg | README + 二进制 | 实证 |
| 逐帧 PNG → FFmpeg 编码 | `pro/references/rendering.md` 原文：「PNG captures a complete browser frame without FFmpeg. MP4 sends complete PNG frames directly to native FFmpeg」 | 实证 |
| 8-bit RGBA 捕获 | 同上：「The capture source is 8-bit RGBA; a ProRes container does not increase the precision」 | 实证 |
| 无 MCP | 全站仅第 07 章一句 H2，零文档零实现 | 实证 |

### 2.4 但 SDK 不能用来集成——这是架构问题，不是许可问题

MH2 的判定，我认为是对的：

> 「SDK 自己写『不包含 Builder、Studio、数据引擎或导出 Renderer』。它导出的所有东西都要求存在
> 闭源的 `RuntimeProvider`。**它是插件通道，只能写"能在 MH 里跑的组件"，不能当渲染引擎用。**」

而且 `render` / `standard` / `time-markers` 三个模块的 `.js` **只有 11 字节**（`export {}`），
只有 `.d.ts` 有内容——**契约对外，实现在闭源宿主**。

### 2.5 三条红线（已落成规约）

1. `package.json` 的 `dependencies` / `devDependencies` 里**永不出现** `@motionharness/*`。
2. 仓库里**永不出现**它的二进制、`.vmg`、`.mhc`、模板、Logo、示例动画、界面截图。
3. 不写它的私有格式解析器。适配层只认「命令 + 输出文件路径」。

### 2.6 学设计的法律依据（让我们可以放心学）

《计算机软件保护条例》：
- **第十七条**：「为了学习和研究软件内含的**设计思想和原理**…**可以不经许可，不向其支付报酬**。」
- **第六条**：「保护**不延及**开发软件所用的**思想、处理过程、操作方法或者数学概念**。」

## 三、能融进来的（按价值排序，共 8 条）

### 第 1 名 · `params.json` 的 schema / values 分离 ★最该做

**这是唯一一条「现在不做，以后要考古」的事。**

MH 的三分（`src/` + `document.json` + 素材）有一个裂缝：**"参数"没有位置**。
它把参数挤进 `document.json`，于是"作品结构"和"覆盖层"住在一个文件里。

**正确形态是四份，不是三份**（MH7）：

| # | 文件 | 写者 | 读者 |
|---|---|---|---|
| 1 | `scenes/<id>/scene.js` | **Agent 主写** | 渲染器、Studio 预览 |
| 2 | `scenes/<id>/params.json` 的 `schema` | **只 Agent 写** | Studio 生成表单、校验器 |
| 3 | 同一文件的 `values` | **只 Studio 写** | 渲染器注入 `window.__params` |
| 4 | `document.json`（已有 plan） | Agent + Studio | 全部 |

**为什么必须做**：
- 它防的不是手滑，是**整文件重写**。Agent 的编辑单位是文件，不是针对你那一行的补丁。
  **参数一旦在源码里，人调的值每轮必丢一次** —— 不是偶发，是结构性。
- 等价于 **overlay（按稳定 id 键控）**，不是 patch（patch 需要 rebase，而基座每轮整篇重写 → 必冲突）。
- 事后无法区分「人的意图」与「Agent 的默认」——两者在文件里长得一模一样。

**唯一需要新增的自动检查（方案成立的前提）**：
> `scripts/static-check.mjs` 加一条：**`scene.js` 中出现在 style / gsap 参数位置的数字字面量即报错**。
> 没这条，文件 1 和 2 就是装饰。

**冲突只剩四种同文件情形**：C1 参数被删/改名 → 标 `orphaned` 保留值；
C2 改默认值且人没调 → 直接生效；C3 人调过 → 人的值优先，记一条 event；
C4 语义漂移（`speed` 从倍速变毫秒）→ **机器判不了，降级为 `unit` + `range` 越界报错**。

**代价**：约 2 人日。**收益**：把一次静默错片换成一次显式失败。

### 第 2 名 · 「唯一语义、唯一通路」★这条治我们四个缺陷

MH4 的发现，我认为是整轮最深刻的一条：

| 缺陷 | 按结构归类的根因 | 违反了什么 |
|---|---|---|
| **D1** `fit`/`box` 被忽略，改属性两次渲染逐字节相同 | 计划层声明了 `fit`，渲染层**另算了一遍布局** | 唯一通路 |
| **D2** 非首场景文字晚 122 帧 | `enable='gte(t,a)*lt(t,b)'` 的 a/b 与场景链起点**不同源** | 唯一语义 |
| **D3** 多 xfade offset 基准错，1464→696 帧 | `offset` 要的是**累计流偏移**，代码按**场景绝对起点**给 | 唯一语义 |
| **D4** `rgba()` 抛错 | 颜色字符串有**两个解析入口** | 唯一通路 |

> **D2、D3 都不是「算错了」，是「算了两遍，两遍不同源」。**

这正是 MH 那句「预览与导出使用相同的创作语义」要防的东西。
**但注意：统一是目的，单位只是手段。我们不需要换成秒制。**

**立刻可做的一级处方（1–2 人日）**：适配器能力声明 + 渲染前强制校验。
- 每个适配器导出冻结常量 `CONSUMES`（它实际消费的 plan 字段集合）
- 渲染前做覆盖校验：**plan 里出现的每个字段必须被某个 `CONSUMES` 覆盖；未覆盖 → 拒绝渲染并列出字段名**

> 效果不是"修好 D1"，是**让 D1 这一类不可能再发生**——下一个未实现的字段会在第一次渲染时炸，
> 而不是在三个月后的证据里被发现。

**立刻可做的二级处方（MH4 主张，我采纳）**：FFmpeg 侧拼接从「全局 xfade offset」
改成「**逐区间 frame-accurate overlay**」。每个重叠区间内两路按帧号对齐，
区间边界由帧号裁出——**没有全局 offset 这个概念了，误差无处累积，D2 + D3 同时结构性消失。**

### 第 3 名 · `TimeMarker` 标记模型 ★我们缺的 90% 是接线不是能力

MH5 的判定，我采纳：

> 「**数据模型我们已经做到比 MH 更严。** 我们的标注是**可复算的锚**（贴在对象+帧范围+版本上，
> 靠程序读），MH 的标记是**便签**（贴在画面上，靠人读）。便签优点是输入成本低，锚的优点是可验证。」

MH7 给的**四段流水线**（MH 只有两段）：

```
annotation(意图) → request(工单) → candidate(提案) → acceptance(采纳)
     人            系统             Agent            人
```

> 「MH 把 1 和 2 合成（标记即工单），把 3 和 4 合成（改了就是新版本）；**我们四段全拆**。」
> 「1 与 4 拆开必须：若批注直接等于授权，"我只是随口一说"就会被执行。**这是产品安全，不是工程洁癖。**」

**要学的三条**：
1. **点画面即写**，不要先选对象再开表单（这一步依赖 `web-scene` 能出画面）
2. **标记必须能编译成「意图」**：`frame 42–78, object t-03, aspect=layout, 当前 box 是 {...}`
   —— 这我们的 `plan.js` 天然能做（参数是数据）
3. **别学它「按标记切换画面风格」**：我们 `annotations.js` 原文写着
   「An annotation is discussion, not a modification authorization」——**这条坚持住**

**5,389 行不是过度设计**，是自建对象模型的税（`OBJECT_KINDS` + `editableProps` + 帧级时间，
每条非法组合都要手写兜住）。真"重"在三处：`sessions` 729（Studio 免费给的事）、
`history` 312（`listHistory` 包装，只有一个消费者）、`comparisons`/`field-diff` 重叠。
**精简后可到 2,300–2,600 行，`producer` 711 行挂起而非替换。**

**代价**：+2 人日。

### 第 4 名 · `web-scene` = 「代码作为素材」，不是「第二个事实源」★设计定稿

MH4 的方案，我采纳。核心一句：
> **把场景代码降格成一种素材（material），而不是升格成第二个事实源。**

```jsonc
{
  "kind": "web-scene",
  "id": "sc07-hero",
  "timeline": { "startFrame": 240, "durationFrames": 90 },   // ← plan 说了算
  "authored": {
    "codeRoot": "materials/web/sc07-hero",
    "codeHash": "sha256:…",          // 内容寻址，不可变
    "entry": "index.html",
    "assets": [{ "file": "logo.svg", "sha256": "…" }]
  },
  "params": {
    "base":   { "scale": 1.0, "x": 640, "y": 360 },   // 人拖的
    "offset": { "rotation": 0 },                       // 代码派生的叠加
    "seed": 20261111
  }
}
```

四条规则：

| 规则 | 拿到 MH 的什么 | 保住我们的什么 |
|---|---|---|
| **R1 代码不可变、参数可变** | 「手调参数不写回源码」的全部好处 | 差异/回退仍是一份 JSON |
| **R2 代码以哈希入指纹** | — | 「画面变了但指纹没变」不会发生 |
| **R3 换代码 = 换素材哈希** | 工程可移交 | **回退 = 改一个字段，不需要 git revert（比 MH 强）** |
| **R4 时间只由 plan 给** | — | 场景不许自己决定时长，出不了框 |

**必须一起做的**：`web-scene` 带 `determinism: { seed, fontsPinned: true, assetHashLocked: true }`，
渲染前**断言**：无网络请求、无 `Date.now`、无未固定字体。

**必须承认的代价**：`params` 是自由 JSON，`validatePlan` 有一处**校验真空**。
缓解：场景自带 `params.schema.json` 并入 `codeHash`。

### 第 5 名 · 「代码即时间函数 + 窄参数 overlay」★否决关键帧面板

MH7 的判断，我认为最反直觉但最对：

> **真正的对立不是「关键帧 vs 时间函数」，是「编辑对象是值还是表达式」。**

三条理由：
1. **关键帧本质是把创造性决策降维成数字**，与你的原则反向
2. 实测 11.5 ms/帧、1440 帧 17 秒——**重渲染变便宜后，关键帧的经济学就消失了**
3. 照抄它的面板会得到**覆盖不到一半的半覆盖面板**（GSAP 表达力超出 CSS keyframes），
   **半覆盖面板比没有更糟**

**边界**：overlay 里要有三类参数，第三类"帧级探针"**形式上就是关键帧**，但只在该打点处存在。

### 第 7 名 · `mh skill` 的分册 / 分节机制

二进制里 `# MotionHarness guide index` 原文：

> `mh skill` / `mh skill --reference pro` / `mh skill --reference <x> --section "<name>"`
> 「Relative links resolve from this file's directory.」
> 「**SDK symbols apply to Pro projects. Standard uses ordinary browser APIs and needs no SDK.**」

**把"给 Agent 的文档"做成了一个可导航的文件树**，而不是一大段提示词。
比我们的"卡片库 + 三闸检索"多了 `--section` 定位与相对链接（知识网而非知识列表）。

**代价**：0（已在我们动作三的计划内）。

### 第 8 名 · 确定性语义的四条写法（写进契约）

`motion.d.ts` 原文：
> 「**Stateless motion**…changing them does not resume a hidden simulation.」
> 「Seeded noise; **independent of evaluation order and FPS**.」
> 「**Reconstructs from start on every call: no playback memory or wall-clock delta.**」
> 「Each interval holds its endpoint source value…so **seek order and output FPS cannot change the curve**.」

还有它诚实划出的不可 seek 边界：
> 「incremental physics, independently created clocks and temporal-feedback effects are
> **not made seekable automatically**.」
> 「R3F clock **does not run on wall time**; delta is zero on first/repeated frame,
> **including negative seeks**.」

**落地**：把这四条写进 `CT-04`，作为 `web-scene` 的硬要求。
**代价**：0（契约文字）+ 验收用例 1 人日。

## 四、不能融 / 不该融的

| 项 | 为什么 |
|---|---|
| **它的 SDK 当渲染引擎** | 架构上不可能：所有导出都要求闭源 `RuntimeProvider`；`render`/`standard` 的 `.js` 只有 11 字节空壳 |
| **它的引擎 / Studio / 导出器** | 从未开源，UNLICENSED |
| **它的 React + R3F 形态** | 引入 `react`/`react-dom`/`@react-three/fiber`/`three` 一条链，与"薄插件"矛盾；且 GSAP `seek` 更适合我们的 637 张卡 |
| **达芬奇桥接** | 仅 macOS（官网 hero 却给 Windows 下载按钮，**自相矛盾**）；且我们不需要剪片 |
| **`.vmg` / `.mhc` 私有格式** | 引入等于自加攻击面；我们的 `delivery/package.js` 明确拒绝 zip 是**安全上的正确选择** |
| **把三适配器合成一个** | MH4 否决我的原建议：三份共享同一对象模型让「同一 plan 三引擎出同一帧」成为**验证手段**。正确做法是**保留结构、让声明变厚** |
| **换秒制时间基** | D3 能被抓住靠 `1464→696` 这个**整数恒等式**。换浮点秒，同一错误变成"短了 24.53 秒"，需反推。**这是可审计性，不是保守** |
| **官网那套 `mh.layer()` DSL** | 是打字机装饰代码（`Yg` 被逐字符 `slice` 进 `<li>`），全文 `window.mh` **0 命中** |

## 五、8 路互相纠正了什么（这是开 8 路的价值）

### 补充：一条可能真会咬人的既有隐患

`产品实现/media/templates/remotion/src/Root.jsx:10-16`：

```jsx
const rate = plan.outputSpec.fpsNumerator / plan.outputSpec.fpsDenominator
<Composition ... fps={rate} />
```

**`fps` 传的是浮点数。** 24/1、30/1 没事，但 29.97（30000/1001）会传 `29.970029970029972`。
Remotion 类型只写 `fps: number`，没做整数约束——**它不报错，而是静默产生畸形合成**。
**建议花 10 分钟跑一次 30000/1001 的真渲染确认。**

## 七、最终建议

### 做

| # | 动作 | 人日 | 完成判据 |

### 不做

- 不引入 `@motionharness/*` 任何包
- 不参考它的 React 形态
- 不换秒制
- 不合并三适配器
- 不在接电之前做减法

### 一句话收尾

**它的价值不在"它做了什么"，在"它证明了什么是对的"。**
它证明：**帧契约可以小到两个方法**、**参数必须与源码分离**、
**预览与导出必须同一语义**、**标记必须带语义 target 而不只是坐标**。

这四条我们都能自己实现，而且我们已经有一半了。
**真正缺的从来不是设计，是接线。**
