## 一、权威数据模型（`.d.ts` 原文，此前是推断）

```ts
interface CompositionInstance {
  componentId: string
  name?: string
  /** Scene and export visibility. Absent means visible; not an animation track. */
  visible?: boolean
  drivers?: Record<string, 'keyframes' | 'static'>
  values: Record<string, ParameterValue>          // 用户值（人调）
  tracks: Record<string, { keyframes, loop? }>    // 关键帧
  timing: InstanceTiming                          // { start, duration?, offset? }
  timeRemap?: TimeRemap
  /** Nonvisual child instances attached without author JSX changes. */
  sounds?: InstanceReference[]
  /** Host-rendered visual content. Only the composition root accepts these. */
  elements?: InstanceReference[]
  linkedVideo?: true
  fadeWindow?: { start, end? }
}
```

```ts
interface CompositionDocument {
  version: 1 | 2 | 3 | 4          // 逐代演进：v2 音频+remap，v3 curveSlice，v4 Canvas 元素
  compositionId: string
  rootInstanceId: string
  revision: number                 // ← 文档级单调递增
  settings: CompositionSchema['settings']
  instances: Record<string, CompositionInstance>
  timeMarkers?: Record<string, TimeMarker>
  markerTypes?: Record<string, string>
  title?: string
  cameraInstanceId?: string
  layerOrder?: string[]
  assetLibrary?: AssetLibrary
}
```

**两个此前不知道的关键点：**

**① `values` 与 `tracks` 分开。** 参数不是"一个带关键帧的值"，而是**两套并行存储**：
人调的值进 `values`，动画进 `tracks`，`drivers` 显式声明某个参数由哪种驱动。
**这正是"人的意图"与"动画"在结构上不互相污染的实现。**

**② `revision` 是文档级单调整数，不是版本树。**
我上一轮说它的「一键撤回」很轻——**说错了**。它有 `revision` + `expectedRevision` 的乐观并发。

**分布**（这才是重点）：

| 类别 | 文件 |
|---|---|
| **核心编辑**（14 个） | `document`(17) `batch`(3) `effects` `geometry` `camera` `markers` `table` `sequence` `stagger` `bake` `reset` `asset-library` `component-editor` `keyframe-selection` |
| **Studio 交互**（12 个） | `CanvasStage` `CompositionStudio` `CompositionTimeline` `playback` `timeline` `transport` `viewport` `session` `project-session` `effect-drop` `EffectCatalog` `EffectStackPanel` |

**结论**：**读操作无锁，写操作强制带版本号。** 这不是"加了个字段"，是**每个编辑入口的签名要求**：

```ts
editCompositionParameter(document, schema, edit: {
  instanceId: string
  parameter: string
  value: unknown
  expectedRevision: number     // ← 必填，无默认值
  time?: number
}): CompositionDocument
```

**对我们的意义**：我们的 `production-lock` + `write-guard` + `versions` 做的是**大粒度（项目/文件级）**保护。
它做的是**小粒度（每个编辑动作级）**的乐观并发。**两者不冲突，可以叠加。**

> 「After this revision's writes finish, inspect the affected frames:」
> ```sh
> mh preview --times '[0,1]' --contact-sheet --output-dir .tmp/previews/p1
> ```
> 「Use a **fresh output directory each time** and **read the returned images together**」
> 「For motion or sound, **render only the interval in question** and inspect that file」
> 「**Frames and levels do not prove motion or listening quality: review clips and audio with

> 「Fix observed defects and recheck what changed; reuse checks for unchanged inputs.」
> 「**Add diagnostics or dependencies only for a concrete problem the available tools cannot check.**」
> 「Checks run in the background: **do not open, focus, seek or play the user's Studio page or
> speakers unless asked.**」

### 3.2 这段为什么比任何架构都值钱

| 它说的 | 我们上一轮诊断出的病 |
|---|---|
| 「每次用**新的输出目录**」 | 接触表覆盖写，看不出变化 |
| 「**把返回的图一起读**」 | 只抽 32 帧，没连起来看 |
| 「**只渲染有问题的那一段**」 | 每次全片重渲 |
| 「**帧和电平不证明运动和听感……否则报为未验证**」 | **我们的验收包恰好写着「未看连续播放、未听任何音频」** |
| 「**只为具体问题加诊断**」 | 建了 27,000 行通用治理 |
| 「**不要打开/聚焦/seek/播放用户的 Studio 和扬声器**」 | 没这条纪律 |

**这一节 22 行，是"观察缺失"这个病的答案——而它是用文档解决的，不是用代码。**

### 3.3 它划的"什么写代码、什么写纪律"

| 事项 | 它放在哪 | 为什么 |
|---|---|---|
| 帧是不是纯时间函数 | **代码契约**（类型 + 校验） | 可形式化 |
| `expectedRevision` | **代码**（函数签名必填） | 可形式化 |
| 确定性（无 `Math.random`） | **代码 + 文档双写** | 半形式化 |
| **"要看图、要连着看、要听"** | **文档** | **需要模型判断** |
| **"只渲有问题那段"** | **文档** | 需要判断 |
| **"不要打扰用户的 Studio"** | **文档** | 是礼仪不是规则 |

**这就是"把创造性决策留给模型，把可形式化易错的操作交给代码"的完整落点。**

## 五、渲染管线的物理细节（此前是推断，现在是实证）

runtime `README.md` 原文：
> 「The executable contains the Rust daemon and embeds Studio, Core and transient Builder tooling.
> macOS and Windows also embed standalone LGPL FFmpeg/ffprobe. **CDP uses chromiumoxide.**」

`skills/mh-author/pro/references/rendering.md` 原文：
> 「**PNG captures a complete browser frame without FFmpeg. MP4 sends complete PNG frames
> directly to native FFmpeg** for H.264 or H.265 encoding.」
> 「The native encoder converts sRGB capture to Rec.709 and preserves straight alpha.
> **The capture source is 8-bit RGBA**; a ProRes container does not increase the precision
> of the authored image.」

**与我们的路线乙对照**：

| | MH | 我们（路线乙计划） |
|---|---|---|
| 驱动 | `chromiumoxide`（Rust CDP） | 零依赖 CDP（node 自带 WebSocket） |
| 取帧 | 完整浏览器帧 PNG | 页内 `toDataURL` |
| 编码 | 内嵌 LGPL FFmpeg | 系统 FFmpeg |
| 位深 | **8-bit RGBA** | 同理（PNG 天然 8-bit/通道） |

**结论：结构与我们的计划相同，只是它用 Rust 重写了驱动层。我们不需要跟着重写。**

## 八、新增一条建议（排进动作清单）

**动作 7｜写一份给 Agent 的《观察纪律》，约 0.5 人日**

内容照 `SKILL.md` 的 `Checks` 节改写（不是抄，是照结构写我们自己的）：

```
每次改完，必须做：
1. 渲一次带新输出目录的接触表（不要覆盖上一次）
2. 把返回的图连起来看，不是只看一帧
3. 只渲有问题的那一段，不要全片重渲
4. 帧和电平不证明运动与听感 —— 没看过连播、没听过，就写"未验证"
5. 只为具体问题加诊断，不加通用诊断
6. 不要打开、聚焦或播放用户的界面与扬声器，除非被要求
```

**这一条的价值**：它不花代码，但它把「观察」从"我们没有这个环节"
变成"我们有一个必须遵守的环节"。**这是过去半年最缺的一行字。**
