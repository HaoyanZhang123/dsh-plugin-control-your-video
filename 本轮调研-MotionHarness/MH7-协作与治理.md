# MH7 · 协作与治理：MH 的人—Agent 分工能搬什么，我们的 2 万行治理层该留什么

**口径**：本文件行数为本轮逐文件实测（`Measure-Object -Line`，排除 `acceptance/` `tests/` `fixtures/`）；53,783 行总量与 11.7% 纯工程保证采信父级实测，未复算。MH 未公开任何 schema，凡涉及其对象字段均为**推断**。

一处必须纠正：任务书「三适配器 2,111 < versions+recovery 2,522」两个数都不对。实测三适配器 **2,031**（ffmpeg 985 + hyperframes 663 + remotion 383），versions 1,264 + recovery 1,146 = **2,410**，比值 1.19，方向不变；**但把 `adapter.js` 372 + `checks.js` 401 算进渲染侧，渲染侧 2,943 反而超过**。这句不能当口号。更结实的对比：`core/project/` **9,554 行** = `media/render/` 2,943 行的 **3.25 倍**。

## §0 三句话

1. 「代码与参数隔离」不是整洁癖，是**同一份工程被两种写入方式同时编辑时的唯一可行解**——人拖拽是连续值增量，Agent 改码是整文件重写；写同一介质，人必被覆盖。它等价于 **overlay**，不等价于 patch。
2. 我们的 `editing/` 5,389 行**不是过度设计**，是"自建对象模型"的税；真问题在**不可达**——`ui/host/index.js` 只注入 `['webServer','connection']`，全 `ui/` 零工具注册，21 条路由无一条通向批注/候选/会话。它是**无人调用的库**。
3. 只学一件事：**参数必须有独立文件，schema 归 Agent、values 归人。** 今天做多一个 JSON + 一条静态检查；以后做是从源码里考古。

## §1 代码与参数隔离解决什么

### 1.1 它防的不是手滑，是「整文件重写」

| # | 失效 | 机制 | 为什么靠纪律解决不了 |
|---|---|---|---|
| A | **覆盖丢失** | 人把不透明度拖到 0.62；下一轮 Agent 产出整个 `scene.js` 新文本，那个字面量不在它上下文，回到默认 1 | Agent 的编辑单位是**文件**，不是"针对你那行的补丁"；它没有"保留我不认识的字面量"这个能力，除非那部分字节不在它要写的文件里 |
| B | **diff 爆炸/归因失效** | 参数在源码里，每次拖动都产生源码 diff。拖 40 帧 ≈ 几百行改动，语义上是**一个意图** | 版本语义粒度被写坏：审美微调与重写动画在 diff 里长得一样，噪声淹掉信号 |
| C | **冲突无法判定** | 都改同一行，只能文本合并，而文本合并对"数值被改写"没有语义 | 需要的是**所有权**，所有权只能由存储位置表达 |

A 的严重性被低估：它不是偶发，是**每次 Agent 重写都发生**。这解释了 MH 为什么把「Agent 改 React 源码，你在 Studio 调开放参数；两边操作同一份工程」单独写成一条承诺——它在描述**边界**，不是一个功能。

### 1.2 等价于什么：overlay，不是 patch

| 模式 | 结构 | 基座变了怎么办 | 适配整文件重写吗 |
|---|---|---|---|
| patch/diff | 记"第几行改成什么" | 需 rebase，上下文漂移即冲突 | **不适合**：基座每轮整篇重写，patch 上下文全失效 |
| **overlay** | 基座给默认值，覆盖层按**稳定键**记当前值 | 键还在就生效 | **适合**，这正是它的设计场景 |
| 配置与代码分离 | 代码读配置 | 天然兼容 | 适合，但是 overlay 的特例（分离文件 vs 分离求值顺序） |

同构例子：Kustomize overlay 之于 manifest、Helm `values.yaml` 之于 chart、CSS 自定义属性之于样式表。共同点：**基座可被无脑重新生成，人的意图留在覆盖层。**

关键推论：**必须按稳定 id 键控，不能按位置键控。** 按位置（"第 3 个 h1 的 fontSize"）基座重写后必然错位；按 id（`scene-07/subtitle-2/fontSize`）才能在 Agent 重排 DOM 后依然指对。

### 1.3 我们做了没有：做了一半，在错的层

| 问题 | 现状 | 判定 |
|---|---|---|
| 参数独立于渲染代码？ | **是**。plan 的 object 带 `params`，适配器读 `object.params?.fontSize ?? 32`（`hyperframes-adapter.js:136,163,178,196,221`）；渲染器是固定解释器 | 实证，已有 |
| 有"每个项目自己的代码"吗？ | **没有**。三个适配器是产品代码，不是作品代码；对象模型之外的表达（推镜/遮罩/混合/字距）**无处可写**——`OBJECT_KINDS` 是封闭枚举（`media/plan.js:38`） | 实证 |
| 那隔离成立吗？ | **成立，但成立在一个不需要它的地方**——参数是数据，纯粹因为**我们根本没有代码层** | 本节最重要的一句 |

直白说：我们的"参数与代码分离"是**偶然的**，是对象模型封闭的副产品。代价写在审计里：`zoompan`/`mask`/`blend`/`letter-spacing` 全 0 命中、`keyframe` 概念不存在。**我们用"没有代码层"换来"参数与代码分离"，代价是表现力封顶**——不是失误，是当初的合理取舍；但它意味着引入 Web 场景后**隔离要从零做**，因为现有机制的前提（没有代码）消失了。

于是任务书那句变尖锐：**每个场景是一个 HTML/JS 文件时，用户的参数调整存哪？**

### 1.4 设计建议：四份文件，不是三份

先指出 MH 三分的裂缝。`src/` + `document.json` + 素材，「参数」**没有位置**：它既不是源码之外的东西（React 里就写着 `style={{opacity:0.62}}`），也不是作品数据。**推断**：MH 靠 CSS 自定义属性——Studio 改的是运行时 CSSOM（浏览器免费给），所以"不写回源码"几乎自动成立；但手调值持久化只能挤进 `document.json`，一挤它就从"作品结构"变成"结构+覆盖层"，两个频率不同的东西住一个文件，正是 B 类失效。

我们要**四份**：

| # | 文件 | 内容 | 写者 | 读者 | 版本语义 |
|---|---|---|---|---|---|
| 1 | `scenes/<id>/scene.js` | 时间纯函数：DOM、GSAP timeline、`__seek(t)` | **Agent 主写**（人也允许） | 渲染器（CDP）、Studio 预览 | 源码，diff 有意义；每次 Agent 改动 = 一个 **candidate** |
| 2 | `scenes/<id>/params.json` | 两段：`schema`（旋钮/类型/范围/单位/默认）+ `values`（当前值） | **schema 只能 Agent 写；values 只能 Studio 写** | 渲染器（注入 `window.__params`）、Studio（表单由 schema 生成）、Agent（读当前值以免覆盖） | 数据，一条记录 = 一次拖动；走 **current 自动保存** |
| 3 | `document.json`（已有 plan） | 时间轴、场景顺序、转场、素材引用；场景**引用** 1、2，不内联 | Agent + Studio 时间线 | 全部 | 数据，已有三分类 |
| 4 | `materials/` | 素材原件 | 用户导入 | 渲染器 | 内容寻址，不改 |

**两条必须写进代码而非文档的不变量**：

- **① `scene.js` 不得内联视觉数值**，契约是 `const P = window.__params ?? DEFAULTS`。可机器检查：`scripts/static-check.mjs` 加一条——`scene.js` 中出现在 style/gsap 参数位置的数字字面量即报错。**这是整个设计唯一需要新增的自动检查，也是它成立的前提**；没这条，文件 1、2 就是装饰。
- **② `values` 键为 `<sceneId>/<objectId>/<paramName>`**，按 id 不按位置。

**谁写谁读**：Agent 新增/改场景 → 写源码 ✅、可写 schema ✅、**禁止写 values** ❌；人拖参数 → **只写 values**，禁止碰源码与 schema；人调时间轴 → 只写 `document.json`；人直接改 `scene.js` → 允许，但需同步 schema。

**冲突怎么判**——不同文件有不同写者，**跨文件冲突在结构上不存在**，只剩四种同文件情形：

| # | 情形 | 判据 | 处理 |
|---|---|---|---|
| C1 | Agent 删/重命名了人调过的参数 | `values` 有键 k，新 schema 无 k | **绝不静默删**：标 `orphaned`，保值、不注入、Studio 显式列出；重命名走 `params.migrations`（可复用 `core/project/migrations.js` 形态） |
| C2 | Agent 改默认值，人没调过 | values 无该键 | **不算冲突**，直接生效（期望行为） |
| C3 | Agent 改默认值，人调过 | values 有该键 | 人的值优先；记一条 event 让"它想改 X、你保留 Y"可查 |
| C4 | 源码变了但 schema 没变，参数名还在、含义变了（`speed` 从倍速变毫秒） | **机器判不了** | 降级为可见错误：每参数强制 `unit`+`range`，越界即**拒绝渲染并报错**。把不可判的语义漂移转成可判的越界 |

C4 是唯一"想不出更好答案"处：**语义漂移在纯数据层无解**，只能选报错还是画错。选报错——把静默错片换成显式失败。

架构红利：四分**天然落在现有三分类上**——`scene.js` 的 Agent 改动 = `candidate`（要 preview/checkScope），values 拖动 = `current` 自动保存（`ensureCurrent` 已是此语义）。**不需要新增第四种版本类**，而 `versions.js:31` 明写"恰好三类"。是设计对上了，不是巧合。

「模板流动」：模板 = 源码 + schema（**不含 values**）；实例化 = 复制 + 空 values。带出去的是"能力+可调面"，不带前一个项目的审美。注意 `media/templates/` 里 `Unit.jsx`/`Root.jsx` 是**渲染器模板**，不是作品模板。

## §2 AI 标记的接口设计

### 2.1 一个标记的最小字段集

用我们的记录反推（`annotations.js:344-380` 存 20 字段），逐条判：

| 字段 | 判定 | 依据 |
|---|---|---|
| `objectId` | **必要** | 没它 Agent 只能猜"这个字"是哪个字 |
| `anchorKind`（object/scene/transition/movie/flattened-clip/canvas-region） | **必要** | 压平视频与 Canvas 内的东西**没有可选内部对象**（`:298-300` 抛错）；这是对"点不准"的诚实，MH 文案无对应物 |
| `range`（startFrame/endFrameExclusive） | **必要** | 时间是视频本体；TIMING/WHOLE_FILM/FLATTENED_CLIP 强制要求（`:78`） |
| `aspect`（12 值枚举 + 按对象种类白名单，`:55`） | **高价值，建议做核心** | 把"自由文本→可执行意图"的映射成本从**模型侧**挪到 **schema 侧**："字太小"与"颜色不对"对 Agent 是两个动作 |
| `body`（上限 2000） | **必要** | 创造性意图只能在这 |
| `versionId` + `planFingerprint` | **必要** | 绑"我当时看到的版本"，含内容哈希；缺它批注会在下一步后指向不存在的东西——这是 MH「每轮有记录」能成立的前提 |
| `anchorSnapshot` | **有用** | `:512-523` 用 `contentHash` 比对快照与现状，可答"我批注的东西还在不在、变了多少" |
| `status`（open/addressed/resolved，明写 **resolved ≠ 接受**） | **必要** | 区分"Agent 说改了"与"我验收了" |
| 截图 | **可去** | 截图是快照的降级替代品，有 `anchorSnapshot` 就不需要位图，位图还不能 diff |

**推断**：MH 六步里位置与时间是点击的自带副产品，对象是副产物流，所以它至少有 `{position,time,body}`。要点：**我们多出来的字段不是花活——`aspect` 与 `versionRef` 恰是最能提高 Agent 命中率的两个。**

### 2.2 与批注/候选/会话：**两个层次，不是同一件事的两种实现**

| 段 | 谁的意图 | 载体 | 行数 | 能改 current 吗 | MH 有对应物吗 |
|---|---|---|---|---|---|
| 1 意图 | 人 | `annotations`+`scope`（把"这个字"解析成合法目标与范围） | 536+607 | **无**（原文：批注是讨论，不是修改授权） | ✅ 标记 |
| 2 工单 | 系统 | `producer`（六态；**要求 C13 绑定的 producer session，生产运行时拒绝 dispatch**） | 711 | 无 | ❌ 无独立对象，标记即工单 |
| 3 提案 | Agent | `candidates`（`baseVersionId`/`scope`/`preservedItems`/`diffRef`/`previewRef`/`checkScope`/`recheckRequired`） | 697 | 无（accept 后才变 current，**永不变 final**） | 部分（提案直接变新版本） |
| 4 采纳 | 人 | `versions` finalize（不可变）+ `decisions` | 1,264+1,341 | 是 | ✅ 一键撤回 |

关系是：**MH 把 1、2 合成（标记即工单），把 3、4 合成（改了就是新版本）；我们四段全拆。** 逐段判：

- **1 与 4 拆开必要**。若批注直接等于授权，"我只是随口一说"就会被执行——这是产品安全，不是工程洁癖。
- **4 内部"接受候选≠定稿"必要**。MH 的一键撤回隐含"改了就生效"，在它那里成本低（DOM 重绘）；我们"生效"意味着重渲染。
- **2 现在不必要**。711 行的存在理由是把改动派给"原制作 sub-agent"，为此读 `orchestration/`——而它不可达（§6）。**今天没有执行者**，不是设计错，是接线断。
- **3 必要但可薄**：`baseVersionId`+`needs-recheck` 真防事故（§3.3）。

### 2.3 5,389 行是过度设计吗？重在哪

| 分组 | 文件 | 行数 |
|---|---|---|
| 标记本体 | annotations 536 + scope 607 | 1,143（锚点解析 + 合法性白名单） |
| 差异呈现 | field-diff 352 + comparisons 195 + projection 332 | 879 |
| 提案 | candidates 697 | 697 |
| 草稿 | sessions 729 | 729（人直接改 + autosave + undo/redo） |
| 派单 | producer 711 | 711 |
| 重复 | history 312 | 312（与 `listHistory` 重叠） |
| 底座 | ids 387 + guard 239 + index 173 + links 119 | 918 |
| **合计** | 13 文件 | **5,389** |

**判断：不是过度设计，是"自建对象模型"的税。** 差价来源：MH 的可改性对象是 DOM + CSS 变量——点选、定位、注入、回读浏览器全给了；我们的对象模型自己定义（封闭 `OBJECT_KINDS` + `editableProps` 白名单 + 帧级时间），于是"这个属性能不能改""改了会不会破坏时间""重叠时点到谁"每条非法组合都要手写代码兜住。**1,143 行标记本体里多数是拒绝非法输入，不是实现功能。**

**但"重"确实三处**：`sessions` 729 在做 Studio 免费给的事（一旦有 values，撤销就是回退那个栈的最后一个键，还是**按参数键**撤销，比整份快照精细）；`comparisons`+`field-diff` 职责重叠；`history` 312 只是包装，**只有 `projection.js:89` 一个消费者**。

### 2.4 保留 / 精简 / 替换

| 结论 | 模块 | 行数 | 理由 |
|---|---|---|---|
| **保留不动** | annotations + scope | 1,143 | §2.1 的正确答案，字段已到"够用且不多" |
| **保留不动** | field-diff | 352 | "人能读懂 Agent 改了什么"的唯一途径 |

## §3 版本与回退

### 3.1 根本差异：它记录「动作」，我们记录「状态」

| 维度 | MH：每轮有记录/一键撤回/马上对比 | 我们 |
|---|---|---|
| 记录单位 | **一轮修改** | **一个项目状态**（`VersionRecord.content` 只存 id/hash，不内联字节） |
| 撤回语义 | 反向执行这一轮动作 | 让历史版本**重新成为 current**（`revertToVersion`），旧 current 进历史 |
| 正确性依赖 | 依赖"这一轮可逆" | **幂等**，不依赖重放正确性 |
| 存储 | 小（只存增量） | 大（引用集 + 快照文件） |
| 对比 | 并排/叠加**两份画面**——便宜，两个页面同时 `__seek` | 字段差异 + `previewRef`（`comparisons` 195 行）——**贵，要两次渲染** |
| 分类 | 无（线性轮次） | **恰好三类**：current/candidate/final，draft/初剪/基线/交付都是 substate，`:31` 禁第四类；final 不可变 |

有实际后果：**"记录动作"在基座不稳定时失效**。动作流隐含"这一轮就是这一轮"；状态流隐含"任何时刻都能被指认、被切回"。我们要允许整文件重写，重写不是可逆动作 → 动作流失效，状态流不会。**这是我们架构上更对的证据，不是更笨。**

### 3.2 更重吗？是。更少用吗？不是"更少"，是「用不上」

重量（实证）：`core/project/` **9,554** vs `media/render/` **2,943** = **3.25:1**；只取 versions+recovery vs 三适配器 = 2,410:2,031 = 1.19:1。**任何口径下治理都重于创作。**

"是否更少用"——我**不能说更少用**：无使用数据（无遥测、无本地日志，本轮未验证），不能拿"没测到"当"没用"。只能给三条结构性事实：

| # | 事实 | 级别 | 说明 |
|---|---|---|---|
| 1 | `routes.js:85-106` 21 条路由**无一条**通向 annotation/candidate/session/version；`ui/host/index.js` 只 `inject=['webServer','connection']`，全 `ui/` grep `ctx.tool\|registerTool` **零命中** | 实证 | 既无 UI 入口也无模型入口。不是"用得少"，是**走不到** |
| 2 | `revertToVersion` 仅见于 `versions.js`（定义）与 `editing/history.js`（包装），**无 host/UI 调用方** | 实证 | "一键撤回"今天不在任何用户可达路径上 |
| 3 | 缺陷第 4 条：`fit`/`box` 被渲染层忽略 → **同一对象改属性两次渲染逐字节相同** | 实证（转引 C16） | **最有力**：回退的价值取决于"改动可见"。当"改属性→画面不变"，唯一需要回退的东西根本不存在。**版本系统在空转，不是设计错，是上游没通电** |

第 3 条解释整件事：**"修改—观察—回退"缺了"观察"，回退就没有需求来源。** 我们不是造了没人用的东西，是造了闭环最后一环而中间一环没接。这决定顺序：**先让改动可见（换渲染层），再谈版本是否冗余**。顺序倒过来之前，任何"砍版本"的建议都是错的。

### 3.3 我们有一件 MH 没有的，不要一起砍

`candidate.baseVersionId` + `needs-recheck`：基版本前进后候选**自动作废**，`acceptCandidate` 在 `recheckCandidate` 跑过前**拒绝**（`:12-14`）。它防的是"基于旧版改出来的东西被静默采纳"——真实事故形态（人调了 A，Agent 基于没调的 A 改 B，合起来错）。MH 的线性轮次模型没有这个概念也不需要（无并行候选）。

所以 §3 的结论不能是"我们过重、该学 MH"。正确结论：**我们在防一类 MH 不必防的风险，付了 3.25 倍的钱；钱花得对，但收款方还没拿到收据——入口没接。**

## §4 关键帧 vs 时间函数

### 4.1 提问里混了两件事

- **关键帧作为数据结构**：`[{t:0,v:0},{t:24,v:0.3}]`，插值求值。
- **关键帧作为编辑行为**：时间轴上拖一个点，该点值可调。

`__seek(t)` 是纯函数，意味着"第 24 帧的 opacity"**不是存储的值而是求值结果**。从外部改它只有两条路：

| 路 | 做法 | 等价于 |
|---|---|---|
| (a) 改函数 | 改 `scene.js` 里那个 `0.3` | 改代码 → 重渲染才看得见 |
| (b) 函数之上加求值覆盖 | `__seek` 先查 overlay 里的关键帧数组，查不到走 timeline | **把关键帧重新引进来，只是存在 params 而非 source** |

所以真正的对立**不是**"关键帧 vs 时间函数"，而是：**编辑的对象是"值"还是"表达式"**。

### 4.2 两范式对照

| 维度 | 参数化关键帧（MH） | 代码即时间函数（gongnyang 卡） |
|---|---|---|
| 编辑对象 | 值 | 表达式 |
| 表现力上限 | **= schema 的笛卡尔积**，schema 之外做不出来 | **= GSAP 能做什么**：逐字入场+位移+缓动链+时间线嵌套全可以 |
| 作者化 | 高，拖一下 | 低，改一帧 = 一次代码编辑 + 一次重渲染 |
| diff 语义 | 语义化（一键一值） | 代码 diff（可读，但要读代码） |
| 确定性 | 依赖插值实现 | **已实测成立**：同刻两次取帧 sha 相同、异刻不同（Nº320、`ken-burns`，两次 CDP 实测） |
| 重渲染成本 | 便宜 | **已实测便宜**：`toDataURL` 11.5 ms/帧 → 1,440 帧约 17 秒；瓶颈在 CDP 传 PNG（259 ms/帧） |
| 精确定时 | 强（拖到 1.2 秒） | 弱（改数字重试） |
| 对我们现状 | **没有对象可挂**：`keyframe` 12 次命中全是"编译出来的逐帧数组"（`motion.js:140-207,281-301`），是产物不是结构 | **接得上**：卡片库已备好 `__ready`/`__dur`/`__seek`/种子随机/竖版 `data-size`，零外部依赖零网络，128 演示 467.4 秒 |

### 4.3 判断：代码即时间函数 + 一层**窄参数 overlay**

1. **用户原则的直接推论。** "动效怎么编排"是创造性决策→模型写代码；"快了还是慢了、大了还是小了"可形式化→归参数。**关键帧的本质是把创造性决策降维成数字**，方向正好相反。让模型填 40 行关键帧表单，是把它的能力按在地上用。
2. **成本结构已反转。** 关键帧范式在工业软件里成立的前提是"改一次看一次很贵"，所以必须就地调。实测 11.5 ms/帧、17 秒渲 1,440 帧——**当重渲染变便宜，关键帧的经济学就消失了**。这是数字的推论，不是偏好。
3. **照抄它的面板会得到低覆盖率面板。** MH 的场景本就是 CSS 动画，关键帧是 CSS 原生结构；我们会用 GSAP，而 **CSS `@keyframes` 表达不了"文字逐字入场后跟一个位移"**。搬过来只能覆盖"CSS 能表达的那部分"，可能不到一半。**半覆盖的编辑面板比没有更糟**，因为它让人以为能调。

### 4.4 边界：overlay 里要有三类参数，第三类形式上就是关键帧

| 类 | 内容 | 形式 |
|---|---|---|
| 数值 | size/opacity/offset/color | values 里一个键 |
| 时间 | start/duration/ease | values 里一组键 |
| **帧级探针** | 在某个 `t` 打点，该点值可调 | **形式上就是关键帧**——只在真要精确定时处打点，不是每场景都有 |

第三类是诚实让步：人要说"第 1.2 秒这个字刚好到位"，纯代码范式只能改数字重试。**给一个"打点"能力比给整套关键帧编辑器便宜一个数量级，且不污染 `scene.js`。**

## §5 如果只学一件事

### 5.1 选它：参数独立文件，schema 归 Agent、values 归人

| 理由 | 说明 |
|---|---|
| **它是其他三件的地基** | 没它，标记只能落到"Agent 猜着改"（它不知道你调过什么）；没它，版本记录 diff 爆炸；没它，Studio 参数面板**只能手写**——面板本该是 schema 的镜像，写一次 schema 自动出表单 |
| **唯一"现在不做、以后要重写"的事** | 一旦作品/模板积累，人调的值已在 `scene.js` 里。迁移 = 把每个值挖出来并判断"这是人的意图还是 Agent 的默认"——**这个判断在事后几乎做不对**，两者在文件里长得一模一样。今天做是新建文件，以后做是考古 |
| **成本最低，不碰现有代码** | 一个 JSON + 一个注入点 + 一条静态检查；`versions.js`、`editing/`、`core/project/` **一行都不用改** |
| **精准对上用户原则** | schema 是"有哪些旋钮"→ 创造 → Agent；values 是"拧到几"→ 判断 → 人。这是整个协作模型里唯一一条**不需要靠自觉**的边界，由文件所有权强制 |

**不学它的「版本管理」**：我们在防它不必防的风险（候选作废、final 不可变、谁能 finalize）。学它的轻量撤销会丢掉 `needs-recheck`，换来的只是"少写点代码"——而 §3.2 已证明少写的不是问题所在。

### 5.2 落地（五步，都是小改）

| # | 动作 | 落点 | 量 |
|---|---|---|---|
| 1 | scene 增加 `sourceRef` + `paramsRef`（**引用，不内联**） | `media/plan.js` | 小。必须保持 `VersionRecord.content` "references only, never bytes"（`:29`），不要破 |
| 2 | 读写 params.json、校验 schema、注入 `window.__params`、判 orphaned | `media/scene-params.js`，**~200 行** | 小。放 `media/` 不放 `editing/`——它是**渲染契约**不是编辑记录 |
| 3 | CDP + `__seek(t)` 取帧 + 注入 params | `media/render/web-scene-adapter.js` | 中。路线已在 `D-渲染能力.md` 论证，协议卡片库写好了 |
| 4 | 静态检查：`scene.js` 视觉属性禁数字字面量 | `scripts/static-check.mjs` | 小。**方案成立的前提** |
| 5 | `editing/annotations.js` **不动** | —— | 零。已在正确层次 |

第 4 步单独强调：**"Agent 会遵守约定"不是可依赖的假设。** 我们整套治理层（`write-guard` 264、`production-lock` 451、`schema` 419）都建立在"不靠自觉"上，参数隔离也一样——它必须有一条**让构建失败**的检查，否则第一个赶时间的 Agent 就会写 `opacity: 0.62`，那天之后整份设计退化成 A 类失效。

### 5.3 一条推论：它顺手解决「界面编辑」的①

官网「界面编辑」第一条是"让 Agent 拆分参数"——**单独列出来，恰好证明 MH 也认为"暴露哪些旋钮"是 Agent 的活**。四步（拆参数→图层→改参数→拖关键帧/曲线）里前三步全由这一份文件驱动，只有第四步需 §4.4 的"帧级探针"。**一个设计点覆盖 3.5 步，这就是"只学一件"的依据。**

### 6.3 三件「不砍但必须处置」

1. **`orchestration`+`producer` 的悬空（11,138 行）。** 不是坏代码，是**没接电的机器**。只有两个选项：接线（把 21 条路由改造成 6–8 个带 schema 的工具，`ctx.tools.register`）或显式挂起（移出 exports、README 标注未接线）。**两头不靠最坏**：它让代码量看起来充足，掩盖"模型在门外写脚本"这个真实状态。
2. **`tools/` 的优先级倒挂。** 说明项目曾把"环境可靠性"当主要矛盾——当时可能对（渲染不可靠是真实痛点），但现在挡住了"创作能力"。建议**不删，冻结**；判据是可达性，不是品味。
3. **`editing/` 瘦身顺序。** 必须先接入口再瘦身（§3.2 第 3 条：改属性→画面不变时回退无需求）。在入口和渲染层都通之前砍 `editing/`，砍掉的可能正是接下来最需要的那部分。

### 6.4 立场

问题**不是治理过度，是治理悬空**。53,783 行里防御/安全占 12–19%、纯工程保证 6,266 行（11.7%）——在"多人+多 Agent 写同一份工程"的产品里**不算高**，MH 连这一层都没有。真问题是：**治理层建完了，被治理的东西（画面、模型入口）还没通电**，所以一切治理都在空转。答案不是"砍 2 万行"，而是"先接电，再按可达性砍"；唯一值得**立刻、独立、不等其他事**去做的新设计，是那一份 `params.json`：**schema 归 Agent，values 归人。**
