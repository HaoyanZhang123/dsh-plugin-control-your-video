# 动画原则与缓动

> 何时读：要选缓动、定时长、判断该用曲线还是弹簧，或要复刻参考片的运动节奏时。读它是为了解决"这个动作该怎么说、用什么参数说"这一个判断。

## 1. 模型默认会犯的七条

先对照自己写的东西，这七条是最容易反复出现的默认值。

| 默认毛病 | 从成片里怎么看出来 | 换成什么 |
|---|---|---|
| 每个 tween 用同一个 ease | 慢放看，所有动作收尾速度一样 | 一个场景里最多两个 tween 共用同一条 ease |
| 所有动作时长一样 | 每个动作都是 0.4—0.5 秒 | 最慢的动作要比最快的慢 3 倍左右 |
| 所有元素从同一个方向进 | 全是从下往上 30px + 淡入 | 换：从左、从右、从缩放、只改透明度、字距 |
| 每场的错时一模一样 | 每场都是"依次出现"，节奏感相同 | 每场给自己的一档错时 |
| 每一镜都加环境推镜 | 每镜都在缓慢推近，看久了像在漂 | 一镜慢移、一镜微转、一镜推、一镜什么都不加 |
| 从 t=0 就开始 | 一开场元素已经在动，像跳了一帧 | 第一个动作推迟 0.1—0.3 秒 |

## 2. 缓动是副词

社区里的说法好用：**位移是动词，easing 是副词。** "滑进来"是动作，"果断地／梦幻地／玩闹地滑进来"是副词。同一个位移换一条曲线，意思就变了。

方向三条，默认照做：

| 场景 | 用 | 为什么 |
|---|---|---|
| 元素进场 | `.out`（起步快、减速停） | 反应快，观众觉得"马上来了" |
| 元素离场 | `.in`（起步慢、加速走） | 被甩出去，代表"不再回来" |
| 元素在画面内换位置 | `.inOut`（两头慢） | 出发和到达都有交待 |

反了会怎样，是可观察的：进场用 `.in` 显得拖沓、像加载；离场用 `.out` 显得依依不舍、像还没走完。

**什么时候这三条不成立：**

1. **位移很长时**（推镜、跨半屏以上）。这时方向规则让位给"这段距离看起来是否匀速"——长位移用纯 `.out` 会前段极快后段几乎不动，观众读成"猛地一顿"。
2. **要机械感、逐格感、硬切感时。** 故意不用缓动是有意的表达，不是漏了。
3. **回弹与拖尾不归 ease 管。** 它们是弹簧与分层错帧的产物；用 ease 硬仿回弹，会得到"假弹"。
4. **缓动不能补偿错误的量。** 一条曲线救不了一个不该动的动作。

## 3. 速度表示重量

四级语义（借自 IBM Carbon 的 Motion 规范）：

| 档 | 时长 | 语义 |
|---|---|---|
| 快 | 0.15—0.3 秒 | 有劲、紧急、自信 |
| 中 | 0.3—0.5 秒 | 大多数内容：看得见动作，但不被动作打断 |
| 慢 | 0.5—0.8 秒 | 重力、克制、从容 |
| 极慢 | 0.8—2.0 秒 | 电影感、情绪、氛围 |

**这是产品 UI 动效规范，不是视频片型规范。** 借的是"快慢分级有语义"这件事，以及"时长跟距离走"这条原则；不借它的 token 值（Carbon `duration-fast-01` 是 70ms、`fast-02` 是 110ms，那是按钮和开关的量级，放到镜头上等于没有动作）。也不把它当门禁：一支情绪片整片走极慢档是对的，不能因为"太快不够有劲"去加速。

同族的另外三条判断可以一起用：

- **按元素是否全程可见选曲线**：全程在画面里 → standard 类；进场 → entrance 类；离场 → exit 类；**离场但会回来**（侧边面板、可召回的东西）→ 用 standard 类而不是 exit 类，让它在画外减速停住，暗示"就在旁边"。
- **不要装饰性缓动。** 曲线如果只是在炫技（为了让动作"看起来花"），删掉。
- **同一层级不要混用两套风格。** 一套克制、一套外放，混在同一层会让观众分不清哪个更重要。

## 4. 一镜之内的三段：build / breathe / resolve

一个镜头内部按时间分三段，比例大约：

| 段 | 位置 | 发生什么 |
|---|---|---|
| build | 0—30% | 元素进场，错时；不要一次倒完 |
| breathe | 30—70% | 内容在场，**只留一个**环境运动让它"活着" |
| resolve | 70—100% | 离场或一个有决定性的收尾 |

最常见的错法是全塞进 build，breathe 与 resolve 空着——画面在入场后彻底静止，这就是"入场即停"（见 `motion-diagnosis.md`）。

**不对称**：进场要比离场长。一个卡片进场 0.4 秒、离场 0.25 秒是合理的比例；反过来会显得拖。

这一段只管一镜之内怎么排。**两个镜头之间怎么接、全片节奏归 video-edit。**

## 5. 编排即层级

观众把"先动的那一个"当成最重要的。

- **按重要性错时，不按图层顺序、不按文案顺序。** 先动主角，再动支撑信息，最后动装饰。
- **错时总时长压在 500ms 以内**，元素多也不要拉长——元素越多，单个间隔越小，而不是整串变长。
- **进场互相重叠，不要等上一个做完。** 等收完再起下一个，会读成"一步一顿"。
- 结论：动效的先后顺序本身在说"什么重要"。所以"给每一样都加一个漂亮入场"等于取消层级。

## 6. 十二条原则里真正在调参的只有三条

挤压拉伸、预备、调度、弧线、次要动作、夸张、结构、吸引力这些，多数落在构图、造型、内容层——那是 video-visual 的活。落到参数上被反复调的只有三条：

| 条 | 判断落点 | 做坏的迹象 |
|---|---|---|
| 缓入缓出（easing） | 每条动作配哪条曲线 | 全片线性；所有动作同一条曲线；缓过头导致发飘 |
| 跟随与重叠（follow-through） | 到位后谁还在动、晚几帧停 | 所有元素同一帧停住，塑料感 |
| 时间与张数（timing） | 动作几帧、停留多长 | 所有动作同一时长，没有轻重 |

## 7. 四条运动路线与选型

动画参数只有四个来源，可以混用。选哪个看工程需求，不看审美。

| 需求 | 选 | 代价 |
|---|---|---|
| 要可 scrub、可逆、跨次渲染完全一致 | 曲线（easing function） | 不天然产生 overshoot 与惯性 |
| 要复刻参考片的节奏／曲线 | 采样折线（`linear()` 点列） | 点少会在慢镜头上看出折角；换帧率要重算 |
| 要有重量、回弹、跟随 | 弹簧 | **不是时间纯函数**，见下 |
| 要速度感、残影、光轨 | 分层错帧（Trail） | 层数多成本线性涨；加在静止物体上会脏 |

- **曲线**是纯函数：同一输入永远同一输出（W3C 明文要求）。这是它"可复现"的来源，也是它"没有重量"的原因——曲线本身不含质量概念。
- **采样折线**是把任意曲线存成点列。真正的用途不是省事，是**从参考片里抽出实测运动曲线再原样复用**：抽帧量出"第 n 帧在位置 p"，存点列即可，不必反推它叫哪个 ease 名字。这是少数人才用的那条路。注意 `linear()` 的输出值可以越出 0—1，所以它也能表达 overshoot；Lottie 的关键帧切线同理（y 不钳制）。
- **弹簧**解的是二阶阻尼（质量／刚度／阻尼／初始速度），按帧积分。**关键限制：它不是时间的纯函数**——结果依赖 fps 与积分步长，24／30／60fps 下同参数不同形。要求跨帧率一致或严格可复现时，要么固定 fps，要么先烘焙成采样曲线再分发。
- **分层错帧**是"过去的自己"叠在画面上，是运动模糊的近似，不是真实快门采样。适合快速运动、发光体、线条。
- **另有一层是排布**：谁接谁、重叠多少。用绝对时间、相对末尾（`+=1`）、标签、或"最近一个动作的首／尾"来定位。绑标签比绑秒更耐改，因为改一个动作长度不会连带打断后面所有时刻。这一层与上面四条正交。

## 8. 引擎语义差别（只记差别，不搬代码）

| 引擎 | 一条必须知道的语义差别 |
|---|---|
| CSS Easing 2 | easing 必须是纯函数；输入与输出都可越界，所以链式嵌套时输入不在 0—1 内是正常的 |
| GSAP | 默认 ease 是 `power1.out`；命名族 `.in`／`.out`／`.inOut` 就是方向；timeline 的 position 参数决定"谁接谁" |
| Lottie | 关键帧用 i/o 切线描述曲线，**y 不钳制**，所以能表达超调；`h` 为 1 时保持值不变（hold） |
| Remotion interpolate | 默认会外推（超过区间继续算），要停在区间内必须显式钳制；缩放有"按感知面积线性"的输出选项——说明线性改 scale 不是视觉匀速 |
| Remotion spring | 质量越小越快；阻尼调大到临界以上可去掉回弹；带 fps 参数，正说明它依赖帧率 |
| Remotion Trail | 层数、每层滞后帧数（可小数）、最高不透明度；子元素必须绝对定位，否则层数变化会推挤布局 |
| Manim rate_functions | `smoothstep` 族按端点导数为零的阶数分档；还有 `there_and_back`、`wiggle`、`rush_from`、`lingering` 这类**非单调**函数，它们不是 ease，是"去而复返"的表达 |

## 9. 这些数字从哪来（必须连着条件一起用）

| 数值 | 出自 | 条件 | 归属 |
|---|---|---|---|
| 快推 0.25—0.35 秒，推近 18—32% | 某支竖屏短片的实做 | 该作者在解说／科普片型下的实测起点；动态文字里它是主语法，其它语法里是少数 | 本文 |
| 缓推 0.6—1.5 秒，sineInOut | 参考片实测（1.0—1.5 秒级） | 同上；推的距离到 2 倍以上可放长 | 本文 |
| 横移 0.5—0.9 秒 | 参考片实测 | 跟随运动物体时速度跟物体走 | 本文 |
| 砸入 0.17 秒 | 一次认可片实做 | 一镜最多一次；不是每次切镜都砸 | 本文 |
| 慢漂 1—4%/秒 | 作者示范片，**没有认可片实测** | 氛围镜、情绪长镜头成立；**解说片里每镜都慢推几个百分点就是 PPT** | 本文 |
| 每镜 2—6 秒 | 同一作者的镜头表 | 该作者路线；镜长是时长预算，不是动效参数 | video-plan |
| 推近每分钟 ≤8 次；重音动作 ≤镜头数三分之一 | 该作者的检查脚本 | 解说／科普类成立；钩子段、音乐卡点段不适用 | 密度归 video-edit，单镜重音比例归本文 |

写进正文前必须能答：这数值来自哪支片、换片型还成立吗、不成立时替代判断是什么。答不全就只留在本表里。

## 10. 已知缺口

- W3C 快照只收到 §1.1、§2、§2.1，`cubic-bezier()` 与 `step()` 的正文缺失。
- Manim 只拿到函数名与参数名，**没有公式**，不能据此复现曲线。
- 所有引用的文档都没有可看产出：可视化器与示例动画未保存，本文没有画面证据。
- 弹簧"跨帧率不一致"是文档语义结论，本文没有在本机跑过 24／30／60fps 对照。
