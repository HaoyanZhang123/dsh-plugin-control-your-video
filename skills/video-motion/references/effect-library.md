# 效果库怎么检索与借用

> 何时读：用户抛来一张效果卡、一个效果名，或问"有没有那种……的效果""照着这个做一个"时。读它是为了解决"从 637 张卡里该挑哪张、挑来之后要改什么"这一个判断。

## 1. 这份库是什么

`resources/research/已确认资产/01-作品与案例/10-gongnyang-awesome-ai-motion/`：637 个技法、128 条参考片、11 个 recipe、7 条设计路线，分 15 个家族。每张卡在 `effects/<slug>/README.md`，给的是定义 + 调好的参数 + 例子 + 来源 + 给 agent 的提示词；有参考片的还带 `clip.mp4`、`preview.gif`、`poster.jpg`。`index.json` 是正本，文档与网站由它生成。

**637 张卡是候选池，不是触发器。** 它的存在不构成"该用某个效果"的理由。

## 2. 十五个家族：先想清楚要说什么，再决定翻哪一格

| 家族 | 数量 | 管什么 | 什么时候翻 |
|---|---:|---|---|
| PRINCIPLES 基本 | 26 | 12 原则、easing、错时、间距——所有运动的语法 | 想不起某个动作叫什么；要拿一个概念的准确定义 |
| ENTRANCE & EXIT 登场退场 | 38 | 元素怎么进来、怎么离开 | 这一镜有东西要出现／消失，而默认的淡入位移不够 |
| EMPHASIS 强调 | 22 | 已在画面上的东西怎么被指出来 | 观众该看的那处已经在，但没被看见 |
| TYPOGRAPHY 排版动效 | 33 | 字怎么出现、变化、被强调 | 字本身是主体（注意：字幕排版规范归 video-edit） |
| TRANSITIONS 转场 | 98 | 两个画面之间 | **不在这份用**，转场与整体节奏归 video-edit |
| CAMERA 相机 | 22 | 整幅取景怎么动 | 这一镜要交代空间、带视线、或揭示全貌 |
| DATA 数据 | 74 | 数字与图表怎么长出来 | 这一镜在讲大小、变化、比较 |
| UI DEMO 界面演示 | 47 | 屏幕操作怎么演 | 这一镜在讲"它怎么用" |
| EXPLAINER 原理图解 | 48 | 看不见的机制怎么画出来 | 这一镜在讲一个过程、一条路径、一层关系 |
| SHAPE & PATH 形状路径 | 32 | 画线、变形、沿路径运动 | 这一镜主体的形态本身在变 |
| TEXTURE & STYLE 质感 | 59 | 噪点、光、扫描、印刷纹理 | 这一镜要的是质感而不是动作 |
| GENERATIVE 生成 | 47 | 粒子、噪声、规则重复 | 这一镜要"多"，且多本身就是内容 |
| 3D & DEPTH 立体 | 33 | 透视、旋转、分层深度 | 这一镜要说明空间或组装关系 |
| LOOP & AMBIENT 循环 | 44 | 呼吸、漂移、长期在场的弱运动 | 需要 breathe 层，或一镜很长 |
| CAPTIONS 字幕 | 14 | 下三分之一、卡拉 OK、引语卡 | **字幕排版规范归 video-edit**；这条只在借"出现方式"时参考 |

## 3. 检索入口是"观众该看哪"，不是效果名

| 这一镜观众该看哪 | 先翻 | 典型卡 |
|---|---|---|
| 一处细节，现在在全景里读不清 | CAMERA | `zoom-to-detail`、`push-in` |
| 一个数，要让人感到它有多大 | DATA | `count-up`、`bar-grow`、`unit-grid` |
| 一个不可见的过程（怎么运作） | EXPLAINER | `progressive-disclosure`、`path-beam`、`attention-lines` |
| 一个"多"（规模、密集） | GENERATIVE | `particle-assemble`、`flow-field` |
| 一个关系的空间结构 | 3D & DEPTH | `exploded-assembly`、`layer-separation` |
| 一个已经有、但没被指出的东西 | EMPHASIS | `focus-handoff`、`circumscribe` |
| 没有新东西要看，只是不想让画面死 | LOOP & AMBIENT | `breathing-loop`、`ambient-glow` |

从效果名开始检索的结果是"这一镜有什么效果"，从"该看哪"开始检索的结果是"这一镜说了什么"。前者会得到一堆彼此无关的动作。

**三种提高检索质量的做法**：先用一句话写下"这一镜要说什么"；只挑 2—3 张比较，不要挑 10 张；比较时看它的**机制**（散→聚、遮挡→揭开、从大到小），不看它的配色和时长。

## 4. 借用时要改什么（默认至少改三项）

卡片是**孤立舞台上的单元素演示**：一块空白画布，一个元素，一条动作。你的镜头里有口播、有其它元素、有上一镜的落点。

| 改什么 | 为什么 | 怎么改 |
|---|---|---|
| 时长 | 卡里的时长是它自己的舞台节奏 | 按这一镜的长度和重音位置重定；覆盖整段 breathe 往往要拉长，反之重音要压缩 |
| 力度 | 卡里的幅度可能很高能量 | 同一机制在不同能量段落幅度不同——参考同一套作者的做法：高能量段 15% 缩放弹出，低能量段只做 3% 白色位移 |
| 配色与质感 | 卡的配色是它自己的 | 换成本片色板；纹理类尤其明显（同一张 `film-grain` 换成彩色就散了） |
| 方向 | 卡的进场方向是任意的 | 按这一镜的构图和视线走；上一镜从左边进，这一镜别又从左边进 |
| 层级与遮挡 | 卡里只有一个元素，没有谁遮谁 | 补上这一镜真实的图层关系，否则借来的动作会穿模或压住主角 |

**借的是机制，不是外观。** 一句可操作的话：借"散→聚"，改"多久、多大、什么颜色、从哪来"。

## 5. 不许整套搬

- 整套搬的证据是**可观察**的：连续几镜各出现一个完整、独立、自成一体的小动画，彼此无关；观众记住的是"这些效果挺花"，说不出这片讲了什么。
- 它与"每镜同一个动作"是同一个病的两面：一个是全都一样，一个是全都不一样，共同点是**动作和内容没有关系**。
- recipe（11 个）比单卡更接近可用的场景，但 recipe 也是别人的片型与时长。可以借它的编排顺序，不能借它的时间轴长度。

## 6. 卡的状态决定它能当什么用

`分类索引.md` 每行末尾标了 `done` / `planned`：

- **done**：有参考片与实现页，可以看它长什么样，可以当"这条机制的参照"。
- **planned**：只有定义，没有参考片、没有实现。**不要把它当"我看过这个效果"**，它只是一句话描述。

全库 637 张里 done 的只是一部分，`planned` 占多数。引用给用户之前先确认状态，把"有参考片"和"只有一句定义"分开说。

## 7. 边界

- **转场与整体节奏归 video-edit。** TRANSITIONS 家族那 98 张在本文只作为"这一镜内部有没有一个元素穿过画面"的素材，两个镜头之间怎么接不在这里定。
- 字幕动效的排版规范（位置、行数、安全区、可读性）归 video-edit；本文只回答"这个字是怎么出现的"。
- 视觉系统（色板、字体、间距、层级）归 video-visual。借用效果时配色要跟着视觉系统走，不跟着卡片走。
- 画面能不能用代码画出来、出帧怎么搭管线，归 video-code-visual。看中一张 webgl 卡不等于这条路在本项目里跑得通。
