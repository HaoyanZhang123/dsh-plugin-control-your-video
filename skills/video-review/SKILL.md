# 审片与取证

## 1. 先判断这次是什么任务

三问，按顺序，前一问不过就不往下走：

1. **有没有可看的输入？** 成片 MP4、已抽的帧、工程文件，还是只有一句"你看看"。没有可看的输入 → 按 §2 降级，不出检查报告。
2. **有没有一个要回答的问题？** 用户说了现象（"字幕压脸""后面拖"）就用他的原话立问题；只说"感觉不对" → 用 `references/observation-checklist.md` 把感受转成问题再取证。
3. **是首次审，还是改后复核？** 复核必须按 id 找回改前那条证据，不凭记忆重看。

不做这份的情况见 §8。

## 2. 能力前置检查与降级

先确认三件事，各自决定你能说什么：能不能读到成片帧、有没有音频通道、能不能连续播放。

| 手上只有 | 能下什么结论 | 不能下什么结论 |
|---|---|---|
| 成片 MP4，可抽帧、可测量 | 单帧内容；黑帧、时长、响度等确定性读数；相邻帧是否连续 | 听感；混音对不对；用户是否满意 |
| 帧 + 接触表，不能连续播放 | 构图、遮挡、黑帧、字幕位置；哪几秒值得回看 | 运镜顺不顺；节奏；闪烁是否真在闪；连续播放是否正常 |
| 只有工程/时间线/预览页 | 时长与方案偏差；元素坐标与字幕块重叠；帧区间空洞或重叠 | 成片长什么样；编码后是否变样；任何听感 |
| 只有用户口述 | 把口述写成待取证的问题 | 任何"我已检查"的说法 |

降级不是一句"如实说明"就完：先写"本次只核到 X 层，Y 未核"，再给该层能支撑的结论。`finding` 没填不算看过；测了响度不等于听过；读了工程不等于看了成片。

## 3. 先立问题，再取证

问题要能回答成"是/不是"或"哪里不对"，带时间点与判据：

- 能取证：`12.4 秒这条字幕的底边有没有压到下颌线？`、`第 7—8 镜接缝那 16 帧里主体位置有没有跳？`
- 不能取证：`这镜好不好？`、`整体感觉如何？`、`有没有质感？`——没有判据，取多少帧都答不了。

取最少够用的证据：一个 `purpose` 一条。全片先导航定位可疑区间，再回原帧与局部裁剪。用途选错，证据就答不了问题：

| `purpose` | 能回答 | 不能回答 |
|---|---|---|
| `look` | 这一帧长什么样、有无遮挡、构图是否成立 | 连续运动、节奏 |
| `seam` | 相邻两镜接得上吗、接缝处有没有空场或双帧 | 整片节奏 |
| `text` | 字有没有出界、压脸、漏字 | 台词写得对不对 |
| `motion` | 这一段动得顺不顺（需连续帧或用户观看） | 单帧构图 |
| `sync` | 声画是否落在同一拍 | 混音平衡 |
| `mix` | 响度、峰值的读数 | 听感 |
| `cover` | 封面或首帧能不能站住 | 正片质量 |

**多尺度不等于可以跳过尺度**：接触表只用来找"该看哪几秒"，不能用来判定。静帧证明不了连续播放正常，抽帧证明不了运镜顺不顺，帧序列证明不了听感。

## 4. 证据不可变与版本

- 去重键 `(revision, shot, t, purpose)`：同键只存一份，重复时复用旧 `id`。
- 重渲另起条目，旧条目标 `superseded`，**旧文件不删**。理由只有一个：改完要能和改前对照。覆盖旧证据，"改前是什么样"就只剩记忆，修改单里"用户看到的"那一栏的证据也一起失效。
- 默认只查 `current`；对照改前时显式按 `superseded` 查。`gc` 只清 `superseded`。

字段与键名见 `docs/编写规范.md` §1.5（英文键逐字使用，不改名）。一条：

```json
{"id":"r3-s05-12.4s-look","file":"r3-s05-12.4s-look.png","revision":"r3","shot":5,"t":12.4,"purpose":"look","source_sha256":"…","derived_from":null,"created":"2026-11-18T02:30:00+08:00","question":"12.4 秒这条字幕有没有压到人脸？","finding":"压到下颌线，约 12px。","status":"current"}
```

写修改单第 2 项时，能取证就带 id，取不到就写"未取证"——不许用"用户觉得不好"代替具体现象。

## 5. 预期—实际闭环

分两段，缺一段等于没闭环：

1. **改前**：写 `预期可见变化`（哪几秒、应该看到什么不同，能写成像素/秒/读数就写）＋ `必须保留项`（人物、品牌、已确认的镜头设计、上一镜落点）。这两项分别进修改单的"期望变成什么"与"波及范围"。
2. **改后**：用同一 `(shot, t, purpose)` 重新取证，逐条对照改前那条证据；再复看改动点前后各 8 帧的接缝，并全片扫一遍同类现象。

对照失败时先排除取证条件变了（修订、时间点、源文件哈希），再判"修复无效"。

## 6. 三层结论，不许混

| 层 | 证明什么 | 不能证明什么 |
|---|---|---|
| 技术测量（黑帧、时长、响度、分辨率） | 没坏、没缺、达标 | 好看、好听、混音对 |
| 已看帧（`finding` 已填） | 这一帧或这一段是这样 | 连续播放正常、节奏对 |
| 用户满意 | 只有用户能给 | 自动结论替代不了 |

报告里分开写：**已看**（附证据 id）、**未看**（缺什么输入）、**需人判断**（听感、审美、是否接受）。

## 7. 判断示例

用户这么说："后面那段有点拖。" → 你这样判断：先分清是节奏还是信息密度：镜头都短但信息原地重复是信息密度，回 video-plan；镜头长、画面不动、没有新事件是节奏，归 video-edit。取证：抽后半段逐镜首帧做接触表定位长镜，对可疑镜测时长并与全片均值比，再抽该镜中段三帧看画面是否在变。 → 所以你这样做："第 9—11 镜共 14 秒只推进一个信息点，其中第 10 镜 5.2 秒无可见变化"，写成三条修改单，不写"节奏偏慢"。

用户这么说："这版是不是比上版好？" → 你这样判断：不能答"更好"，只能答"改前那个现象还在不在"。取证：按改前证据 id 找同一 `(revision, shot, t, purpose)`，在新修订上重取一帧对照。 → 所以你这样做："第 5 镜压脸已消失（对照 `r2-s05-12.4s-look`）；第 7 镜同类问题本次未核"，未核写进"未看"。

用户这么说："字幕是不是压脸了？" → 你这样判断：这是可回答的是/否：取该秒原帧，再裁人脸局部放大，量字底边与下颌线距离。 → 所以你这样做："重叠约 12px"，修改单"属于谁的问题"判"执行（字幕安全区没算）"，不判"创作设计"。

**反例**：只看了一张接触表就说"运镜很顺、节奏没问题"。错在两处：把导航工具当判据（接触表是抽帧拼图，帧间发生了什么它不记录）；绕过了 `purpose`（运镜与节奏要 `motion`，只能来自连续片段或用户观看，不能用 `look` 帧顶替）。

## 8. 什么时候不做这份

- 用户没让你看片，只是在推进下一步 → 不主动出检查报告。
- 手上没有成片、帧或工程 → 先说要哪种输入，不凭文件名和工程结构写"检查结论"。
- 用户只问"能不能发" → 转 `video-release`；只问"下一版怎么拍" → 转 `video-plan`。
- 改动成本远高于问题本身（改一处要重做整段）→ 只报最值钱的一两处，不铺全片清单。

## 9. 边界

- 不替用户判断好不好看、值不值得发。用户问"好不好"，把问题拆成可取证的现象；拆不出来就说这条只能人判。
- 不直接改片、不改镜头设计、不改时长预算——修改单交回 `video-plan`。
- 合规、标识、许可、响度门禁、交付清单归 `video-release`；字幕文本怎么写归 `video-script`；转场与整体节奏的改法归 `video-edit`。
- 接口字段只在 `docs/编写规范.md` 定义，本份只用不定义。

**不适用**：还在调提示词、问"怎么让模型出这个镜头"（用 `video-prompting`）；没有成片也没有帧、只有想法（用 `video-plan`）；只问能不能发（用 `video-release`）。

## 按需参考

- 用户只说"感觉不对"说不出哪里，或要审一整版 → `references/observation-checklist.md`

- 根因已定，要选保留／局部修补／重做 → `references/repair-strategy.md`
