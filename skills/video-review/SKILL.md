# 审片、取证与专业判断

审片要同时做三件事：**取证**（成片里到底有什么）、**判断**（作为创作者，你认为哪里不对、为什么）、**交付修改范围**（改哪一镜、代价是什么）。

三层不能混：**能测的是事实，能看的是判断，能定的是用户。** 把判断说成事实是造假，把判断推给用户是失职。

## 1. 先判断这次是什么任务

三问，按顺序，前一问不过就不往下走：

1. **有没有可看的输入？** 成片 MP4、已抽的帧、工程文件，还是只有一句"你看看"。没有可看的输入 → 按 §2 降级，不出检查报告。
2. **有没有一个要回答的问题？** 用户说了现象（"字幕压脸""后面拖"）就用他的原话立问题；只说"感觉不对" → 先按 §5 拆成可观察的判断，再取证。
3. **是首次审，还是改后复核？** 复核必须按 id 找回改前那条证据，不凭记忆重看。

## 2. 能力前置检查与降级

先确认三件事，各自决定你能说什么：能不能读到成片帧、有没有音频通道、能不能连续播放。

| 手上只有 | 能下什么结论 | 不能下什么结论 |
|---|---|---|
| 成片 MP4，可抽帧、可测量 | 单帧内容；黑帧、时长、响度等确定性读数；相邻帧是否连续 | 听感；混音对不对；用户是否满意 |
| 帧 + 联系表，不能连续播放 | 构图、遮挡、黑帧、字幕位置；哪几秒值得回看 | 运镜顺不顺；节奏；闪烁是否真在闪 |
| 只有工程/时间线/预览页 | 时长与方案偏差；元素坐标与字幕块重叠；帧区间空洞或重叠 | 成片长什么样；编码后是否变样；任何听感 |
| 只有用户口述 | 把口述写成待取证的问题 | 任何"我已检查"的说法 |

降级不是一句"如实说明"就完：先写"本次只核到 X 层，Y 未核"，再给该层能支撑的结论。`finding` 没填不算看过；测了响度不等于听过；读了工程不等于看了成片。

## 3. 先立问题，再取证

问题要能回答成"是/不是"或"哪里不对"，带时间点与判据：

- 能取证：`12.4 秒这条字幕的底边有没有压到下颌线？`、`第 7—8 镜接缝那 16 帧里主体位置有没有跳？`
- **不能直接取证、但必须给出判断**：`这镜是不是有点廉价？`——它不是一个测量题，但也不是不能回答的题。拆法见 §5。

取最少够用的证据：一个 `purpose` 一条。全片先导航定位可疑区间，再回原帧与局部裁剪。用途选错，证据就答不了问题：

| `purpose` | 能回答 | 不能回答 |
|---|---|---|
| `look` | 这一帧长什么样、有无遮挡、构图是否成立 | 连续运动、节奏 |
| `seam` | 相邻两镜接得上吗、接缝处有没有空场或双帧 | 整片节奏 |
| `text` | 字有没有出界、压脸、漏字 | 台词写得对不对 |
| `motion` | 这一段动得顺不顺（需连续帧或用户观看） | 单帧构图 |
| `sync` | 声画是否落在同一拍 | 混音平衡 |
| `mix` | 响度、峰值的读数 | 听感 |
| `cover` | 封面或首帧能不能站住 | 正片质量 |

**多尺度不等于可以跳过尺度**：联系表只用来找"该看哪几秒"，不能用来判定。静帧证明不了连续播放正常，抽帧证明不了运镜顺不顺，帧序列证明不了听感。要判运动，用联系表或连续帧把这一段的**变化**取出来，不要用单帧顶替。

## 4. 证据不可变与版本

- 去重键 `(revision, shot, t, purpose)`：同键只存一份，重复时复用旧 `id`。
- 重渲另起条目，旧条目标 `superseded`，**旧文件不删**。理由只有一个：改完要能和改前对照。覆盖旧证据，"改前是什么样"就只剩记忆。
- 默认只查 `current`；对照改前时显式按 `superseded` 查。`gc` 只清 `superseded`。
- 字段与键名见 `docs/编写规范.md` §1.5（英文键逐字使用，不改名）。

一条：

```json
{"id":"r3-s05-12.4s-look","file":"r3-s05-12.4s-look.png","revision":"r3","shot":5,"t":12.4,"purpose":"look","source_sha256":"…","derived_from":null,"created":"2026-11-18T02:30:00+08:00","question":"12.4 秒这条字幕有没有压到人脸？","finding":"压到下颌线，约 12px。","status":"current"}
```

写修改单第 2 项时，能取证就带 id，取不到就写"未取证"——不许用"用户觉得不好"代替具体现象。

## 5. 审美问题怎么答：拆成可观察的判断

用户问"好不好看""有没有质感""哪不对劲"，这是**这一层最常见的请求**，不能回一句"这个只能人判"。

正确的做法是**先拆、再判、标明置信度**：

| 用户的话 | 拆成可观察的判断 | 需要什么证据 |
|---|---|---|
| "有点廉价" | 焦点是否成立／层级是否只有一档／材质与光是否太平均／是否缺少一个刻意的选择 | 帧 + 联系表；必要时看两镜对比 |
| "看着闷" | 信息是否每镜等量／画面是否每镜同一动作／声音有没有起伏／是否存在超过两镜的同一个构图 | 联系表逐镜首帧 + 镜头时长 |
| "不像人做的" | 是否有具体的、不平整的细节（真实数字、具体处境、意外）／是否所有元素都"刚好居中" | 帧 + 文案 |
| "节奏怪" | 切点是否跟着信息落地／是否等间隔／是否有连续两镜说同一件事 | 逐镜时长表 + 首帧联系表 |
| "听不清" | 人声与音乐的电平关系／闪避有没有做／语句是否太长 | 响度读数 + 波形；**没有听辨就写"未听"** |

拆完之后给**一条判断**，形式见 §6。**拆不出来的部分才交给用户**，而且要具体：不是"这只能人判"，而是"这三处我能判（附证据），剩下的这一个取舍只能你定：要不要为这个效果牺牲第 2 镜的信息量"。

## 6. 一条可信的专业判断长什么样

六件，缺一件就会被当成主观意见：

1. **判断**：哪一镜、哪一秒、看到什么。
2. **依据**：在真实帧/连续片段/读数里看到的，能指出来。没看到的不要编。
3. **因果**：为什么这么读——观众的眼睛先落在哪、听觉被什么占住、信息在哪断了。
4. **可反驳条件**：什么情况下这个判断不成立（换播放尺寸、换受众、这是刻意的风格）。
5. **置信度**：看得清就说清楚，拿不准就说拿不准。
6. **另一条路与代价**：改成什么会怎样，要多花什么、要丢什么。

禁忌三条：**不把判断伪装成测量**（"显得挤"不是"密度超标 12%"）；**也不因为不能量化就不给判断**；**不用"用户觉得不好"代替自己的分析**。

## 7. 预期—实际闭环

分两段，缺一段等于没闭环：

1. **改前**：写 `预期可见变化`（哪几秒、应该看到什么不同，能写成像素/秒/读数就写）＋ `必须保留项`（人物、品牌、已确认的镜头设计、上一镜落点）。这两项分别进修改单的"期望变成什么"与"波及范围"。
2. **改后**：用同一 `(shot, t, purpose)` 重新取证，逐条对照改前那条证据；再复看改动点前后各 8 帧的接缝，并全片扫一遍同类现象。

对照失败时先排除取证条件变了（修订、时间点、源文件哈希），再判"修复无效"。

## 8. 三层结论，不许混

| 层 | 证明什么 | 谁负责 |
|---|---|---|
| 技术测量（黑帧、时长、响度、分辨率） | 没坏、没缺、达标 | 工具 |
| 已看与专业判断（`finding` 已填、附因果与置信度） | 这一段是这样，以及为什么它可能不对 | 你 |
| 用户决定（满不满意、要不要接受这个代价、值不值得发） | 只有用户能给 | 用户 |

报告里分开写：**已看**（附证据 id）、**专业判断**（附因果与置信度）、**未看**（缺什么输入）、**需用户决定**（取舍，不是评价）。

## 9. 判断示例

**"后面那段有点拖。"** → 先分清是节奏还是信息密度：镜头都短但信息原地重复是信息密度，回 `video-plan`；镜头长、画面不动、没有新事件是节奏，属于 `video-craft` 的剪辑一节。取证：抽后半段逐镜首帧定位长镜，测时长与全片均值比，再联系表看该镜是否在变。 → 输出："第 9—11 镜共 14 秒只推进一个信息点，其中第 10 镜 5.2 秒无可见变化"，写成三条修改单，不写"节奏偏慢"。

**"这版是不是比上版好？"** → 不能答"更好"，要答"改前那个现象还在不在"：按改前证据 id 找同一 `(revision, shot, t, purpose)` 重取对照。 → 输出："第 5 镜压脸已消失（对照 `r2-s05-12.4s-look`）；第 7 镜同类问题本次未核"。

**"整体感觉有点廉价，说不上哪不对。"** → 按 §5 拆：先看焦点（缩到 320px 还认得出主元素吗），再看层级（是否只有字号一档），再看材质与光（是否均匀无光比），最后看有没有一处刻意的选择（真实数字、具体处境、意外细节）。取证三镜首帧 + 联系表。 → 输出一条判断加代价："第 2、5、7 镜的主元素都只占画面 1/4 且居中，层级全靠字号；把主元素放大到 1/2 并给一处明暗对比会更稳，代价是第 5 镜要重排版式。置信度中等：我只看了静帧，运动未核。"

**反例**：只看了一张接触表就说"运镜很顺、节奏没问题"。错在两处：把导航工具当判据；绕过了 `purpose`（运镜与节奏要 `motion`，只能来自连续片段或用户观看）。

## 10. 什么时候不做这份

- 用户没让你看片，只是在推进下一步 → 不主动出检查报告。
- 手上没有成片、帧或工程 → 先说要哪种输入，不凭文件名和工程结构写"检查结论"。
- 用户只问"能不能发" → 转 `video-release`；只问"下一版怎么拍" → 转 `video-plan`。
- 改动成本远高于问题本身（改一处要重做整段）→ 只报最值钱的一两处，不铺全片清单。

## 11. 边界

- **不替用户决定满不满意、值不值得发、要不要接受这个代价**；但**必须给专业判断**（§5、§6）。
- 不直接改片、不改镜头设计、不改时长预算——修改单交回 `video-plan`。
- 合规、标识、许可、响度门禁、交付清单归 `video-release`。字幕怎么写归 `video-craft` 的文字一节；转场与节奏的改法归 `video-craft` 的剪辑一节。
- 接口字段只在 `docs/编写规范.md` 定义，本份只用不定义。

**不适用**：还在选技术路线、问"怎么让模型出这个镜头"（用 `video-types`）；没有成片也没有帧、只有想法（用 `video-plan`）；只问能不能发（用 `video-release`）。
