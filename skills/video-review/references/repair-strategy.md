# 修复策略：保留、局部修补还是重做

> 何时读：现象已经定位到根因，要在三种处置里选一个，或改完要判断"这次到底改到位没有"时。读它是为了不把结构问题当参数问题修，也不把单点问题拖成重做。

## 一、先选处置，再谈改法

| 处置 | 成立条件 | 代价 | 改完必须复检 |
|---|---|---|---|
| **保留** | 现象只在单帧或单元素；改动会碰到"必须保留项"（人物身份、品牌、已确认的镜头设计）；或它其实不是缺陷 | 零，但要把"为什么保留"写清，否则下一版又被提一次 | 无；在修改单"波及范围"记"不改"与理由 |
| **局部修补** | 根因能指到一个可改的点：一个坐标、一条字幕的位置、一段增益包络、一个层序、一帧的归零 | 只动这一处，但要连带复检相邻接缝 | 改动点前后各 8 帧；全片同类现象一次 |
| **重做** | 根因在结构：这一镜的信息或动作本身不成立；同一现象在 ≥3 镜重复出现（系统性）；或修完会推翻时长预算与相邻镜 | 要回 `video-plan` 重定这一镜，可能连带改时长与邻镜 | 整镜重看一遍 + 与前后镜的接缝 + 全片同类扫描 |

判据顺序：**先问"不改行不行"，再问"能不能只改这一点"，最后才问"要不要重做"。** 反过来容易一上来就重做。

三种各自写进修改单的方式：

- 保留："波及范围"写"不动"，"改完怎么验"写"下版复核它是否还成立"。
- 局部修补："波及范围"写"只动这一处；相邻第 4—6 镜同类位置一起核，其余不动"。
- 重做："属于谁的问题"写"创作设计"，"波及范围"列出会连带变的镜与时长。

## 二、改之前：写清预期（第一步）

必须写两行，写在修改单第 3、5 项里：

1. **预期可见变化**：哪几秒、应该看到什么不同。能写成可核的就写：
   - 位置：`12.4—14.0 秒，字底边与下颌线间距 ≥8px`
   - 读数：该段集成响度达到 `video-release` 给定的平台口径，段间差 ≤2 dB——口径与目标值由它定，本份只对照
   - 连续性：`第 7—8 镜接缝处主体位置差 ≤5% 画宽`
2. **必须保留项**：这次不许变的东西。人物身份、品牌、已确认的镜头目的、上一镜的落点。写不出保留项，说明还没想清这次改动的边界。

反例：预期写成"更自然""更顺""更高级"。这三句在改完之后无法对照——不是预期，是愿望。

## 三、改之后：对照（第二步）

1. **同键重取**：同一 `(shot, t, purpose)` 在新修订上重新取证，靠改前那条证据的 `id` 找回对照物，不靠记忆。
2. **逐条打勾**：预期可见变化一条一条对；必须保留项一条一条对。有一项没对，就不算改完。
3. **扩展复检**：改动点前后各 8 帧（接缝是否被带坏）；全片同类现象扫一遍（同一根因往往不止一处）。

对照失败时按顺序排除：

| 排查 | 现象 |
|---|---|
| 取证条件变了吗 | 修订号、时间点、源文件哈希不同 → 先重取，不下"修复无效" |
| 改的是不是根因 | 只改了一处，现象仍在别处 → 根因判断错，回缺陷库 |
| 修复引入了新问题 | 原现象没了，接缝或相邻元素坏了 → 局部修补代价超预期，改判重做 |
| 预期本身错了 | 改完符合预期，但用户仍不满意 → 预期写的是 AI 的理解，不是用户要的 |

## 四、常见错误修法

| 错误 | 为什么会犯 | 正确做法 |
|---|---|---|
| 字幕挪走压脸，结果压住底部进度条 | 只核了被投诉的那一处 | 挪完把该元素在整个安全区内的四个边界都复检一遍 |
| 元素没出现，去查时间轴 | 没看层序 | 先确认它是否被后画的容器整块盖住 |
| 闪烁修不掉，就把元素复制一份常亮的 | 看起来"稳了" | 要改的是双份叠渲染/曲线，不是再盖一层 |
| 用加动效掩盖静止 | "动起来就不算静止" | 只有与该段动词对应的动作才算；找不到就让它静着，改的是信息节奏 |
| 为过指标加元素（碎屑、装饰） | 指标好看 | 指标只报不判；加元素会稀释主角 |
| 把结构问题拆成五条局部修补 | 单条看起来都能改 | 同一现象 ≥3 镜重复就是系统性，回 plan 一次解决 |
| 改完只看了改动帧 | 省时间 | 接缝是最容易被带坏的地方，必须看前后各 8 帧 |
| 用预览页截图证明改好了 | 方便 | 从成片抽帧；预览与成片可能不一致 |
| 一键整体提亮/整体调大音量 | 掩盖段间差异 | 差异在段间，就该分段处理 |
| 同一处改两遍（既改坐标又改父容器缩放） | 两处都"看起来该改" | 先定一处为根因，另一处作为保留项复检 |

## 五、改到哪一步停手

- 修改需要动到用户已确认的镜头设计、时长预算或人物身份时，不自行改。写进修改单"波及范围"，由 `video-plan` 决定。
- 同一处修了两次仍在，第三次先停下：说明根因判错了，回缺陷库重新定位，不要继续试参数。
- 修完的版本要能被下一次对照找回：新修订另起证据条目，旧条目标 `superseded`，旧文件不删。
