# 代码出画面

本份只管"用代码把一镜画出来，并证明它过关"。设计系统归 video-visual，动效原则归 video-motion，提示词归 video-prompting。

## 1. 先判断这一镜该不该用代码画

不是"能不能"，是"该不该"。读 §1.1 的字段 3 画面、4 动作、5 镜头、8 做法（字段定义见 `docs/编写规范.md` §1.1），只回答一个问题：这一镜要观众**看懂**什么。

| 这一镜要观众看懂的 | 代码 | 判据 |
|---|---|---|
| 结构、顺序、数量、比例、参数关系 | 擅长 | 画面能被算出来，且算出来的比拍出来的更准 |
| 一个过程怎么发生（长出来、拆开、对上） | 擅长 | 变化本身是信息，不是修饰 |
| 真实的人、现场、材质与光 | 不擅长 | 观众判的是"像不像真的"，几何再准也过不了 |
| 情绪、微表情、手感细节 | 不擅长 | 代码给不了细节里的不确定 |
| 已经有实拍或截图素材的段落 | 不该 | 素材就是主画面，代码只该做标注与运镜 |

三条硬规则：

1. **写"做法＝代码"之前，先能说出这一镜"算的是什么"。** 说不出算的是什么，说明这一镜要的是质感——只是把"我不会拍"说成了"我用代码"。
2. **替换测试**：把这镜的代码画面换成一张精确的静态示意图，信息还在不在？还在，你要的是图解，不需要整条出帧管线；全丢了，才说明代码在承担"过程"。
3. **不许因为代码容易就全片代码画。** 识别方法：数一遍"做法"列里代码的占比；过半时逐镜回读字段 3 画面——凡是写着真人、现场、一只手、一件实物、一张截图素材的镜，做法就不该是代码。这类镜出去（实拍素材或 video-prompting），不是留在代码里硬画。

判完只回写字段 8，不动其他字段。

## 2. 动手前两道门

**第一道：时间来源。** 三选一，定了才能写第一行动画——帧域纯函数（要交付就用它）、弹簧积分（有重量，但换帧率就变）、曲线映射（语义清楚，但绑实现）。选了写进交付说明，中途换等于重做。

**第二道：确定性。** 要求是"同一工程两次渲染，同一时刻逐像素一致"：冷渲一次、热渲一次分开比。破坏它的是没种子的随机、读系统时钟、资源没就绪就取帧、字体回退、逐帧累加、跨机 GPU 差异、运行期联网。其中"运行期从 CDN 拉库和字体"是硬杀手，有现成反例。

两道门没过就别调节奏与美观——那时做出的"好看"不可复现，等于白做。

## 3. 选画法与字体

先定"这一镜最不能出错的是什么"，再选画法：排版 → HTML/CSS；几何与图表 → SVG 或 Canvas；材质与空间 → three，且文字仍用 HTML 叠层。

字体是第一翻车项：缺字会**静默回退**系统字体，换台机器字形全变，代码里看不出异常。所以画面里每个字（含数字与符号）都要在字体文件里；改了文案就重做子集；跨机承诺之前先确认字宽稳定。

## 4. 产出格式

| 给什么 | 内容 |
|---|---|
| 一镜一文件 | 同镜号一个视频文件，全片同宽高同帧率，便于硬切拼接 |
| 帧证据 | 每镜至少起点、动作中点、落点、镜末四张；带转场的另加 3 张；文件名带镜号与秒数 |
| 每镜一行结论 | 看了哪几处 → 量到什么 → 过／黄／红 → 哪项没看 |
| 一页交付说明 | 时间来源、确定性怎么验的、性能数字、用了哪几套字体与能否分发、已知限制 |

不写 §1.5 的证据索引（那是 video-review 的取证条目）：只交帧与结论，要正式取证时把那几帧交过去。

## 5. 三个判断示例

**例一**
用户这么说："第 4 镜就讲 KV cache 每步只算新的那一个，我想看小方块一个个冒出来，一眼看出数量差别。"
→ 你这样判断：字段 4 的动作是"每步只新增一块"，要看懂的是数量与顺序，代码擅长，而且"第 n 秒应该有 n 块"是能算出来、能核对的。字段 8 可以是代码。
→ 所以你这样做：时间来源定帧域纯函数（块数只是镜内秒的函数），先渲起点／中点／落点三帧核块数，再**跳着单渲 3.2 秒那一帧**与顺放时的同帧比对——两次不一致就说明实现里存了上一帧状态。

**例二**
用户这么说："机房那排指示灯亮起来，也用代码画吧，省得再去拍。"
→ 你这样判断：字段 3 写的是"一间没开灯的机房，一排指示灯在闪"，字段 8 已经是实拍素材＋调色——素材就是主画面，观众判的是"像不像真机房"。代码给的是干净几何，越画越像示意图。
→ 所以你这样做：这一镜不进本份，回 plan 保留"实拍素材"，代码只用在同一镜的标注（哪一排、第几号灯亮起）。确实找不到素材才转 video-prompting，不是拿代码顶。

**例三**
用户这么说："日志往上滚、越滚越快，速度要跟键盘声对上。"
→ 你这样判断：要"速度"被看见，代码擅长；但"对上声音"的锚点不在代码里，在剪辑时间线上。这镜的风险不是画不出来，是同步与可复现。
→ 所以你这样做：时间来源仍是帧域纯函数，但锚点秒数从 video-edit 的剪辑时间取来当参数传入，不自己数拍子；验收时抽锚点前后各两帧确认滚动位置，并把锚点出处写进交付说明。

**反例**
看起来合理、实际会错：这一镜已经用 three 搭了产品外观，就把同一镜里的人物特写也改成代码画，"反正都是 3D"。
错在第 1 步就错了，而且不容易看出来：字段 3 写的是这个人的脸和手，字段 5 是手持特写，观众判的是皮肤与眼神；代码给得出人形，给不出可信的脸。第 2 步也救不回来——时间来源定得再纯、确定性验得再干净，画面仍是"几何正确但没人信"。还有一处更隐蔽的错：为了迁就几何，这镜的镜头被从"手持特写"改成"正面不动"，那是字段 5，越界了，而且等于把用户否掉的东西当方案交上去。
正确处置：产品外观留 three，人物特写切出去走 video-prompting 或真实素材，两段用相近机位与光线衔接；衔接不上，说明这镜本来就不该混两种做法。

## 6. 边界

- 不设计系统：色板、字体气质、版式层级、封面归 video-visual。本份只说"这套字体在这个管线上会不会回退"。
- 不改动效原则：缓动是否自然、像不像 PPT 归 video-motion。本份只判"时间来源能不能支撑这个动效被复现"。
- 不写提示词：要真人或实拍质感归 video-prompting；要用真实素材回 video-plan 改字段 8。
- 不改镜头规格：字段 1、2、5、9 都不归本份。为了迁就代码把镜头改简单，是越界。
- 不做剪辑与字幕：转场、剪辑点、字幕规范归 video-edit。
- **不适用**：这一镜的判断标准是"像不像真的"（人物、现场、手、材质）时，不该用本份——用 video-prompting 或真实素材；只要一张精确图解、不需要"过程"时，也不必走整条出帧管线。
