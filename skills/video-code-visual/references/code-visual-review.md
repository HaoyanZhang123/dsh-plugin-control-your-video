# 代码画面的验收

> 何时读：一镜代码画面已经渲出来、要说"这镜过了"之前；或用户说"投出来有问题/怎么糊了/中间黑了一下"时。读它是为了用看画面得到证据，替代"我把代码逻辑读了一遍，应该是对的"。

## 0. 先划清一件事

代码正确 ≠ 画面对。所有"我看着代码没问题"的结论都不算验收，因为代码里看不见的东西才是高发区：字体回退、资源没加载、裁切溢出、图层顺序、某几帧几乎纯色、后段掉帧。这些全部只在帧上可见。

所以验收的单位是**帧和片段**，不是文件和 diff。取帧之后必须真的打开看；没看就写"未看"，不许写"已检查"。

## 1. 取帧：先定看哪几处

每镜至少这四类帧，缺一类就等于没验：

| 位置 | 看什么 |
|---|---|
| 起点（第一个有内容的画面） | 是否空板、是否有未加载的占位框 |
| 动作中点 | 运动是否连续，有无跳变、闪烁、穿帮 |
| 落点（动作结束那一刻） | 最终构图、字是否被裁、主体是否在画面里 |
| 镜末 | 与下一镜衔接前有没有停在空画面或黑场 |

补充两处，代价很小但常常抓到问题：

- **转场/衔接处**：按 1/4、1/2、3/4 进度各一张。逐段取帧时转场代码根本不会被执行，所以转场崩了也能"全绿"——这是真实踩过的坑。
- **段首那零点几秒要避开**。镜头冲击最强的地方会被误判成"没内容"或"跳变"；把测量起点往后挪，或把镜头事件单独标出来。

取帧密度按目的分：找"有没有内容"用低密度就够；找"跳变/闪一帧"必须按接近交付帧率取；判"字的位置对不对"用整屏 1× 不够，要看局部 2× 截取。

## 2. 几何一致性

要求：**同一场景在不同帧之间，只有"该变的东西"在变。**

- 做固定机位的场景时，除被指定的元素外，其余像素应当几乎不动。做法：取同一镜的起点与中点两帧，叠加求差，看差异是不是集中在预期区域；如果边框、标尺、标题、页脚也在动，说明它们被挂在了会动的容器上。
- 做有机位运动的场景时，判据换成"运动是整体的、可解释的"：所有元素按同一变换走，不该出现"背景在推、字不动"或"字跟着推但字宽变了"。
- 字跟随画布移动这条要单独验：字如果在离屏缓冲里画好再贴上来、或位图推镜，最容易与背景不同步；**跳着渲一帧**（直接跳到 3.2 秒）与顺放时那一帧比对，能抓出"依赖上一帧状态"的实现。
- 参考线/引线/箭头这类"手画的对齐"最容易出错：它们的端点是否真的落在所指的物件上，只有在帧上量才看得见。

## 3. 空场、占位、黑帧

按顺序查三类，判据都是"看帧"：

1. **占位**：画面里出现"待演绎""示例""Lorem""TODO""图 1"、灰色虚线框、未加载图片的占位块、只有外框的卡片。占位不是"以后再说"，是这一镜没做完。
2. **空板**：整帧几乎没有边缘或纹理（大面积纯色 + 中心一小块在动），或主体根本不在画面里。可执行的量法：在一帧里统计"梯度明显的像素占比"，占比极低就是空板；用边缘判、不要用颜色判——按颜色判会把黑底细线的图解、白板上的笔画一起判成空。
3. **黑帧/闪白**：中段出现连续若干帧近乎全黑或全白。给它一个可判的门槛（例如连续 ≥0.3 秒才算事故，单帧闪白要看是不是有意的节拍），并报告每一段的时间码，方便回去定位。

三类的结论都写成"时间码 + 看到了什么"，不要写"中间有点空"。

## 4. 字体

代码画面里最高发、也最容易被当成"设计就是这样"的一类。逐条过：

- **有没有回退**：把画面里要用的每个字（含数字、单位、标点、符号）与字体文件比对；缺了就是回退。回退的表现是笔画风格突然变了、某些字比旁边粗或细，不是报错。
- **有没有豆腐块**：方框里一个问号、或整块空白。这是缺字的最粗暴形态，但只在部分字上出现，漏看概率高。
- **动态写出的字**：从脚本里拼出来的文案最容易被漏进子集。改完文案要重跑子集，这一条不改就是"改了字，字没了"。
- **加载时机**：前几秒的字是空的、后几秒才出现，是字体晚加载 + 阻塞式显示的典型症状。查第一帧和第二个镜头开始的那一帧。
- **字宽与换行**：同一句话在同一台机器上换行位置应当固定；换机器后如果换行变了，说明字宽不稳定，版式没锁。
- **行高**：中文行高低于约 1.15 时，字身框会顶到上一行，表现为"两行贴在一起"或"检查工具报叠字"。
- **裁切**：字被画面边缘切掉一半、或落进字幕带（会被烧录字幕盖住）。查左右边距与底部区域，四个角最容易出问题。

## 5. 叠字与遮挡

- 两串不同的字互相压住：判据是两组文字的外框相交且都可见。装饰性的大字压在字幕带上、贴纸盖住标签，都属此类。
- 被非文字物件挡住的字不算叠字，但算遮挡：卡片、照片、讲解员后弹出来时，要确认被挡的是不是关键信息。
- 文字外框要**持续可见超过一定时长**再报，避免"飞过一帧"的动画被误报。

## 6. 性能

不要用"看着不卡"判断，用数字：

- **单帧耗时**要包含一次"强制 GPU 把活干完"的操作（例如读一个像素）。只计脚本的同步时间会量出 1ms 这种假数字，随后在长片上表现为莫名掉帧。
- **趋势**：第一帧、最后一帧、最密的一帧各量一次。如果越渲越慢，通常是缓存没命中或对象在泄漏。
- **上限**参照成片帧率的倒数：60fps 是 16.7ms、30fps 是 33.3ms，留出余量，别贴着上限做。移动端目标通常按 30fps 算。
- 时间超了先减**细节**（点、环、螺栓当细节画）、再把静态部分移出每帧循环、最后才降分辨率。

## 7. 流畅与跳变

- 相邻帧差要**成序列**看，不能只看首尾。只看首尾会漏掉"一卡一卡"——中间顿住，首尾却差得很多。
- 两个指标几乎够用：相邻帧差的**峰值与中位数之比**（孤立尖峰 = 跳变/闪烁/穿帮），以及"几乎不动的帧对占比"（占比过高 = 卡住，但要注意静止本身在讲解片里是合法的）。
- **镜头动作不是跳变**。推、拉、横移会被帧差判成"大变化"，要把它们单独记为镜头事件，并用"变化是否连续、结束是否停在最远处"来区分"推过去"与"闪一下又回来"。
- 数值超阈值只代表"去看这几帧"，不代表错。有意的节拍闪、整屏换色都是合法的，看完再定。

## 8. 成片层

- 规格：宽、高、帧率、时长是否等于要求；差 0.03 秒这种也要报，因为它会在拼接时累积。
- 音轨在不在、时长对不对。
- 硬切接缝处有没有一帧黑、一帧重复、一帧顺序错。
- 画法一致性：同一支片里有没有哪一镜明显是另一种画风（拼贴感），有就回 `canvas-and-three.md` 第 7 节。
- 配色与版式的判断不在这里：色板、层级、封面归 `video-visual`；节奏与转场归 `video-edit`。本份只报"画面里有没有坏"，不判"好不好看"。

## 9. 记录怎么写

每镜一行，四段：**看了哪几处 → 量到什么 → 结论（过/黄/红）→ 没看的部分**。

- "红"必须有时间码与一句可复现的动作（"3.4 秒起连续 0.4 秒整帧纯黑"）。
- "黄"写清是"去看"还是"确实有问题"。
- 没验的项照实写"未看"。全绿但有一项没看，结论是"未完成"，不是"通过"。
- 数字（耗时、运动面积、静止帧对占比）写进交付说明，不要只留在临时终端里。

## 10. 这一节不可省的理由

一份独立评审的标准里，把"回退字体或豆腐块""黑帧""规格不符"列为**critical**（严重）项而不是"小瑕疵"；另一套门禁把"中段连续近乎纯色"直接做成红灯不出片。它们都建立同一个判断：**这几类问题不是品味问题，是"没做完"**。所以本份的检查项不设"这次算了"的余地。
