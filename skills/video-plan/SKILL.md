# 完整制作方案

创意由主 Agent 与用户确认，随后集中调研，再规划完整作品。已有明确要求时承接用户的输入；还有关键分歧时先说明方案差异，确认会改变作品的取舍。历史偏好与作品仅在用户授权后参考。

## 先抓住片子靠什么成立

- 确定它靠信息推进、人物变化、情绪体验、实拍证据还是形式实验成立。要比较片型读 `references/format-and-shape.md`，要分析阶段推进读 `references/structure.md`。
- 从受众、场合和真实材料推导结构与时长。时间限制变化时重新算哪部分信息能讲完整。需要时读 `references/duration.md`。
- 用户提供参考时确认要借的效果和适用条件，读 `references/reference-rebuild.md`。

## 让全片每一镜真的能做

在一份 `plan.md` 里保留 `video-intent` 归纳的创作意图与用户确认的要求，并说明全片目标、约束、时长和结构。**逐镜写清四件事**：

1. **观众看见什么**：主体、景别、构图、空间。
2. **在变什么**：动作、运动，或**有意停留**（并写清为什么这里要停）。
3. **为什么在这一镜**：这一镜承担的表达目的。写不出目的的镜头，要么合并要么删。
4. **用什么做出来**：实际采用的技术或工具、需要的输入（已有素材路径／待产出）、产出怎么用于这一镜。

第 4 条是"可执行"与"看起来漂亮"的分界。**不存在的素材要写清怎么制作**，不能留"这里放个画面"。允许逐镜小节或镜头表两种写法；接手续作时先读原方案里的意图与约束。

区分三类资产：已有素材（指向已授权的项目内副本）、制作时生成的工件（说明用什么技术、从哪些输入做）、真缺条件的素材（说明影响与处理选项）。

**关键技术写进方案。** 实际会用的工具与技术路线、具体生成模型（若采用）、用途、预计费用上限、拟外发的内容范围，都写在这份方案里，与逐镜方案一起给用户看。用户批准方案即认可这些选择，之后按此范围执行与重试，不重复询问同一个选型；超出已写明范围（新费用、新的外发、换掉关键路线）才另外取得许可。

**技术路线按当前作品需要选，不预设。** 需要判断某条路线能不能达到效果、有哪些独有风险时读 `video-types`；需要判断画面、节奏、声音本身好不好时读 `video-craft`。不要为了"用上某个技术"而改镜头设计。

## 从小样到全片

通过 `cyv` 写入并检查当前版本。完整交付前自己复核叙事、制作可行性、镜头衔接和关键约束，让用户看得见完整版本，再用 `approve_plan` 请求批准。

完整方案批准后，制作**能验证关键效果**的代表性小样：挑最能暴露方案风险的镜头（新做法、最贵的一镜、最容易翻车的那类画面），而不是最好做的几镜。选段依据见 `references/sample.md`。

小样经过用户实际观看并认可，才进入全片。自选本机制作路线用 `approve_plan` 的 `external`，正式输出前调用 `prepare_run`，制作后用 `register_artifact` 登记**已组装好的成片**（画幅、帧率、帧数要与方案一致；中间产物留在工作目录）。

## 修改时先确定影响面

- 已明确的局部字幕或执行细节可保持核心内容、时长和用户硬要求，保护其他镜头。
- 当前写法有歧义时问清具体版本、片段和期待。改动核心结构或重要效果时，更新受影响的计划并重新取得相应认可。
- 成片运动、声音覆盖、连贯性和时长用实测检查；判断与取证分别见 `video-craft` 与 `video-review`。
- 每轮修改交完整新版，保留已被认可的版本。

## 不适用

- 用户只给一句模糊感受 → 先走 `video-intent`。
- 只是要改已有片子的字幕或某一段 → 按局部任务做，不必重排全片方案。
- 只问"这版哪里不对" → `video-review`；只问"能不能发" → `video-release`。
