# 视觉与版式

本份管四件事：设计系统（色、字、间距、层级）、版式通则、封面与标题画面、3D 与空间。管的是**决定**，不是画法：一镜的画面内容写在镜头规格第 3 字段"画面"里（字段定义见 `docs/编写规范.md` §1.1），本份读它、判断它够不够，不改它。

## 1. 先判断这次是什么任务

判据一条：**这次要动的视觉决定，会不会波及第二处**（第二镜、第二块版式、下一轮交付）。会，才值得重定系统；不会，就地改那一处。

| 用户这么说 | 处置 |
|---|---|
| "这个字改成深灰""标题再大一号" | 改这一处，不动系统、不动版式 |
| "封面没人点""换个封面" | 只走封面 → `references/cover.md` |
| "整片看着杂／太空／发土" | 先走版式通则，判完再决定要不要动系统 |
| "这套配色和字体先定下来" | 走设计系统 → `references/design-system.md` |
| "这镜要不要上 3D" | 先答"运动是不是解释" → `references/three-d.md` |
| "帮我做动效""这段怎么用代码画""这镜提示词怎么写" | 转 `video-motion` / `video-code-visual` / `video-prompting` |

三种情况下**不要**重定设计系统：只做一张封面、只改一处、已有品牌规范或用户已认可上一版。重定会把上一轮验过的对齐、字号和色彩关系一起推翻，代价远大于收益。

## 2. 决定顺序：从整体到局部

六步，前一步解决了就停。**"看起来更用心"不是继续往上的理由。**

1. **焦点**：把画面缩到 320px 宽（或眯眼看），还认得出一个主元素吗。认不出，后面五步都白做。
2. **构图**：主元素占多大、放在哪、视线从哪进、和文字是什么关系（→ `references/layout.md`）。
3. **疏密**：该空的地方空着吗。"空"是没有内容，"留白"是内容之间的间隔；区别在边缘有没有东西托住。
4. **空间**：2D 够不够。只有"不转起来就说不清"才往 3D 走（→ `references/three-d.md`）。
5. **排版**：字号、行高、行长、层级；中文断行在这一步一并判。
6. **色彩与细节**：最后才动色值、描边、阴影、颗粒。

换路条件：已有品牌规范 → 跳过系统部分，只做版式判定；用户只要封面 → 直接走封面的钩子判断；焦点没过 → 不调色，"靠配色救构图"是最常见的返工来源。

## 3. "高级感"不是配方

高级感来自**一套语言贯彻到底**（同一组字重、同一处分隔方式、同一个色相家族），不来自某一组数值。同一句"想要高级"，落到画面上至少有四组可以反向走的选择：大留白 vs 密排、低饱和 vs 高对比、衬线 vs grotesk、细描边 vs 实心。每组都能成立，也都能显得穷——成立条件与失效样子见 `references/design-system.md` 的"四组对比"。

明确拒绝一条公式：**低饱和＋慢镜头≠高级**。它是某类品牌片已经用滥的既有习惯，换到讲知识、讲工艺、讲人的片子里，只是让画面变灰。用户说"高级""克制""有质感"时，先翻成可观察的决定（色相数量上限、留白尺度、字重对比、分隔方式），翻不出来就从理由里删掉。

## 4. 可读性是交付门槛

不是风格问题，是不合格。按真实视口、真实字体、100% 阅读尺寸判断；**缩略图只能判构图，不能判字号**。

- 字号：视频正文不小于屏高 4%（1080p 约 40px 字高），再按观看距离核一次。网页正文 16–18px 直接搬进视频等于放弃可读性——那个值来自阅读型网页（`resources/research/已确认资产/03-美术图像与提示词/03-oil-ui-references/visual-language.md` 的"可读性是交付门槛"），只有换成手机竖屏近距离才近似成立。
- 行高：中文正文 1.7–1.8；多行中文标题 1.3–1.4（区间与失效条件见 `references/design-system.md`，按真实字形核）。汉字撑满字身框，不要照搬英文海报的 1.0–1.1，会撞行。
- 行长：正文 45–60 个汉字（约 50–75 字符），超了就加行或加宽。
- 中文断行三缺陷，见到算没做完：不可拆的词被拆开（"不会""38 秒""47 分钟"）、行末只剩一两个字、一个词跨两行。
- 中英混排：基线对齐、两种字看起来一样重；数字用等宽数字，单位跟着数字不换行。

## 5. 示例数据要像真的

整数指标、"张三李四"、"标题／描述"占位、每条都是"2 小时前"，一眼就是模板。改法：指标带零头（1,238 位用户、+1.83%）；时间分层（刚刚／昨天 16:12／3 月 14 日）；名字长短不一，顺带验长名排版；按钮写具体动作（"保存草稿""周二发送"）。同一支片里所有示例共用一个虚构场景：同一个产品、同一批人、同一组数字。

## 判断示例

**一、只改一个字**
用户这么说："这个'免费'太扎眼了，换成灰的。"
你这样判断：单点改，不波及第二处；但它原本可能是这一镜唯一的视觉重音，改灰会把重音一起抹掉。
所以你这样做：先确认它在体系里是什么角色——是强调就先把重音挪到旁边那处（价格或期限），再改灰；只改这一处，不重出配色。

**二、封面没人点**
用户这么说："封面没人点，帮我换一个。"
你这样判断：不是版式问题，是钩子问题。先看封面有没有一句能直接读出的事，再看文字占比：文字只占三成、主体是产品图，等于把海报当缩略图用。
所以你这样做：从片子里挑一个具体到能核的钩子（原文里最反直觉的那句），让文字占主导、主体退到一角；逐字核验中文，按平台原生比例重排，而不是裁一张 16:9。

**三、这镜要不要上 3D**
用户这么说："轴承的工作原理能不能做个 3D 转起来？"
你这样判断：要转的是"钢珠在滚道里的位置随转动变化"——运动本身就是解释，成立；只是想看外观转一圈，就是装饰，留在 2D。
所以你这样做：只给一个可读的角度范围和一个主光方向，标清观众要读到的那一处（滚道接触点）；文字与标注留在固定层，不跟着转；先准备"停成静帧也读得懂"的退化版。

**反例**：用户说"画面太土了"，你判断成配色不行，于是换了一套更灰的色板、降饱和、加颗粒，顺手把字号统一小一号。
错在第一步：没做焦点判定。土往往是三处同时弱——主元素不够大、层级只有字号一档、文字压在正中。换色之后焦点仍然散，还把可读性一起赔掉。正确顺序是先判焦点与构图，配色只能放最后。

## 边界

- 动效与缓动、单个元素怎么动、为什么像 PPT → `video-motion`。本份只判"该不该动、动的是什么关系"。
- 用 Canvas/three/HTML 实现画面、出帧管线、代码画面验收 → `video-code-visual`。本份给意图与约束，不给实现。
- 生成模型的提示词（封面要生成、这镜要生成） → `video-prompting`。本份写"要什么关系"，不写模型输入。
- 转场、剪辑点、字幕排版与安全区 → `video-edit`。字幕带在这里只当版式禁区用，字怎么排归它。
- 片型、结构、镜头编号与时长 → `video-plan`。本份不改镜头规格的任何字段。
- **不适用**：无画面的交付（纯声音、纯口播稿）不归本份；只需审片取证（这帧糊不糊、字幕有没有压脸）走 `video-review`，用 §1.3 的修改单回来；创作设计被否时先回 `video-plan` 判范围，不在视觉层打补丁。

## 按需参考

- 要定配色／字体／间距，或判断"这套系统要不要重定" → `references/design-system.md`
