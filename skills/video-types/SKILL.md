# 制作路线

这份管"这一镜怎么做出来，以及这条路线会怎么坏"。

**路线不是身份。** 一支片里不同镜头用不同技术是正常的；同一镜里也可以分层（三维空间 ＋ HTML 文字 ＋ 后期调色）。不要因为会用一个工具，就让全片都用它；也不要因为用户说了一个工具名，就把另一个更合适的方案咽回去。

## 1. 先定要什么，再定用什么

三个问题，答完再挑技术：

1. **观众要看见什么、看懂什么？** 是主体与材质、是结构与顺序、是过程、是情绪、还是"像不像真的"。
2. **要准确到什么程度？** 数字、比例、参数关系必须对（代码擅长）；还是只需要可信的观感（实拍与生成擅长）。
3. **可编辑性与交付要求是什么？** 要改一句话就重出（代码/工程擅长）；只交一次成片（生成也够）；要能长期复用同一套工程（要保留源与依赖）。

**替换测试**：把这一镜换成一张精确的静态图/一段真实素材/一句更强的文字，信息还在不在？还在，你要的是图解或表达，不需要整条出片管线；全丢了，才说明这条路线的"过程"本身是内容。

**"轻易不要用最贵那条"不等于"只用最便宜那条"。** 判断标准是这条路线是否真的服务于这一镜的表达，以及它的风险是不是你能验的。

## 2. 五条路线的独有风险

不是功能清单，是"它会怎么坏"。

| 路线 | 它独有的是什么 | 最常翻车 | 怎么验 |
|---|---|---|---|
| 程序化/代码 | 时间可精确控制、几何与数据绝对准确、可任意重渲 | 不可复现、字体静默回退、渲染慢到改不动 | 两次渲染逐像素比；跳帧单渲比对；字体子集核字 |
| 实拍素材 | 真实质感、现场的不确定性、可信度 | 素材不够、时间码对不上、权利与肖像、影音同步 | 清点与时间码；看首末帧；核授权 |
| 三维 CG | 空间关系、材质与光、任意机位 | 像玩具、渲染成本失控、动起来不像有重量 | 停成静帧还读得懂吗；同机位同光渲染对比 |
| 生成式素材 | 低成本得到难拍的画面与风格 | 不可控、一致性差、文档与型号过期、许可与费用 | 一次只改一个变量；小样先验；约定可接受的失败率 |
| 混合媒体 | 各取所长 | 画幅/帧率/色彩/声音桥接处露馅 | 桥接点逐帧看；统一色彩空间与响度 |

**一条片里出现"两个世界"不是问题，桥接处露馅才是。** 混合媒体的功夫都在接缝上（见 §7）。

## 3. 代码与程序化：先判该不该，再过两道门

**不是"能不能"，是"该不该"。** 只回答一个问题：这一镜要观众看懂什么。

| 要观众看懂的 | 代码 | 判据 |
|---|---|---|
| 结构、顺序、数量、比例、参数关系 | 擅长 | 画面能被算出来，且算出来比拍出来更准 |
| 一个过程怎么发生（长出来、拆开、对上） | 擅长 | 变化本身是信息，不是修饰 |
| 真实的人、现场、材质与光 | 不擅长 | 观众判的是"像不像真的"，几何再准也过不了 |
| 情绪、微表情、手感细节 | 不擅长 | 代码给不了细节里的不确定 |
| 已经有实拍或截图素材的段落 | 不该 | 素材就是主画面，代码只该做标注与运镜 |

**写"做法＝代码"之前，先能说出这一镜"算的是什么"。** 说不出算的是什么，说明这一镜要的是质感——只是把"我不会拍"说成了"我用代码"。

**两道门，没过就别调节奏与美观**（那时做出的"好看"不可复现，等于白做）：

1. **时间来源三选一**：帧域纯函数（要交付就用它）／弹簧积分（有重量，但换帧率就变）／曲线映射（语义清楚，但绑实现）。定了才能写第一行动画，中途换等于重做。
2. **确定性**："同一工程两次渲染，同一时刻逐像素一致"——冷渲一次、热渲一次分开比。破坏它的是：没种子的随机、读系统时钟、资源没就绪就取帧、字体回退、逐帧累加、跨机 GPU 差异、运行期联网。**运行期从 CDN 拉库和字体是硬杀手。**

**画法选择**：先定"这一镜最不能出错的是什么"——排版 → HTML/CSS；几何与图表 → SVG 或 Canvas；材质与空间 → three，且文字仍用 HTML 叠层。

**字体是第一翻车项**：缺字会**静默回退**系统字体，换台机器字形全变，代码里看不出异常。画面里每个字（含数字与符号）都要在字体文件里；改了文案就重做子集；跨机承诺之前先确认字宽稳定。

细节见 `references/code-driven.md`、`references/code-canvas-three.md`、`references/code-render-pipeline.md`。

## 4. 实拍与素材：素材就是主画面

实拍路线成败的九成在开机之前：素材够不够、能不能对上、有没有权利。

- **先清点再设计**。写下每段素材的时长、分辨率、可用区间与限制（编号、隐私、客户信息、不能出现的品牌）。素材清单不是形式主义——"我以为有那个镜头"是这类片子最常见的返工。
- **时间码是事实**，不是大概。剪点、卡点、字幕时间都要落在真实时间码上；预估和实测差半秒，整段节奏就错。
- **权利与肖像**是要先问的：谁拍的、能不能商用、有没有人的可识别形象与声音。判断与核查清单在 `video-release`，这里只负责**别在制作中途才发现用不了**。
- **影音同步**：采访与口播的口型、环境声的连续性、静场的位置。声音的工艺判断在 `video-craft` 的声音一节。
- **剪辑伦理**：纪录与采访类，镜头顺序会改变语义。删掉一段话与删掉一句话，是两种不同的事。
- **素材不足时不要硬顶**：用代码画"像真的现场"、用生成模型补"不存在的证据"，都会在观众那里立刻失效。宁可改分镜、改叙事方式，或如实说明缺什么。

细节见 `references/real-footage.md`。

## 5. 三维 CG：空间是不是解释

**只有"不转起来就说不清"才往 3D 走。** 要转的是"钢珠在滚道里的位置随转动变化"——运动本身就是解释，成立；只是想看外观转一圈，是装饰，留在二维。

- 只给一个可读的角度范围和一个主光方向，标清观众要读到的那一处（滚道接触点、装配关系、层级）。
- **文字与标注留在固定层**，不跟着转。
- **先准备"停成静帧也读得懂"的退化版**——很多人是在小屏、静音、滑动中看到这一帧的。
- **渲染成本会改变创作**：一次迭代 40 分钟和 40 秒，能试的方向数量差一个量级。先按"能不能在今晚试三个版本"来定精度与采样。
- **像玩具的三个来源**：光比太平均、材质缺乏微小尺度（划痕、指纹、灰尘）、运动没有重量感。三个都不在建模层解决。

细节见 `references/cg-3d.md`。

## 6. 生成式：它是不确定的合作者

**先查这个模型当前允许什么，再决定怎么写；查不到就降级成散文，并标明这是假设。**

**六种任务，写法与约束不是一回事**：新建（文字输入）／编辑（原片输入，改什么、其余不变）／延长（往哪个方向接）／首尾帧（1—2 张图，中间怎么过渡）／参考（图/视频/音频各控制什么）／分镜（多图或多段文字，切点与连续性）。任务类型判错，后面写得多准都白费——把编辑写成新建，模型会重拍一遍。

**通用方法是查约束，不是套公式**。动笔前确认六件事：任务类型清单、比例与时长是否被输入锁死、参考素材的数量与时长上限、素材编号与绑定方式、提示词长度上限、有没有音频通道与负向支持。

- **参考素材一份一句话职责**：主体身份／风格／构图／动作与运镜／场景／声音。编号按上传顺序、正文逐份绑定；**不要把名字写在图片上再在正文里喊名字**。一张图同时被要求管风格和管身份，是冲突源；拆不开就说明这一版做不了。
- **写可见的东西**："夜景街道"换成"湿沥青、斑马线、霓虹倒影"。动作写成"从什么到什么"。"高级""有质感"对模型不是指令。
- **保留项单列**：总时长、帧数、卡点结构、分镜区间、全局视觉规范，指向具体文件或常量，不靠上下文记忆。
- **一次只改一个变量**，否则下次好转也说不清是哪一步起的作用。身份错了的排查顺序是：参考用途 → 上传顺序与编号 → 模型支持的主体数量 → 最后才重写主体描述。**不要**先加"高质量""8K""完美五官"。
- **失败要按证据归因**，不用"再抽一次"代替判断：措辞、参数、模型边界、服务问题，四类分开。见 `references/generative-failure.md`。

**能力、型号与价格会过期。** 具体型号的名称、参数、上限、是否关停，一律以当前可查到的资料为准，不要照抄本文或旧快照。仓库里的 `docs/model-notes/` 是**带日期的历史快照**，只作写法参考，不作能力声明。

**当前工具只有提示词通道。** 授权接口明确拒绝 `image/video/inputs/source/path` 之类参数——也就是**参考图、首尾帧、图生视频目前没有通道**。需要时必须如实说明并商量替代（改分镜、用代码合成、用实拍），不要假装能发图。

**费用与选型写在完整方案里**：型号、用途、预计费用上限、拟外发内容随 `plan.md` 一起给用户批准；批准后按此范围执行与重试，不再重复询问同一个选型。超出已写明范围才另外取得许可。

## 7. 混合：桥接才是风险

同一支片用多种技术，本身不产生新问题；**接缝产生**。

- **画幅与帧率**：不同来源不同帧率时，先统一到交付帧率再谈节奏；否则卡点会在重采样后漂移。画幅不同时决定是裁、是补、还是把差异做成设计（黑边/框架）。
- **色彩**：不同来源的 gamma 与色域不同，剪在一起会"一个世界一个世界"。先统一色彩空间，再调风格；只在最后一步做整体 grade。
- **声音**：不同来源的底噪、响度、房间里不同。统一响度与底噪比统一画面更难，也更容易被听出来。
- **运动速度**：三维渲染的"真实"与代码动画的"设计感"在同一条时间线上的速度感不同，剪在一起会显得一段快一段慢。
- **一致性的三个支点**：机位与光线关系、色彩空间、运动速度。这三个对齐，风格差异反而成了段落标记；这三个不对齐，观众读到的是"拼的"。
- **分层要把责任写明**：这一镜里谁负责空间、谁负责文字、谁负责粒子、谁负责最终合成。写在工程备注里，不要靠记忆。

细节见 `references/mixed-media.md`。

## 8. 把路线落进项目

- **中间产物留在工作目录**：图片序列、音频、工程文件、缓存都进项目 `work/`；**正式交付必须是组装好的成片**。
- **登记的是成片，不是素材**。外部路线用 `prepare_run` 拿阶段身份与期望参数，做完再 `register_artifact`。这个校验要求画幅、帧率**精确相等**、帧数与时长吻合、单视频流可完整解码——也就是说**组装这一步必须由你完成**：模型原始输出、图片序列、分轨音频都要先合成成片，再登记。
- **依赖与版本要记**：用了什么引擎、什么版本、哪些字体、哪些模型，写在工程备注或交付说明里。下次换台机器能不能重来，取决于这一行写没写。
- **可复现**：同样的输入再跑一次，能不能得到同样的东西。做不到的要在交付说明里写清"不可复现的部分是什么"。
- **能力状态分级**：听说过／有文档／本机装了／能跑通／已在本项目验证，是五件不同的事。没验证过就写"未验证"，不要说"支持"。
