# 意图澄清与意图摘要

把用户的原话变成 `video-plan` 能直接用的判断。

**目标不是问全信息，是把"说不清"变成"可以比较、可以选、可以做"。** 大多数用户说得出感受、说不出参数；你的工作是给读法与代价，不是发一张表让他填。

## 1. 先判断这次是什么任务

| 进来的样子 | 怎么处理 |
|---|---|
| 方向清楚，只差片型、结构、时长、镜头 | 简短归纳已明确的意图和约束，交 `video-plan` |
| 有感觉、有材料，说不出要做成什么片 | 进本份，产意图摘要 |
| 丢来参考片说"就要这样" | 进本份，先拆片（§5） |
| 给了文稿或旧成片，说"按这个来" | 材料即方向：进本份但少问（§6） |
| 用户改了口径 | 只改摘要里受影响的那几项（§7） |

## 2. 问不问，问几个

一个问题值得问，只有一条判据：**答案不同，方案会选不同的结构、材料或路线。** 答案只影响执行细节的，不问，自己给默认值并写清"这部分我按 X 处理，你不满意随时说"。

真正值得问的四类，其余归你：

- 目标不同：同一批材料能做两支用途完全不同的片；
- 私有事实：只有用户知道的产品口径、人名、数字、不能公开的东西；
- 价值取舍：真实与好看、信息量与情绪之间的两难；
- 交付与花钱：平台、时长、必须交付的东西、要不要付费生成。

**执行细节与技术选型你不必逐项请示**：普通实现方式、本机制作工具、走哪条路线，由你按作品需要判断；会改变作品效果的取舍才拿出来商量。具体模型与其他关键技术写进完整方案，随方案一起获批（见 `video-plan`）。

几条实践判据（不是配额）：

- 只问会改变方向的问题；能合并就合并。一轮通常两三个就够，问多了通常说明第一问没问到点上。
- **先给判断与依据，再问。** "我理解你要的是可信而不是燃，所以想确认一件事：……"比"你想要什么风格？"有用得多。
- 同一件事只问一次，答过的不再问第二遍。
- 不问"你觉得这个方向怎么样"，要给**两三种具体读法**让他选、否，或说"都试试"。
- 不把字段表丢给用户填，不在对话里显示置信度分数或诊断表格。

## 3. 产出：意图摘要

在对话中归纳，写完整方案时并入同一份 `plan.md`。清楚时可以简写。摘要要能让没参与对话的人知道：

| 要知道什么 | 例 |
|---|---|
| 用户的原话（关键处逐字保留） | "别太燃，燃了我反而不信。" |
| 你的理解，且每句能指回某句原话 | 可信 > 激动：用真实细节换掉形容词，不加快切、不用大字金句。 |
| 不能丢的约束 | 真人出镜不能出现品牌；90 秒内；必须出现这三个数字 |
| 明确不要的东西 | 大字口号、摆拍演员、快切 |
| 交给 AI 决定的部分 | 结构、时长分配、配色、音乐风格 |
| 仍然未知、且会影响效果的 | 观众是谁（决定术语深浅） |

最后一项控制在真正会影响方向的少数几条，是**缺口清单**不是问题清单——不要为了填满而发明问题。

## 4. 感觉词怎么翻

不建"感觉词＝配方"的映射（"高级感＝低饱和＋慢镜头"就是假公式）。固定三步：

1. **找比较对象**：这感觉是跟什么比出来的——竞品、他自己以前做的、他讨厌的某支片。
2. **落到四层**：看到什么与信息多少／画面在变还是故意不动／声音关系（谁说、说什么、有没有静场）／质感取向（干净可控还是现场粗糙）。
3. **给至少两种读法并说代价**，让他选、否，或标"未知"交给小样定。

分辨不了时给对照，不给形容词；能指认具体位置（哪一帧、哪一句）就先按可指认的那条推进。常见读法与代价见 `references/feeling-words.md`。

## 5. 参考片：先判断他看中哪一层

允许问、也只问这一句："你指的是整支，还是里面某一段、某个瞬间？"——答案改变拆解对象。

拆解顺序本身就是判断：**叙事结构 → 节奏与时长 → 视觉语言 → 具体效果**。先看结构才知道要不要借；先看效果最容易把"某个转场"当成"整片风格"。

写进摘要时分成两栏：**借什么**（两三条，可检验、能落成动作）／**不借什么**（带原因：品牌不能占、内容不匹配、成本做不到）。结构层面的重构归 `video-plan`，本份只写清要借哪一层。拆法见 `references/reference-teardown.md`。

## 6. 已有材料：先标可用程度

| 材料 | 判断 | 处置 |
|---|---|---|
| 用户逐字给的句子、口号、数字、人名 | 可直接用，且不改字 | 进"必须有的"；整篇文稿的删改另看授权，他说"随便改"就是授权，没说就只删不改写 |
| 录屏、成片、现场素材 | 可直接用或需加工 | 写明能用到什么程度、哪里不能用（编号、隐私、客户信息） |
| 截图、别人的片、竞品 | 需向用户澄清 | 确认要参考的效果与可用范围 |

旧成片可以当方向和素材，**不默认沿用它的结构**。不因为手上有素材就必须用。

## 7. 缺字段与改主意

- 缺就写"未知""未提出"，不编。
- 先判是补充还是覆盖：**同一件事的新说法＝覆盖**，旧约束失效；新增维度、语气加强＝补充。
- 覆盖的写法：原话**追加**并标日期，旧原话不删，后面注"（2026-11-18 起前一句不再适用）"，再一句话告诉 `video-plan` 哪条失效。没被提到的其他约束一律继续有效。
- 结构、镜头、声音被改不回头改摘要，除非用户改的是目标本身。

## 8. 判断示例

**"想要那种高级感，但别太像广告。"** → 判断：这是"怕像广告"，不是"要某种调色"。广告感来自大字口号、快切、摆拍和口号式旁白；高级感至少有三种读法（少信息大留白／真实材质细节／克制的声音）。 → 做法：只问一句"你更怕哪一种：满屏大字金句，还是假笑摆拍的演员？"，把答案写进"一定不能有的"；"我的理解"写"信息少、留白多、不出现口号式旁白"，其余标未知交给小样。

**"就要这样。"（附一支 90 秒片）** → 判断：还没分清他看中的是结构、节奏还是某个效果；整支照抄会把别人的品牌语言一起搬进来。 → 做法：先问"整支，还是里面某一段？"，再按 §5 四层拆，写"借：开头只给环境声不给音乐、信息一段一段给／不借：那支片的快切密度、它的品牌色"；他指认了某个字效，就只把那个字效写进"必须有的"。

**"稿子我写好了，你随便剪，越快越好。"（附 3000 字文稿和上一版成片）** → 判断：文稿可直接用，逐字给的句子不改；"随便剪"是授权；上一版成片只当参考，不定结构。 → 做法：只问一个会改变做法的问题——"上一版那句开场白保留还是换掉？"；风格、音乐、镜头一概不问，摘要写完直接交 `video-plan`。

**反例**：用户说"我想要那种高级感"，你回一张字段表让他填；或者直接写下"高级感＝低饱和＋慢镜头＋无衬线字体"进入制作。错在把"哪一种读法"这个该由你判断、或用小样分辨的问题退回到用户身上，同时把用户没说过的一种读法写成了要求。

## 9. 边界

**不适用**：用户已给完整脚本、明确片型与时长，只说"帮我做得好看点"——进本份会把明确任务退化成提问，直接交 `video-plan`。

片型、结构、时长预算归 `video-plan`；视听专业判断归 `video-craft`；制作路线归 `video-types`；成片哪里不对归 `video-review`；拆解结果要不要入库由 `video-library` 决定，写入前问用户。

| 丢来参考片说"就要这样""照着这个做" | `references/reference-teardown.md` | 四层拆解与"借什么/不借什么" |
