# 本包与 DSH 的机制约定

> 何时读：要新建或移动一份技能、要决定它放哪一层，或"技能没出现/没触发"要定位原因时。读它是为了按机制事实摆文件，而不是靠印象反复试。

## 1. 名字与形态

- 名字正则：`^[a-z0-9]+(?:-[a-z0-9]+)*$`。大写、下划线、空格、中文都不合法。
- 两种形态：目录包 `<name>/SKILL.md`（本包一律用这种）；单文件 `<name>.md`。
- **目录名 = frontmatter `name` = 正文标题**，三者必须一致；加载时名字与候选不符会被拒绝并触发重新发现。
- **嵌套的 `**/SKILL.md` 故意不被发现。** 所以 `references/` 下放多少带 frontmatter 的文档都不会被注册成技能——这是"套娃"免费的机制来源，也是本包把细节放参考的依据。

## 2. frontmatter

| 字段 | 必填 | 作用 |
|---|---|---|
| `name` | 是 | kebab-case，与目录名逐字一致 |
| `description` | 是 | **唯一触发面**，进目录 |
| `whenToUse` | 否 | 额外路由提示，**不进目录**，不影响触发 |
| `metadata` | 否 | 任意对象，给作者自己用 |
| `disable-model-invocation` | 否 | `true` = 模型看不到、目录里不出现 |
| `user-invocable` | 否 | `false` = 用户 `/名字` 调不了 |

- 布尔合法值：`true/false`、`yes/no`、`on/off`、`1/0`，大小写不敏感。其余写法一律按非法处理。
- **非法值 = 整条技能被丢弃，只写日志，模型侧没有任何诊断。** 驼峰 `disableModelInvocation` 直接毁掉这条技能。
- 由此推出一条：想改进触发，只能改 `description`。指望 `whenToUse` 补触发是无效的。

## 3. rank 与遮蔽

| rank | 来源 | 路径 |
|---|---|---|
| 100 | project-dsh | `<项目根>/.dsh/skills` |
| 200 | project-agents | `<项目根>/.agents/skills` |
| 300 | custom | `customSkillDirs`（本包产品技能） |
| 400 | user-dsh | `<DSH_HOME>/skills`（跳过 `.system`） |
| 500 | user-agents | `$DSH_AGENTS_HOME/skills` |
| 600 | bundled | `bundledSkillDir` |

- 项目根 = 最近含 `.git` 的祖先；没有则用 cwd。
- 重名决出顺序：**rank → 提供者注册顺序 → 本地顺序**。
- **某根发现失败 → 该根零候选，低优先级同名会顶上**，没有任何提示。表现是"版本静默更换"：你以为在用包里的，其实在用别处的旧版。
- 所以：用户在工作区 `.dsh/skills` 放了同名技能，会静默盖住 rank 300 的产品技能。排查时先查这一条。

## 4. 分层与作用域

注册表 = host 层 + 每作用域层。读取时合并全局层与当前作用域链，**最近层同名直接胜出**，rank 只在同层内比较。

两个问题要分开看：

| 问题 | 由什么决定 |
|---|---|
| 技能出现在哪些会话 | provider 挂在哪一层（preset 常驻组合的 provider 注册进该 preset 的层） |
| 扫描哪些目录 | provider 的配置（`customSkillDirs`、`includeDefaultRoots` 等） |

结论：产品技能放 `customSkillDirs` 只在本 preset 可见；放进 `.dsh/skills` 或 `$DSH_HOME/skills`，**所有 preset 都能看到**。用户自写技能放 `<工作区>/.dsh/skills/`（rank 100），自动发现、不用改 patch；产品内容严禁放 `$DSH_HOME/skills`。

## 5. 目录消息

- 会话首个 pre-step 之前注入，作为**持久 user-role 消息**；之后只有变化才追加替换；全删时追加空信封并禁止使用旧名。
- 内容只有 `name` + 规范化并做 XML 转义的 `description`。**不含正文、路径、source、provider、whenToUse。**
- 单个描述上限 `catalogDescriptionMaxLength`，默认 **500**（最小 3），超长截断。
- 本包自加一条更严的：总长 ≤320，首个负向边界必须落在前 220 字符内，并点名替代技能。
- 成本：随技能数与描述长度增长；只发一次不是每请求，但描述确实常驻。真正的代价不是 token，是**触发歧义**——13 条描述排在一起读，看不出该用哪条，就是这份描述写坏了。

## 6. 加载

两条路：模型调 `skill({name})`，或用户输入 `/名字`。两者产出同一份内容：

```
<skill_content>
  <skill_resources>   资源基址（不是文件清单）
  <skill_instructions> 正文
</skill_content>
```

两条硬规则：

1. **加载结果不枚举技能目录，只给资源基址。** 正文不写"什么条件下读哪份"，参考文件在模型眼里等于不存在。这不是文风问题，是机制。
2. **正文每次重读，注册表不缓存完整定义。** 改正文立刻生效、不产生目录消息、不改写已发生的旧结果；改 frontmatter 才会更新目录。

关于 8192：那是标准 preset 里工具结果压缩工具的阈值，裁剪在压缩触发之后运行，**不是 Skill 合法性上限**。"8000 字符超了就不算合法 Skill"是流传的错误口径，不要写进正文当门禁。

## 7. 调用策略四种组合

| 模型可调 | 用户可 `/` | 结果 |
|---|---|---|
| 是 | 是 | 默认形态，本包各份都用这个 |
| 是 | 否 | 只有模型能加载（`user-invocable: false`） |
| 否 | 是 | 隐藏技能，只有用户点名才进上下文 |
| 否 | 否 | 只有程序能取，等于内部库 |

在技能目录里点名一份技能、写过"不要再调一次工具"的，属于用户 `/名字` 内联那条路；模型主动加载仍然走 `skill` 工具。

## 8. references / scripts / assets 的职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `references/` | 模型资料、参数与版本、案例拆解、判据清单 | 命令速查表以外的正文判断（判断留在 SKILL.md） |
| `scripts/` | 确定性动作：抽帧、测量、索引查询、结构校验 | 需要模型临场判断的事 |
| `assets/` | 模板、媒体、字体、示例文件 | 会被误当成正文的方法描述 |

- 脚本要能重复执行、参数明确、失败给退出码。**只打印结论不返回非零的检查不算门禁**，调用方会以为它过了。
- 路径写相对技能目录，不写本机绝对路径。

## 9. watch 刷新什么、不刷新什么

| 会刷新 | 不会刷新 |
|---|---|
| 目录与文件的增删改名 | `references/` 的内容 |
| frontmatter 变化（含 `description`） | `scripts/` 的内容 |
| 新技能出现 | `assets/` 的内容 |

所以改参考文件之后，正在跑的会话不会重新发现它；要**新开会话**再验证。这条几乎所有人都会踩：改完参考发现"模型还是没读"，其实是它不知道有这份文件，或者它拿到的是旧基址。

## 10. 哪些改动要新开会话

| 改了什么 | 处理 |
|---|---|
| SKILL.md 正文 | 立刻生效，无需重开 |
| frontmatter（尤其 `description`） | 目录刷新；老会话的目录消息不会重放，要新开会话看新描述 |
| 新增技能目录、改 `customSkillDirs`、改 patch | 重装 + **新开会话**；老会话保持启动时的版本 |
| `references/`、`scripts/`、`assets/` | 新开会在新会话里验证 |
| 本地链接安装 | 改文件即改产物；不需要重新打包 |

验证动作只有一个：**新会话的技能目录里有没有那个名字**。看目录，不看日志；也不要从模型说"我没看到"反推。

## 11. 十个坑

| # | 坑 | 后果 |
|---|---|---|
| 1 | 子文档放二级目录并指望被注册 | 永不出现（设计如此） |
| 2 | invocation 键写驼峰 | 整条静默消失 |
| 3 | 关键边界写在描述 500 字符之后 | 被截断，误触发 |
| 4 | 产品技能放项目或用户目录 | 泄漏到所有 preset |
| 5 | 项目里有同名技能 | rank 100 盖住 300，无提示 |
| 6 | 改完 patch 在老会话里看 | 老会话保持启动版本，必须新开 |
| 7 | 正文过长 | 压缩触发后被掐头去尾，关键判断丢失 |
| 8 | 方法写进 persona | 每请求付费，且改动影响缓存前缀 |
| 9 | 指望技能授予工具能力 | 技能不挂工具、不给权限 |
| 10 | 只放参考不写"何时读" | 模型不知道去读，参考等于不存在 |

## 12. 排障：技能没出现，按这个顺序查

1. 名字是否 kebab-case；目录名、`name`、正文标题是否逐字一致。
2. frontmatter 是否合法（布尔写法、有没有驼峰键）。
3. provider 是否挂在本会话的 preset 里（换个 preset 看不到是正常的）。
4. `customSkillDirs` / 根路径是否解析成功（`!!js` 是否成立）。
5. 是否被更高 rank 的同名技能遮蔽（先查项目 `.dsh/skills`）。
6. 是否在用老会话（preset 改动只对新会话生效）。
7. 是否属于不完整发现（目录会带警告，可重试）。
8. 描述是否超长被截断到看不出用途。

名字在、但该触发时没触发：问题在 `description`，不在正文。名字不在：问题在装配或发现，不在文案。
