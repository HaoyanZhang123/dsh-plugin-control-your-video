# 怎么验证一个技能

> 何时读：一份技能刚写完、改过 `description`，或要回答"它到底有没有用"时。读它是为了分清哪一层已经证明、哪一层根本没碰过，不用一层的结论替另一层下判断。

## 1. 四层各自证明什么

| 层 | 证明什么 | 不能证明 | 谁做 |
|---|---|---|---|
| 结构校验 | 名字、frontmatter、行数、参考头两行合规 | 内容有用 | 逐项核，或脚本 |
| 静态评审 | 有专业增量、无空话、示例具体 | 模型会照做 | 人读 |
| 隔离的新会话任务 | 会加载、行为真的变了 | 作品好不好 | 新会话 + 对照 |
| 真实作品 + 用户看 | 这次能用 | 普遍有效 | 用户 |

顺序不能跳，也不能互相顶替。前两层做完只能说"文件合格"，后两层做完只能说"这次成立"。任何一层缺失，结论就要写成"这一层还没验证"。

## 2. 第一层：结构校验

逐项核，任何一项不过就改，不要带着问题往下走：

- [ ] 目录名 = `name` = 正文 H1，三处逐字一致；名字匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`
- [ ] frontmatter 只有合法字段，布尔值用 `true/false`、`yes/no`、`on/off`、`1/0`
- [ ] `description` 三段齐（做什么／何时用／不适用），总长 ≤320，首个"不适用"在前 220 字符内，且点名了替代技能
- [ ] 正文 ≤150 行；没有把命令、参数、模型清单塞进正文
- [ ] 每份 reference 头两行是 `# 标题`＋空行＋`> 何时读：…。读它是为了…。`
- [ ] "按需参考"每条都是 `触发条件 → 文件名`，文件名真实存在，与头两行对得上
- [ ] 没有空目录、没有占位文件
- [ ] 相邻技能的边界处只有一句指针，没有展开写别人的方法

结构校验只证形态。它通过而内容空洞，是非常常见的状态。

## 3. 第二层：静态评审

- **删段测试**：逐段问"删掉这段，模型的行为会变差吗"。答案否就删。这一条能删掉大部分空话。
- **空话识别**：出现"要专业""注意质量""保持统一""多练""要善于总结"，直接删。判断方法是把它换成一句可执行的话，换不出来就是空话。
- **专业增量**：这一句，只有做过这件事的人写得出来吗？任何领域的人都能写的，属于通用常识。
- **示例具体性**：判断示例里有没有用户原话、有没有具体处置（改哪一镜、走哪条路、说什么话）。写"当用户需要 X 时"就是没写。
- **反例**：有没有写清**错在哪一步**，而不只是"这样不好"。
- **触发面**：只读 `description`、不读正文，能不能决定用不用？读不出就是触发面没写好。
- **条件化**：所有数值、禁令、阈值，写没写它来自哪支片、换片型还成不成立、不成立时替代判断是什么。

静态评审只证内容自洽。它不证明模型会照做，也不证明这套方法在真实任务里有用。

## 4. 第三层：隔离的新会话任务

协议，按顺序：

1. **新开会话。** 老会话保持启动时的版本，改完 patch 或新增目录在老会话里看不到。
2. **先确认目录。** 看技能目录里有没有那个名字，名字和描述对不对。这一步不过，后面全是白做。
3. **同模型、同输入。** 对照那条会话用同一个模型、同一句话、同样的材料。
4. **只说任务，不说技能名。** "帮我看看这条片为什么像 PPT"而不是"请用 video-motion"。点名调用测的是服从，不是触发。
5. **看它有没有真的加载**：调用了 `skill` 工具、加载的是这一份。看的是调用记录，不是模型自述。
6. **看行为差在哪一处**：同一个输入，加载与不加载，处置具体差在哪里。说不出差异，就是没验证。

### 前后对照怎么不被历史污染

- 不能"先加载再看"——同一个会话里历史已经带着正文，后面的表现不再干净。
- 两条会话：A 能看到这份技能，B 看不到（或看旧版），其余条件完全相同。只差这一个变量。
- **不做效果百分比。** 两句对话、一次任务，给不出"提升 30%"这种数。要写就写"这一处从 A 变成了 B"。
- 顺序也要控：先跑 B 再跑 A，避免先跑 A 时你已经带着它的思路，把输入写得不一样了。

第三层证明的是"行为变了"，不是"变好了"。好不好看、好不好听，它答不了。

## 5. 第四层：真实作品 + 用户看

拿一次真实任务做完整流程，让用户看成片、听声音、说意见。这一层证明的是"这次能用"，只对这次的作品成立。

- 用户说"不对"时，先分是**理解错、方法错、还是执行错**，再决定改技能还是改作品。不要把每一次修改都回写成技能规则。
- 一次任务成立，不等于普遍有效。写结论时限定范围："这一支、这个片型、这次素材下成立"。
- 用户没看过就结束的，这一层没做。不要拿第三层的"行为变了"顶替。

## 6. 什么不算验证

| 做法 | 为什么不算 |
|---|---|
| "我通读了一遍，觉得很专业" | 这是静态印象，连第二层都不到 |
| "日志里显示已加载" | 加载 ≠ 行为改变；且日志不是模型看到的目录 |
| 模型说"我已按规范执行" | 自述不可作证据 |
| 在改完技能的老会话里试 | 历史已污染，且老会话可能是旧版本 |
| 只跑一个会话 | 没有对照，差异无法归因到技能 |
| 用一句"请用 video-xxx"试 | 测的是点名服从，不是触发 |
| 报一个效果百分比 | 样本与设计都不支持，属于无依据结论 |
| 结构校验通过就说"技能可用" | 只证形态 |

## 7. 验证记录怎么写

一行一层，缺哪层就写缺：

```
结构：131 行；name/目录/标题一致；description 208 字符，首个"不负责"在第 131 字符；参考 3 份，头两行齐。
静态：删段后剩 12 节；示例 3 个含原话；反例写清错在第 3 步；未发现"要专业"类句子。
新会话：新开两条，同模型同输入；A 目录里可见，B 不可见；A 触发并加载，处置差异是"先查归属再改"，B 直接改。
真实作品：未做。上游还没出成片，本层空缺。
```

"未做"本身是有效结论。把空缺写清楚，比补一个不可靠的通过更有用。
