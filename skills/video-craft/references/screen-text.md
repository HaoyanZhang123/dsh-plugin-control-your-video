# 字幕：四个旋钮、行长与断行

> 何时读：要定字幕的行长、断行、出现多久、放在哪，或用户说"字幕来不及看""压脸了""断得怪""太长了"时。读它是为了先判断四个旋钮里哪一个拧错了，而不是一律改字号。

## 四个旋钮，其余都是派生

| 旋钮 | 它决定什么 | 拧错的症状 | 主要调法 |
|---|---|---|---|
| 断句单位 | 一条字幕装多少话 | "一条太满"或"一闪而过" | 并块／拆块；断在从句边界 |
| 行长 | 一行的物理宽度 | 溢出被裁、或空掉一半 | 量像素宽；换字号只在最后考虑 |
| 时长与阅读速度 | 出现多久 | "来不及看""停太久" | 并块延长、掐缝、按字数反推 |
| 位置与安全区 | 出现在画面哪里 | 压脸、压画面文字、被裁 | 挪位置、留出 UI 区 |

四个里只有一个错了却去改别的，是最常见的返工来源。比如"来不及看"多半是断句单位与时长的问题，不是字号。

## 行长：两套单位，两套约束

来源是 BBC 的字幕规范（广播与在线两套载体）：

| 载体 | 上限 | 性质 |
|---|---|---|
| 广播（Teletext） | 37 个**固定宽**字符（40 字节里至少 3 个是控制码；用了彩色字要更少） | 载体的硬限制 |
| 在线（比例字体） | 画幅宽度的 68%（16:9）；90%（4:3 / 1:1 / 9:16） | 像素比例 |
| 两平台同时要满足 | 区域内字符数不超过 37 | 取更严的那条 |

BBC 还给了换算参考：16:9 的 75% 宽区域约等于 37 字符，换成 9:16 的 90% 宽区域约 25 字符；比例字体下窄字（i、l）能多塞几个，但宽字（w、m）多时 25 个也可能放不下。

**条件化**：37 是 Teletext 的载体约束，不是视觉标准。今天做网页、竖屏短视频，这一条不成立；能带走的是"留白比例"这一层——任何画幅都别贴着边放，两侧留出画面宽度的 15—30%。

## 字符数 ≠ 像素宽度：要量，不要数

- 同样字符数宽度不同：材料里给的原例是 `lilly` 比 `mummy` 窄得多。
- 中文与拉丁更不是一个尺度：中文近方块，宽度约等于字号；拉丁随字母组合浮动（`i` 与 `m` 差好几倍）。
- 所以"一行不超过 20 字"这种规则，只在"字体、字号、画幅、语言"都不变时才近似成立。

**实测做法**（思路取自一项按字体量宽再平衡折行的实现，GPL-3.0，只取思路）：

1. 用**实际会用的字体与字号**量出这条文本的包围盒宽度，字间距按 `(n-1)×spacing` 加上。
2. 与可用宽度（区域宽 − 左右内边距 − 余量）比。
3. 超了才折行；折行时先按可用宽度贪心算出**最少行数**，再按"总宽 ÷ 行数"把字重新分配，让两行长短接近——一长一短时观众眼睛要来回找。
4. 留 5—10% 余量：换个渲染环境、换个字体回退，恰好放满的会溢出。

中英混排时按显式字体测，不要假设浏览器/渲染器的默认度量与设计师的软件一致。

## 断句单位

- **一条一个字幕装一句话**（BBC 的默认口径）。语速快时有例外。
- **短句可以合并**成一条（阅读时间有限时），但要同时看画面与说话节奏；连续的短字幕有时更贴语速，未必更差。
- **长句不要拆成两句**，让它跨多条字幕，断在从句边界，每条各成一个语义单位（"当你上了／那辆公交／我看见那个人……"）。
- 常见的误用：把一句话切成三块、每块只显示零点几秒——这时最短时长与阅读速度两条都不过（见下一节）。
- ASR 出来的分段常带短缝，按停顿合并到一条是常见起点：材料里一项实现用 1.5 秒作为"允许的最大间隔"，更长的缝才断开。具体值随语速变，是起点不是标准。

## 时长与阅读速度：下限与上限是两条规则

| 约束 | 口径 | 来源性质 |
|---|---|---|
| 下限（最短时长） | 每个字幕事件最短 5/6 秒（24fps 下 20 帧）；最长 7 秒 | Netflix 交付规范 |
| 上限（阅读速度） | 推荐 160—180 词/分钟，折成约 0.3 秒/词（4 个词给 1.2 秒） | BBC 字幕规范 |

**不能混算成一条。** 把两条揉成"平均每条 3 秒"，会让长句超上限（读不完）、短句破下限（等于没出现）。同一句"6 秒 40 字"两条都过；"2 秒 30 字"两条都不过——后者正是"字幕来不及看"最常见的真实病灶。

算的顺序：

1. 先算这条**读得完**要多久（字数或词数 × 单位时长）。
2. 再与语音给的时间比。语音太短，有三种做法：并块延长、延后消失（让它在语音结束后还留一下）、改文本（归 `video-craft` 的文字部分）。
3. 中文按字算：口播约 4 字/秒是估算起点，字幕的上限要快于口播——常见落在 4—6 字/秒区间，超过 6 字/秒基本读不完。**这一条是从口播语速推的，不是字幕规范给的**；以自己读一遍计时为准。

**条件化**：5/6—7 秒是 Netflix 的平台规范；37 字符是广播载体约束；160—180 WPM 是电视字幕的推荐速率。一支 15 秒竖屏短视频里，一条字幕待 7 秒显然不对——上限要跟着载体的注意力走，下限则始终成立（短于一瞬等于没有）。

## 行数与位置

- 横屏与方形（16:9、4:3、1:1）**最多 2 行**；竖屏（9:16）**最多 3 行**（BBC）。多行的前提是不遮重要画面信息。
- 居中，放顶部或底部。避免压住画面上已有的字；压脸属于执行错误，不是审美选择。
- 安全区（Teletext 网格口径）：顶行文字上沿在画面 5% 处，末行下沿在 95% 处，左边界不小于 12.5%；等效说法是"在中间 90% 的高度里放一个 4:3 区"，在 16:9 里宽度约 67.5%。现代做法把可用宽度扩到 75%，两侧另加行内边距。
- **条件化**：这些百分比来自广播时代防过扫描（overscan，电视把边缘切掉）的做法。流媒体没有过扫描，但"别贴边"仍然成立；具体比例随平台与画幅，别把 5%/95% 当通用门禁。

## 断行是语言问题，不是几何问题

BBC 的原话方向是：理想的排版在"语言"与"几何"之间折中，但**优先语言**。

不能断开的搭配（BBC 五类＋Netflix 六类合并）：

| 不能拆开 | 例 |
|---|---|
| 冠词与名词 | the + table；a + book |
| 名词与形容词 | a red + car |
| 介词与后面的短语 | on + the table；about + his life |
| 连词与后面的从句 | and + those books；but + I went there |
| 代词与动词 | he + is；they + will come |
| 复合动词的组成部分 | have + eaten；will + have + been + doing |
| 介词性动词与它的介词 | look + after |
| 动词与助动词、反身代词、否定词 | do + not；wash + himself |
| 名字与姓 | Ada + Lovelace |

另加三条：

1. **词不能被拆到两行**。这是最破坏阅读的一种。
2. **行末不要孤字**（一行只剩一个词）。
3. **优先断在标点**：句号、逗号、破折号。

BBC 允许的例外：空间实在紧张时，可以断在动词之后（原文例：`We are aiming to / get / a better television service.`）；但把一个紧密短语劈开（`aiming to get a / better…`）比断在动词后更糟。

**中文的落地**（BBC/Netflix 是英文语法规则，中文要自己补）：

- 数字与单位不断开：`40 秒` 不能拆成 `40` / `秒`。
- 否定词与它修饰的成分不断开：`不会` / `不能` / `没法` 这类双字否定词被拆开，语义直接变。
- 量词与名词、把字句/被字句的介词与宾语不断。
- 行末不要只剩一个汉字（孤字），宁可让上行少放一个字。
- 中文词间没有空格，断行靠语义判断，比英文更依赖人工；纯按字数均分会切在词中间。
- 中英混排：外文术语不拆；中文数字与外文之间用不断行空格。
- 标点不要孤悬在行首（句末标点应留在上一行末）。

## 三种格式的抽象不同，换层要重写

| 格式 | 抽象 | 排版靠什么 | 明确做不到 |
|---|---|---|---|
| WebVTT | cue（时间段＋文本）＋ cue settings（line / position / size / align / vertical / region） | 外部 `::cue` CSS，或文件内 STYLE 块（必须在第一条 cue 之前，且块内不能有空行、不能用 ` --> `） | 样式表达力受 `::cue` 限制；浏览器在需要时会自行插入换行，作者写的断行不一定是最终看到的 |
| ASS | 行样式（字体/颜色/边距/对齐）＋ override tag | 边距以**脚本像素**给出，决定自动断行在哪发生；`\N` 硬断行、`\h` 硬空格、`\an` 九宫格对齐；override tag 只影响它之后的文字 | **没有两端对齐**（格式限制）；部分参数只在样式里有、部分只在 tag 里有；`\fad` 只做淡入淡出，**不延长显示时长** |
| 组件/数据（Remotion 等） | caption 数组，每条起止时间＋文本 | React/CSS/组件样式 | 分页要自己做（token→page）；换渲染环境样式可能不可用 |

三条判断：

1. 三种之间不存在"翻译"，只有重写。把 ASS 的"边距决定断行"搬到 cue 上会错位——一个是脚本像素，一个是视口百分比。
2. 任何格式都要问一次"最终看到的断行是谁决定的"。WebVTT 允许浏览器重排，ASS 由边距与 `\N` 决定。
3. 样式参数能不能生效，取决于播放器/渲染器；查当前工具支持什么，查不到就退回"位置＋行数＋字数"这三件最稳的事。

## 词级时间从哪来：能力边界

- Whisper 原生给的是**句级**时间，不是词级，而且可能偏几秒（WhisperX 自己的说明）。
- 词级要靠额外手段：cross-attention＋DTW（stable-ts 的 `word_timestamps`）、强制对齐（wav2vec2，WhisperX）、VAD 校正。
- 有了词级时间才能做逐词高亮与精确的块起止；没有就按句排，不要假装词级。
- 字幕起点与音频起点的误差可以量：读波形找 onset，一项实现记录做到约 1 帧。
- 许可提醒：`videocaptioner` 是 GPL-3.0，只能作研究参考，代码与常量不随包；本份从它只取"按像素量宽再平衡折行"这一个思路。`stable-ts`（MIT）、`faster-whisper`（MIT）、`whisperx`（BSD-2-Clause）可作工具线索，但本轮未安装、未运行。

## 验收

- 抽全片最长的一条：正常速度读一遍，读得完吗？读不完就是上限没过。
- 抽最短的一条：来得及看一眼吗？来不及就是下限没过。
- 抽三处断行：有没有把词拆开、有没有孤字、有没有断在搭配中间。
- 看有人的镜头：字压没压脸；看有字的画面：字幕有没有压住画面文字。
- 量三条字幕的起点与语音起点偏差，超过一帧量级就要重排。

### 中文断行：十分钟自验法

三条中文规则（数字与单位不拆、否定词不与动词分开、行尾不留孤字）是从英文规则推的，没有语料。不要凭这份文档直接定规则，用一段你真会用的字幕验一遍：

1. 取 20 行成片字幕的纯文本，按平台的字宽上限逐行切。
2. 出声读每行，记下"读起来断了"的位置，不凭看。
3. 把断点归类：数字被拆、否定词与动词分开、行尾落单一个虚词、专名被拆、其它。
4. 命中最多的那一类，就是这份片型的第一条真规则；写进资产库 `methods/` 并标"本片型实测"。

验之前这三条只能当假设用；写进方案时标注"待验"。行宽与像素宽的测法来自一项具体实现，本轮未安装、未运行其代码。
