# 把文章改成口播稿

> 何时读：用户给的是一篇文章、一份文档、一段旧稿或一堆笔记，要求"改成口播／解说／念出来的版本"时。读它是为了判断哪些字必须留、哪些能砍、以及原文长到装不下时该怎么跟用户说。

## 0. 先定三件事，再动笔

| 要定的事 | 为什么会改写法 |
|---|---|
| 这条片子有没有人声、观众在什么场合听 | 无人声时不需要改口播，只需要切屏上字（归 video-craft 的剪辑部分） |
| 观众对这个题材已经知道多少 | 决定术语要不要先解释、例子要不要从零讲 |
| 目标时长是多少 | 决定这是"改写"还是"容量不够，得拆"（见 §4） |

第 3 条没有答案就先问时长，不要先改。改完再发现装不下，等于白改一遍。

## 1. 核心原则：换说法，不是做摘要

文章改口播，改的是**说法的形状**，不是**信息的量**。把一篇论述压成几条结论，做出来的不是口播稿，是一份提纲的朗读版。

判断标准（用三条，不只第一条）：

1. **关键事实对得上**：数字、名称、时间、结论逐条能对上，不能整段消失。
2. **论证链没跳步**：前提 → 结论、因为 → 所以、A 与 B 的对比，可以换说法，不能跳过中间那一环。
3. **具体例子还在**：案例、场景、原话，这些都是口播里最抓人的部分，不能因为"太长"先砍它们。

### 关于"信息保留度 ≥ 60%"

garden 那份材料把它写成硬门槛（`script.md` 字数 ÷ `article.md` 字数 ≥ 0.6）。这是一个**有用的起点参考值**，不是通用门槛：

- 它成立的条件：原文本身就是给人读的成稿、结构清楚、套话不多、目标是同平台的视频化改写。
- 它不成立的情况：原文是一份 API 文档、一份会议记录、一份已经写得很紧的讲稿——这类原文里可压缩的水分本来就少，删到 60% 往往已经伤了内容；反过来原文注水严重时，删到 40% 也可能还剩九成信息。
- 所以用它当**事后核对**，不要当**事前配额**。写的时候按"这段有没有信息"决定去留，写完再算比例，明显低于六成时回查一遍是不是砍错了东西。

### 关于"每句 ≤20 字""B 站默认风格"

同样来自那一份单作者材料，是**某个平台某种片子的默认值**：

- 短句在口播里普遍有效，因为长句念不断气、观众跟不上。
- 但"≤20 字"不是通则：舒缓的长视频、需要铺陈的纪录片腔、带大量专有名词的技术讲解，句子允许更长；反过来短视频可能要求更短。
- 真正跨场景成立的是**句子长度要变**（见 `narration-principles.md` §8），以及**一句话里不要塞两个转折**。

## 2. 保留什么

以下五类，删任何一个都要先问自己"删了之后观众会漏掉什么"：

1. **关键数据与数字**。核心冲击数字保留原值；过程性数字可以换感受，但原值不能从稿子里消失——移到屏上字或稿末的"必须能核的"清单。
2. **案例、例子、故事**。这是口播里唯一能让人坐住的东西。原文有一个具体场景，改写时它应该变得更具体，不是更短。
3. **论证链的中间步骤**。原文"因为 A 所以 B，因此 C"，不能改成"A，所以 C"。中间那步是观众跟上来的台阶。
4. **反方观点、限制条件、例外情况**。这是最容易被一刀切掉的部分，也是最容易让稿子变成吹稿的部分。原文说"但在 X 情况下不成立"，这句话必须留，而且往往值得单独一句。
5. **作者的判断与不确定**。原文哪里明确说"我认为""不确定""有争议"，改写时不要抹平成客观陈述。

## 3. 压缩什么

可以大幅压、甚至完全删掉的：

- 套话开场（"随着……的发展""在当今时代"）与客套结语。
- 同一件事说两遍（一处抽象一处具体时，留具体那处）。
- 学术性铺垫与文献格式（"据《XX 研究》2023 年指出"→"我看过一份研究，它说……"，出处留在稿末清单里）。
- 章节目录式的过渡（"首先 / 其次 / 最后""下面进入第二部分"）。
- 为了完整而存在的句子（"除此之外，还有其他因素需要考虑"）。

## 4. 装不下的时候：报数，不要偷压

原文长度与目标时长对不上时，最常见的错误是悄悄压到三成，交一份看起来完整的稿子。这比交不出稿更糟——用户以为信息还在。

正确做法：

1. **报数**：按中文约 4 字/秒估，给出"目标时长大约能放多少字"和"原文按六成留存需要多少时长"。两个数字摆出来，用户自己看得见矛盾。
2. **给两条路**，并说清代价：
   - **拉长视频**：信息保得住，但钩子、节奏、段数要重排，原稿的密度会显得拖。
   - **拆成多集**：每集要有自己的处境开场和自己的落点，不能只是把文章切成三段。
3. **给拆分建议**：找原文里"各自能独立成立"的因果段作为集边界；找不到独立成立的段落，说明这篇不适合拆，只能拉长或改做别的形式。

不要替用户选。也不要在压完之后补一句"如需保留更多内容请告知"——那句话不解决问题，问题在数字上。

## 5. 具体改写动作

按这个顺序做，每一步都能单独检查：

**① 先抽主线，不要跟着原文段落走。** 原文的段落顺序是写作顺序，不是理解顺序。先写下这条片子要回答的那一个问题，再决定原文哪几段属于它、哪几段是旁支。

**② 定开场。** 从原文里找最具体的一个场景、最反常识的一句结论、或最刺人的一个数字，把它提到第一句。不要用"本文将介绍""我们来看看"开场。

**③ 逐段换说法。** 一段一段过，每段问三个问题：这段的结论是什么？观众为什么想知道这个结论？有没有一个具体的东西能替代这里的抽象说法？

**④ 处理念不出来的东西。**

| 原文里的 | 口播里怎么办 |
|---|---|
| 括号补充（"该模型（基于 attention 架构）"） | 并进正文，或删；括号里的话念不出来 |
| 书名号、引号引用格式 | 改成"我看过一份报告说……"，完整出处进稿末清单 |
| emoji | 删（除非用户明确要） |
| 大段英文术语 | 判断观众是否熟悉；不熟悉就先用中文讲清再挂英文名 |
| 网址、邮箱、代码片段 | 不念；改成"链接我放评论区"或让画面上显示 |
| 数字与单位 | 写成要念出来的样子（"1.9 万亿"写成"将近两万亿"），精确值让画面显示 |

**⑤ 数字改写两次**：一次决定保真还是换感受（见 `narration-principles.md` §5），一次决定它写成的样子是不是"人能念出来"的（"99.999%"念作"九十九点九九九"没人跟得上，画面显示即可）。

**⑥ 出声读一遍。** 默读不算。读到哪里想跳过、觉得"这话我说不出口"，回到那一段重写。

## 6. 双源：节奏跟新稿，细节回原文

改写完成之后，稿子只承担**顺序与说法**；原文继续承担**细节密度**。画面上的数字、引用、案例维度、时间线，回去原文抽，不要只从改好的稿子里拿。只从稿子拿的结果是屏幕把旁白打了一遍字。

这条对写稿的人只有一个动作：稿子定稿后，把原文对应段落的位置标出来（哪一段来自原文哪一节），交给下游。

## 7. 平台差异怎么用（条件化，别当默认）

不同平台的听感基线不同，这个差异是**调整**，不是**重写**。参考下面这张表时，注意它描述的是"节奏与信息密度"，不改变语言、不改变信息量。

| 场景 | 句子倾向 | 钩子位置 | 一个想法占多久 |
|---|---|---|---|
| 长视频讲解（十分钟级） | 允许长句铺陈，但每段仍要有短句落点 | 半分钟内建立处境即可 | 8—12 秒 |
| 中视频（三五分钟） | 长短交替 | 十秒内 | 5—8 秒 |
| 短视频（一分钟内） | 短、密、直接给结论 | 一两秒内 | 3—5 秒 |

表里的秒数是**经验区间，不是门禁**。查不到依据时按"这个题材的观众能跟多快"判断，不要为了对齐某个数字把一句完整的话切成三段。

## 8. 交稿前自检

- [ ] 关键事实逐条对得上原文，没有整段消失
- [ ] 论证链没跳步（尤其"因此"前面那一步还在）
- [ ] 反方、限制、例外还在
- [ ] 每个抽象说法后面有具体物
- [ ] 数字分过类：该保真的保真，该换感受的换了，原值有落脚处
- [ ] 术语先讲清再挂名，挂了的名字后面还用了一次
- [ ] 段落交界处上一段留了问题，没有报幕句
- [ ] 括号、书名号、emoji、网址、代码不在要念的部分里
- [ ] 出声读过，没有"说不出口"的句子
- [ ] 算过字数与时长，和用户给的目标对得上；对不上时已经报数并给了两条路
