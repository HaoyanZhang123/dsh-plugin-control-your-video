# 权利、许可与肖像

> 何时读：片子里用了他人素材、字体、音乐、真人肖像，或要把一支片子交给平台/甲方/客户、要判"我有没有权利这样用"时。读它是为了分清"用工具做的"与"用素材做的"两条链，并按动作查出必须做什么。

## 1. 先分链，再查条款

| 片子怎么来的 | 受什么约束 |
|---|---|
| 用工具做的（MIT/Apache/GPL/AGPL 工具、OFL 字体嵌入成片） | **片子不受工具许可约束**；工具本身的分发仍受约束 |
| 用素材做的（CC 系列、他人音乐、他人画面、他人字体文件） | **片子受素材许可约束**，署名/非商业条件直接落在成片上 |
| 我们随包交付的东西 | 按"完全 MIT"目标逐层核；外部工具与用户作品不因此被重新许可 |

一句话记住：**用工具做出来的片子不受工具许可约束；用素材做出来的片子受素材许可约束。** 两条链不能混。

## 2. 按动作查（比按许可查更好用）

| 我们要做的事 | 会触发什么 |
|---|---|
| 复制/修改一个 MIT 仓库的代码 | 保留 LICENSE 与版权行 |
| 修改 Apache-2.0 文件后分发 | 标注"我改过"；保留原声明；**把 NOTICE 传导下去**；不用作者商标 |
| 内部用 GPL 工具渲染、不分发 | 不触发附加条件 |
| 修改 GPL/AGPL 代码并对外分发 | 整体 GPL/AGPL 化；AGPL 另需向网络用户提供源码 |
| 片子里用 CC BY 素材 | 五要素署名＋标明修改＋放许可链接 |
| 片子里用 CC BY-NC 素材 | 同上＋仅非商业（按"主要意图"判，不是"有没有收钱"） |
| 用 CC0 素材 | 无署名义务；**但仍需自己清第三方权利（肖像/商标/音乐）** |
| 嵌入 OFL 字体到视频/网页 | 可以；成片不受 OFL 约束 |
| 子集化/改名/改字形后**分发字体文件** | 很可能构成 Modified Version → 不得使用保留字体名；字体须整体 OFL |
| 用 AI 生成画面 | 见 `ai-labeling.md`；版权只保护人类创作部分 |

## 3. 三条"输出归属"条款

- GPL-3.0 第 2 条：运行输出"仅当该输出依其内容本身构成 covered work"才受本许可覆盖 → 用 GPL 工具渲染的 mp4 **通常**不受 GPL 约束。
- OFL 1.1 末段："字体须整体 OFL 分发"的要求不适用于用该字体创建的文档 → 用 OFL 字体做的片子不受 OFL 约束。
- MIT / Apache-2.0：只覆盖"软件及相关文档" → 用它们做的片子不受约束，但工具本身要保留声明。

**反向提醒**：这三条只管"工具→输出"。片子里若用了 CC 素材，署名/非商业条件直接作用于片子。

## 4. CC 系列的三个坑

1. **"署名"是五要素，不是写个作者名**：创作者标识、版权声明、许可声明、免责声明、许可 URI/链接；还要**标明是否修改**。实践中漏得最多的是免责声明和修改标注。
2. **"非商业"测的是主要意图/指向**：免费发布但为自家产品导流，仍可能算商业。
3. **CC0 不是"没有权利"**：声明人只能放弃他自己的权利——放弃不了被拍摄者的肖像权、画面里的商标权、音乐版权。CC0 文件自己写明"不负责清理他人权利、不负责取得必要同意"。**CC0 不能替代模特授权。**

## 5. 真人肖像与声音

- 换脸/换声/口型/数字人 → 必须有"告知＋单独同意"的证据包（来源、授权文本、生成记录三者对得上）。详见 `ai-labeling.md` §6。
- 素材是 CC0 或买断，不等于肖像也清了：被拍摄者的肖像权是独立的一层。
- 不得无同意使用真人照片级替身；不得使用受保护标志（如红十字）；不得出现第三方品牌 logo。
- 同人／fan-art IP：粉丝向可以，商业化或赞助前必须显式提示风险。

## 6. "完全 MIT"是四层，不是一句口号

| 层 | 能否完全 MIT | 说明 |
|---|---|---|
| ① 我们自己的源代码 | 可以 | 前提是不并入 Apache/AGPL/NC 代码 |
| ② 随附素材（图、音、字体） | 不能一刀切 | 字体几乎都是 OFL，素材常是 CC BY/CC0；不能改成 MIT，只能各自声明 |
| ③ 运行时依赖（GSAP、ffmpeg、Playwright/Chromium） | 不能 | 是"依赖"不是"我们的代码"，但会进入交付物 |
| ④ 成片本身 | 不受工具许可约束 | 用了 CC 素材则受素材许可约束 |

**所以"完全 MIT"要写清是第①层**；把①说成"整个项目都是 MIT"会误导。

**适用边界（已确认口径）**：覆盖随包交付的全部内容——源码、内置依赖、Preset/Skill、模板、随包媒体；用户另装的 DSH、浏览器、FFmpeg 等工具与在线模型/服务按各自许可与条款，不因被本产品调用就变成 MIT，但仍需逐项核查获取、调用、自动化与输出条款；用户自己的作品不自动改为 MIT。

## 7. 换措辞消不掉义务

- 一般思想、事实、通用功能可以借鉴；**受保护的具体表达不能靠翻译、近义改写、照搬编排变成 MIT**。
- 许可文件、版式、独特范例、条款式重述都算表达层。
- 所以"把受限内容换个说法就能随包标 MIT"这条**明确不接受**。需要的能力：理解功能 → 形成规格 → 独立设计实现 → 核对新实现的来源与依赖，再谈能不能标 MIT；且不预先保证任何改写都不再受原许可约束。

## 8. 素材矩阵的分级（用于判"这份材料能不能用"）

| 级 | 含义 |
|---|---|
| A｜可直接用 | MIT 代码，保留版权声明即可 |
| B｜原内容 Apache，必要功能按规格重实现后纳入 | 原 Apache 内容仍有其许可义务；不直接并入 |
| C｜原实现受限，必要功能按规格重实现后纳入 | 强 copyleft、非商业或附加限制的原实现不搬入；功能可进蓝图 |
| D｜不能进 | 权利不清或明确非商业（如无许可字体、来源不明音频、非商业立绘） |

**"无第三方声明"不等于没有第三方权利。** 已登记的代表性空洞：某仓库 110 个字体无许可文本、某仓库 5 个字体含商业厂牌字体、某仓库 11 个音频里 5 个来源无法反查、某立绘为 CC BY-NC-SA、某动画库非 OSI 须单独声明。

## 9. 缺口

- 八份许可里只有 MIT 是全文，其余为摘录。**缺 4 条关键条文**：Apache-2.0 第 2 条（授权条款本身）、CC BY 4.0 第 7 条（终止/补救期）、CC BY-NC 4.0 第 3 条（署名条件）、AGPL-3.0 全文（现以 GPLv3 摘录近似替代，措辞不完全相同）。
- 缺这四条的直接后果：讲得了"必做条件"，讲不了"授予了哪些权利"；讲不了"用错了还有没有救"；讲不出 BY-NC 的署名到底要什么。
- 本份不是法律意见，也不替代许可证原文；判定"这份材料能不能进随包"必须回到具体文件与具体许可文本。
