# 口播与文字

本份只管"观众听到的那串字"和"标题/开场那几个字"。稿子落在作品文件夹的 `script.md`；屏上字、字幕断行、字号归 video-edit。

## 1. 先判断这次要不要写台词

任一成立，先别写：

| 判据 | 结论 |
|---|---|
| 用户给了定稿文稿，并说"一个字都别改" | 不重写。只做念得住的检查：标出念不断气、会听错、同音歧义的位置，改不改由用户定 |
| 这条片子本来没有人声（纯音乐、纯画面、只有屏上字） | 不写。硬加旁白会把一部视觉片变成解说片 |
| 用户要的其实是屏上字、字幕断行、字号 | 归 video-edit |
| 用户说的"脚本"是指分镜、镜头、时长分配 | 归 video-plan |

剩下的情况再问一句：这条片子里有没有一句话是画面说不出来、必须有人说出来的？没有就先别写；有，就从那句开始写。

## 2. 判断顺序

按 1→7 走，前一步的结论会改后一步的做法。

**① 主线：段落能不能互换。** 把稿子的段落在纸上换位置读一遍，换了之后观众察觉不到损失，说明没有主线，只是把概念按同一待遇排了一遍。这时不要硬加"因为…所以…"的假因果，先选一条真主线（一个过程走到底、一个张力解开、一个疑问被回答）。**但并列蒙太奇是合法的**：清单、多案例合辑、风格盘点的段落本来就该可互换，判据换成"每段自己有没有一个落点"，而不是"段与段有没有因果"。

**② 先因后果：数一下 why 句和 how 句。** 讲解类旁白里，一段每有 2—3 句"怎么做"，就该有至少 1 句"不加它会出什么事 / 为什么要这一步"（情绪片与叙事片不按这个比例算）。缺 why 时先补 why，不要先删 how——被删的机制细节通常还有画面可以承担，被删的动机没有替代品。

**③ 数字：分成两类对待。** 这条片子想让人记住的那一个数字——保留原值，并在别处再钉一次（屏上字、重复、对照）。过程性、规模性、纯用来让人感觉大小的数字——换成日常经验能比的尺度。分界线是**有没有人会去核它**：会核的（报价、参数量、临床结论、时间点）必须保真；只用来给大小感的，换感受更有效。换掉原值的，把原值留在"必须能核的"清单里，不要弄丢。

**④ 术语后置。** 先用大白话把事讲清，再挂名字（"这件事有个名字，叫 X"）。挂上名字之后必须再用到一次，否则这个名不该起。反过来做——先给名字再解释——观众要先花一句话的力气忍住不懂。

**⑤ 接缝：段落交界是丢人最多的地方。** 上一段末尾留下一个问题、一笔代价或一个缺口；下一段第一句先回指刚完成的东西，再开新题。"接下来我们看第二部分"是缺陷：它报的是你的播讲顺序，观众不需要知道稿子有几段，而它占掉的位置本该放"刚才那个办法的代价"——正是这句话让下一段非存在不可。

**⑥ 说画面说不了的。** 旁白承担理由、后果、比较、判断；画面承担结构、顺序、数量。删句标准：删掉这句，观众是不是少知道一件事？只说明屏幕上有什么的，删掉，让画面自己演。

**⑦ 念出来。** 不是默读，出声读。读到哪里想跳过、想笑、觉得"这话我说不出口"，那一句就是问题句，回①—⑥找原因，不要靠改标点遮过去。同时扫 AI 味（见 references）。

## 3. 标题与开场

**标题不是摘要。** 摘要服务的是已经在找这条片的人；标题要决定"谁会点进来"。所以标题里最该有的是一个不平整的地方——一个反常、一个代价、一个具体处境，而不是"本文讲了什么"。

什么时候可以直白：观众已经知道你是谁，或者这条片是被人搜出来的（"XX 报错怎么解决""XX 怎么装"）。这时标题就该把用户真会敲进搜索框的词放在前面，钩子是负担。

什么时候必须给钩子：观众不认识你、片子在同类里被划过、内容的价值靠反差或意外成立。这时标题给的是"这里有个不对劲的地方"，不是范围说明。

**开场：三秒内落在具体处境。** 不落在自我介绍、不落在"本期我们讲"、不落在背景铺垫。判断方法是把它删掉试一次：删掉第一句，从第二句开始，观众是否损失了什么？没损失，第一句就是废的。

标题和开场不要重复同一句。标题已经摆出的钩子，开场不要再复述一遍——开场是把观众放进标题承诺的那个处境里。标题承诺的东西，片子里要在观众还能忍的时间里兑现；兑现不了不是风格问题，是这条片子在骗点击。

## 4. 产出格式

`script.md`：

- 只放要念出来的字。标题、镜号、屏上字、批注都不混进来。
- 一段一个想法，空行分段；分段按"换意思"切，不按"换气"切（切块给字幕的是 video-edit）。
- 每个段落后给一行估读时长，写成"约 6 秒（中文约 4 字/秒估）"，标明是估读。全片时长预算归 video-plan。
- 稿子末尾列一小节 `必须能核的`：数字、名称、时间、结论逐条列，每条后写来源或写"待核"。这一节不念。

改稿时给三样，不要只给新版本：改前那句 → 改后那句 → 为什么改（一句，指到具体毛病）。

## 5. 判断示例

**示例一**
用户这么说："帮我写条 3 分钟的解说词，讲 KV cache 是怎么回事。"
→ 你这样判断：3 分钟中文口播上限约 700 字；主题本身有一条真主线（越写越慢 → 把算过的存起来 → 省了时间但花显存 → 于是有省显存的招），可以走因果链，不用并列。用户没说给谁看，术语后置的程度由此定不了，先按"懂编程但没做过推理优化"写。
→ 所以你这样做：第一段不解释 KV cache 是什么，先写"每吐一个字都要把前面重算一遍，所以越写越慢"这个处境；第二段用大白话讲完"算过的存起来，新的只算自己"，再把名字挂上去；第二段末尾留一句"代价是显存"，作为第三段的入场券。

**示例二**
用户这么说："这篇 5000 字的文章，压成 2 分钟口播。"
→ 你这样判断：5000 字按"文章转口播的一个起点"六成留存也有 3000 字，中文约 7—8 分钟，2 分钟装不下。这不是压缩技巧问题，是容量问题。
→ 所以你这样做：先报数——"原文 5000 字，2 分钟大约只能放 450—500 字，等于丢掉九成，剩下的不会还是这篇文章"。然后给两条路：拆 3 集（按文里各自能独立成立的因果段切，给出三集的落点），或做 8 分钟版（信息保得住，但钩子与节奏要重排）。不偷偷压到 30% 交差。

**示例三**
用户这么说："这段念出来怪怪的，你帮我顺一下。"
→ 你这样判断：先定位是哪种毛病——是句子被形容词包住（主谓宾隔了十几个字），还是 AI 味（用"恰恰/反而"包装一个平庸观点），还是术语没后置。三类改法完全不同。
→ 所以你这样做：只改出问题的那几句，逐句给"改前 → 改后 → 为什么"；句子结构问题就拆句，AI 味问题就删掉转折词看意思变不变，变了才留。用户没要求整篇重写，就不整篇重写。

**反例**
看起来合理、实际会错的做法：把"接下来我们看第二部分：缓存怎么省显存"当成稿子里最稳的过渡，还因为"结构清晰"留着它。
错在第⑤步：把章节顺序当成了信息。观众在这句里没有获得任何新东西，而它替换掉的那句话本来可以承担"上一段留下的显存代价"。判断方法很直接——把这句删掉，下一段是否仍然成立？成立，说明它没干活，是报幕，不是接缝。

## 6. 边界

- 不选人声路线：真人录、TTS、已有配音、干脆不要人声，归 video-sound。本份只判断"这句念出来顺不顺"，不判断"这句该由谁念"。
- 不做表演设计：重音、停顿、语速、情绪走向归 video-sound。本份在稿子里只留出"这里该停一下"的位置，不写表演指令。
- 不排镜头、不分配时长：镜头规格与时长预算归 video-plan。本份只报"这句念出来大概多长"。
- 不管字幕排版与断句切块：字在屏幕上的行数、每行字数、出现时机归 video-edit。本份只管字的顺序与意思。
- 标题长度、封面字与标题的配合归 video-visual；平台标题上限与验收归 video-release。本份只判断直白还是给钩子。
- **不适用**：片子没有人声、或用户要的是把稿子直接变成配音音频时，不该调用本份——前者不需要台词，后者归 video-sound。
